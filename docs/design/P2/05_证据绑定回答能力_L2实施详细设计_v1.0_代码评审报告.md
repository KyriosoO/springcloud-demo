## 5. 修复后复审结论

1. LLM 生成输入现在只接收有 `snippet/content` 可读权限的 evidence，且 pre-filter 输出不携带自由 metadata、ACL 字段、embedding 或带 token 的 `sourceUri`。
2. citation verifier 不再把“空引用 id 的 binding”误判为 VERIFIED，能按设计触发 fallback/refuse 的上游路径。
3. `DocumentEvidenceContextPacker` 仍保留 metadata 白名单和 `sourceUri` 净化，和 pre-filter 形成双层防护。
4. candidate 字段继续由 `DocumentResultSecurityProjector` 投影为最终 `answerText`，且投影后清空 candidate 字段；本轮未扩大 `agent-api` 公共契约。

## 7. 剩余风险

1. REFUSE 策略在 ResultSecurity inline citation 二次校验失败时仍缺少策略上下文，当前会走 fallback。建议单独授权扩展 `agent-api` 或内部候选上下文后处理。
2. 本轮未验证真实文档 provider、ES 检索集成和生产数据库脚本；这些属于 P2 07/08 或集成环境门禁。
3. 现有修复限制在 `agent-service` 测试和实现范围，未修改 SQL、配置、依赖和上级/关联设计文档正文。
