## 4. 代码问题清单

| 编号 | 级别 | 类型 | 文件 | 依据文档 | 问题描述 | 影响 | 处理 |
|---|---|---|---|---|---|---|---|
| CR-P2-06-001 | medium | functional_correctness | `DocumentPlanValidator.java` | P2 06 第 8、10.1 节 | 空 `summaryScope.documentIds=[]` 被当作空白 ID 拒绝；但主题摘要允许不指定 documentIds。 | Runtime 按 prompt 输出空数组时，合法主题摘要会被 Java 可信校验拒绝。 | 已修复：仅在列表非空但归一化后为空时拒绝。 |
| CR-P2-06-002 | medium | design_consistency | `DocumentPlanValidator.java` | P2 06 第 10.1、14 节 | protected filter 使用归一化 ID，但 `DocumentRetrievalRequest.summaryScope` 仍保留重复和空白 ID。 | adapter 若读取 summaryScope 可能看到不稳定范围，影响相同 documentIds 集合的稳定性。 | 已修复：构造 request 前复制归一化后的 `DocumentSummaryScope`。 |
| CR-P2-06-003 | high | security | `DocumentResultSecurityProjector.java` | P2 06 第 10.3、15 节 | ResultSecurity 过滤 citation 后仍沿用 adapter/source 的 `coveredDocumentCount`。 | 如果部分 citation 因权限或数量限制不可见，coverage 可能泄漏过滤前文档覆盖数量。 | 已修复：按最终可见 citations 重新计算 covered/evidence，并在安全过滤导致数量下降时标记 truncated。 |
| CR-P2-06-004 | medium | api_contract_consistency | `DocumentPlanValidator.java` | P2 06 第 10.1、16 节 | `maxSummaryChars` 只检查上限，未拒绝 0 或负数。 | Runtime 不可信场景下可能把非法摘要长度带入后续执行链。 | 已修复：校验 `maxSummaryChars > 0`。 |
| CR-P2-06-005 | medium | implementation_completeness | `DocumentCapabilityHandler.java` | P2 06 第 10.4、16 节 | SUMMARIZE 生成请求的 `maxOutputChars` 未受 `summaryScope.maxSummaryChars` 收窄。 | provider 可能被要求返回超过用户摘要上限的候选摘要。 | 已修复：provider 输出预算取 generation 配置与 summary scope 的较小值。 |
| CR-P2-06-006 | medium | implementation_completeness | `DocumentResultSecurityProjector.java`、`DocumentSafeTextComposer.java` | P2 06 第 10.5、16 节 | ResultSecurity/fallback 阶段没有结构化 `summaryScope.maxSummaryChars` 输入，只能按全局 `agent.document.max-summary-chars` 截断。 | 如果 provider 或 fallback 输出超过本次请求的更小 scope 上限，最终投影无法严格按请求级长度收敛。 | 未自动修复；需要为 ResultSecurity 增加内部 scope 上下文或扩展公共/内部 payload。 |
| CR-P2-06-007 | medium | implementation_completeness | `DocumentEvidenceContextPacker.java`、`DocumentCapabilityHandler.java` | P2 06 第 10.3 节 | coverage.truncated 尚不能完整表达 evidence 文本被 `maxEvidenceChars` 截断的情况。 | 摘要覆盖诊断可能低估 context budget 对摘要依据的影响。 | 未自动修复；需在 evidence package 或 handler 内增加截断诊断承载，并确认 provider 请求兼容。 |
