## 2. 本版本强化内容

1. `stratified_results` 成为必填字段，并固定为 `by_domain`、`by_scenario`、`by_tag` 三个分层维度。
2. 每个分层必须列出精确 `case_ids`、样本数、可回答/拒答数及9项指标；验证器按评价集重建全部分层，拒绝遗漏、额外或错误归组。
3. `case_results` 必须与评价集的26个 case ID 精确相等，不允许重复、遗漏或额外案例。
4. 每个案例必须提供可重算的事实声明、引用和关键要点原始计数/ID，不再接受无结构的 `metric_evidence`。
5. `validate_evaluation_report.py` 从案例结果重算总体指标、分层指标、失败门禁和 `gate_result`；提交值与重算值不一致即失败。
6. 验证器从检索结果、模型输入、引用、权限、撤权及时间版本自动推导可观察安全事件；报告不得漏报这些事件。

## 4. 报告验证

```powershell
python validate_evaluation_report.py --report <evaluation-report.json>
```

验证通过同时要求：Schema/结构有效、case集合精确一致、原始计数合法、自动安全事件无漏报、总体与分层重算一致、门禁结论一致。验证器退出码为0表示通过，退出码1表示报告无效。

## 5. 使用约束

1. 运行评价必须记录数据集、报告 Schema、被测制品、模型和检索配置版本。
2. 权限和时间过滤必须在检索及模型输入前执行，不得事后删除越权结果来掩盖泄漏。
3. 参考答案不得拼入被测模型 Prompt。
4. 所有9项门禁逐项判定，禁止以加权总分抵消。
5. 人工/模型裁判仍须对事实支持、相邻引用直接支持和关键要点覆盖给出原始证据；验证器负责范围约束、汇总和一致性，不替代语义裁判。
6. 冻结目录禁止原地修改；后续变更必须创建新版本目录。

## 6. 版本规则

- 错别字且不改变语义、Schema或标注：递增 PATCH。
- 新增兼容样本、语料或可选诊断字段：递增 MINOR。
- 修改指标、权限、既有标注，或对报告生产者引入不兼容要求：递增 MAJOR。
