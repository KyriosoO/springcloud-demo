目标清单固定为 9 份：L0、两个 L1、L2 总览及 01～05。执行方式是按清单顺序逐份完成 5 轮后才进入下一份，共 45 轮；上位或关联文档的原子同步只用于解除冲突，不计作被同步文档的新一轮，也不以一次统一评审替代任何目标文档的五轮。

每份文档依次覆盖：基线/边界，接口/安全，状态/异常/一致性，实现/测试/追踪，治理/最终回归。README 和本记录是治理材料，不在 9 份目标计数内。评审不包含代码符合性、LangGraph PoC、目标系统质量、供应商批准、生产配置验证或生产放行。

## 12. 原子同步记录

以下同步用于保持权威原子性，不改变逐文档计轮：

1. L0、Agent L1、L2-00/01/02/04：统一官方 Python LangGraph 单运行时、固定 StateGraph、`checkpointer=False`、全局失败路径和无第二状态权威。
2. L0 AD-13、Agent L1、L2-04：将禁入 State 的对象收敛为完整文档/未投影响应，允许只在请求内保存已授权、限量证据片段，禁止持久化与 trace 正文。
3. L2-02、L2-03：将字段权限拆成 filter/display/sort/group/metric 用途，禁用未冻结币种/单位/精度的金额聚合。
4. L2-02、检索 L1、L2-04、L2-05：同步 Search 的独立服务身份、短时请求绑定 JWS、检索前过滤和零越权泄漏合同。
5. 检索 L1、L2-05：同步复合文档键、单活动重建、快照追平/静默门禁、Alias 原子切换及旧索引受审计清理。
6. L2-04、L2-05：同步 `indexedAt/logicalIndexVersion`、有界 SearchHit 与版本化质量门禁。

## 13. 最终退出条件与当前证据

- 9 份目标文档必须各自存在五轮记录且最后一轮无遗留 S0/S1；
- L0/L1 和所有 L2 严格结构校验须为 0 错误、0 警告；
- L0→L1、两个 L1→下位 L2 不得有上位约束漏承接；
- REQ/CON/DR/IMPL/TEST/VAL 追踪不得存在未映射 ID；
- README/本记录与目标文档的状态、LangGraph、实现/生产边界保持一致；
- 当前代码基线测试只证明空壳模块可启动，不能冒充目标能力或质量验证。

- 3 份 L0/L1 使用架构严格校验，3/3 均为 0 错误、0 警告；
- 6 份 L2 使用详细设计严格校验，6/6 均为 0 错误、0 警告；
- L0→两个 L1：`missing_upstream_ids_in_lower=[]`，其余三类未追踪/未映射集合均为空；
- 两个 L1→6 份 L2：`missing_upstream_ids_in_lower=[]`，`untraced_lower_design_ids=[]`、`unmapped_implementation_ids=[]`、`unmapped_test_or_validation_ids=[]`；
- `mvn -f es-query-api/pom.xml test`成功，但该模块当前无源码、无测试；
- `mvn -f es-query-service/pom.xml test`成功，1 个空壳启动测试通过；测试输出含 Mockito/JDK 动态 agent 的未来兼容警告，不影响本次结果但需在后续依赖升级中处理。
