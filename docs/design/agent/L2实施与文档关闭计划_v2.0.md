- 用户本人同时承担需求、架构、开发、测试、评审和发布决策。
- 项目范围内的文档、代码、公共合同、依赖、配置、测试、Git 检查点和关联同步默认已授权，不需要再次等待批准。
- “评审通过”“有条件通过”和文档状态只记录技术成熟度，不再形成额外的人为等待队列。
- 当前 L2-01 正式实现评审通过；L2-02/03A/04/05A 正式实现评审有条件通过。条件满足后可直接实施。
- `not_ready` 阶段仍必须先补齐设计；默认授权不能替代缺失的字段、状态、错误、所有权和一致性事实。

## 5. 当前实现基线、关联资源与责任边界

### 5.1 模块职责分解

| 资源 | 当前事实 | 责任 | 明确不负责 |
|---|---|---|---|
| `agent-service` | 不存在 | 新建 API、Graph、State、安全节点和能力节点 | 不拥有 Auth、业务数据库、ES、文档原文 |
| `gateway-service` | 已存在 | Agent 路由、认证头传递、边界超时 | 不解析计划、不编排能力、不重试业务调用 |
| `auth-service` | 已存在旧 Agent 权限投影路径 | 用户验签、Auth 上界和新 facade | 不拥有 Agent 字段策略或 Graph State |
| `common-security` | 已存在通用安全能力 | 新增独立 Agent 服务 key purpose/provider | 不共享用户 JWT 或旧 payload key |
| `employee-service` | 已存在宽业务端点 | 新增专用 Employee QUERY 严格入口 | 不让 Agent 直连数据库或复用宽端点 |
| `mq-procedure-service` | 已存在 Transaction 宽端点 | 后续承载 Transaction AGGREGATE Runtime | 不把业务计算交给模型 |
| `transaction-api` | 已存在 | 仅承载分布式共享 Transaction 专项模型 | 不承载 Runtime 和编排 |
| `es-query-api/service` | 当前为空壳或基础路径 | Search、Index、Rebuild 原子能力 | 不编排 DOCUMENT、不生成答案 |
| 模型供应商、ES、数据源 | 文档外资源 | 提供真实目标、环境和数据事实 | 不成为 Agent 授权权威 |

允许依赖方向：

`Gateway -> agent-service -> Auth/Employee/Transaction/Search/Model`

`DOCUMENT -> DocumentSearchClient -> es-query-service -> Elasticsearch`

禁止反向依赖、Java 主编排、Agent 直连数据库/ES、模型持有 Auth/业务/ES 凭据，以及任何绕过 `validate -> authorize -> capability -> result_security` 的路径。

### 5.2 内聚、耦合与最小必要性

Graph 编排、安全、业务计算、检索和模型访问分别保留在其稳定责任所有者内：Python Agent 只编排和投影，Java 业务服务只拥有业务事实，检索服务只拥有派生索引能力。跨模块只通过严格契约耦合，不共享内部实体、ES Client、数据库对象或 Graph State。本计划只规定交付顺序，不新增运行时服务或通用抽象；每个阶段只加入当前能力所需的最小依赖和代码。

### 5.3 接口与契约设计边界

所有 HTTP、JWT、OpenAPI 和跨语言 DTO 由对应专题 L2 与其规范源定义。本计划只规定“合同夹具先行→provider→consumer”的实施顺序，不新增第二套字段或错误权威。公共合同变更必须同时更新 provider、consumer、固定夹具、错误映射和兼容/回滚测试。

### 5.4 数据生命周期与迁移回滚边界

Agent 首版不新增业务数据库或持久 Graph State。Employee/Transaction 业务数据仍由上游服务拥有；ES 只保存派生索引。旧 Agent/Document/ES 不要求迁移。Index/Rebuild 的版本、删除、保留、切换、清理和迁移回滚仅在 L2-05 阶段 B/C 按来源事实实现。

### 5.5 权限与安全审计设计边界

默认授权只适用于项目管理动作，不改变运行时权限。Auth 上界、Agent 策略、资源事实和目的交集必须失败关闭；所有成功结果经过 `result_security` 和脱敏安全审计。日志、测试报告和证据产物不得包含 JWT、secret、Prompt、正文或完整权限表达式。

- `mq-procedure-service`/`transaction-api` 边界测试通过。
- L2-03 阶段 A/B 均完成；创建 Git 检查点。

### 7.6 P5：L2-05 阶段 B Index

P5 开始前先完成第 8 节 `OFF-07`，然后：

1. 修订 L2-05，把 `FUTURE-05-B01` 展开为首个来源专用 Index API、Source Adapter、版本/删除/幂等模型和测试。
2. 先实现单条/批量中最小必要写入方式，不建设通用摄取平台。
3. 固定稳定 ID、来源版本顺序、删除事实、安全标签和重放语义。
4. 验证同版本同内容幂等、同版本异内容冲突、旧版本拒绝、删除不被旧事件复活。

P5 退出条件：

### 7.7 P6：L2-05 阶段 C Rebuild/Cancel/Rollback

P6 开始前先完成第 8 节 `OFF-08`，然后：

1. 修订 L2-05，定义最小任务状态、单活动所有者、checkpoint、取消、切换、未知结果核实和回滚。
2. 选择最小控制状态存储；不得同时引入 ES 控制索引、数据库和 Redis 多套权威。
3. 实现完整构建、增量追平、验证、Alias 原子切换和观察窗口。
4. 取消不得发布半成品；崩溃恢复不得重复发布。
5. Alias 切换结果未知时先读取事实，再决定完成、恢复或重试。
6. 验证回切旧索引不会丢失删除和增量。

P6 退出条件：

## 12. Git、回滚与连续开发

单人项目使用阶段检查点代替审批流程：

1. P0 建立基线检查点。
2. 每个 P1～P6 阶段只有在测试通过后提交。
3. 提交说明包含阶段、L2、实现范围和验证命令。
4. 当前阶段失败时回退能力开关或当前阶段提交，不改写已验证的上游业务事实。
5. 推送前执行 `git diff --check`、目标测试和状态检查。
6. 禁止用 `reset --hard`、删除测试或弱化断言制造通过。
