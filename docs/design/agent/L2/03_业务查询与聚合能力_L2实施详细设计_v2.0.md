## 3. 设计目标与范围

目标是确定性执行两个只读业务能力；范围外如上表。最小必要抽象是两个 Validator、共享元数据类型和每域一个 Adapter，不建立动态插件或通用查询语言。

## 4. 当前实现基线、关联资源与责任边界

新 Agent 能力代码不存在；`employee-service`与`mq-procedure-service`是关联上游。当前`GET /employees`返回过宽业务实体、`GET /employees/count`不支持受控过滤，`POST /txn/aggregate`返回宽松 Map；这些只证明路径存在，不满足目标严格 DTO/错误/授权合同。业务服务唯一负责数据与计算，Agent 只负责计划校验/映射/投影，不负责公共合同或数据库。首个 PoC 必须先冻结一个专用只读合同；若需修改上游，按已授权的关联文档同步范围处理并单独验证调用方兼容性。

## 5. 模块职责、依赖方向与调用边界

`application -> Query/AggregateCapability -> Validator -> BusinessCapabilityAdapter -> upstream`。禁止 Adapter 反向依赖规划候选，禁止能力绕过权限/Validator，禁止模型读取结果。稳定 canonical 合同降低域服务耦合并保持能力内聚。

## 7. 能力元数据

首阶段元数据来自受版本控制的配置并在启动时严格校验，不建设动态注册中心：

```yaml
domains:
  EMPLOYEE:
    queryFields:
      department: {type: STRING, operators: [EQ, IN]}
      status: {type: ENUM, operators: [EQ, IN]}
      hireDate: {type: DATE, operators: [GTE, LTE]}
    displayFields: [department, status, hireDate]
    sortFields: [hireDate]
    groupFields: [department, status]
    metrics: [COUNT]
  TRANSACTION:
    queryFields: {}
    displayFields: []
    sortFields: []
    groupFields: []
    metrics: [COUNT]
```

字段名是 Agent canonical 名称，上游映射由域 Adapter 明确维护。权限策略可进一步缩小元数据范围。类型/枚举/别名冲突、未知映射或空 Adapter 在启动时失败。

`SUM_AMOUNT/AVG/MIN/MAX`等金额指标只有在上游合同明确金额单位/币种、跨币种处理、精度和舍入责任后才能加入元数据；当前 Transaction 模型未提供币种权威，首个基线不得启用这些指标或假定默认币种。

启用任一域的 AGGREGATE 还必须在元数据中声明`minGroupSize`，并由对应上游合同在返回前执行低基数抑制；缺少该字段、上游不支持或返回任一低于阈值的桶时，该域 AGGREGATE 失败关闭。Agent 不在本地合并小桶，因为这不能替代业务数据所有者的推断控制。

## 8. QUERY 合同

模型计划 payload：

```json
{
  "filters":[{"field":"status","operator":"EQ","value":"ACTIVE"}],
  "select":["department","status"],
  "sorts":[{"field":"hireDate","direction":"DESC"}],
  "page":{"number":0,"size":20}
}
```

规则：

- filters 最多 10 个，首阶段只支持 AND；不支持任意嵌套逻辑。
- operator 仅 `EQ|IN|GT|GTE|LT|LTE|CONTAINS`，且必须被字段声明；IN 最多 50 项。
- 值先按字段类型严格解析，再做枚举/长度/日期范围校验；不接受脚本、表达式、SQL 片段。
- select 必须非空且全在 `displayFields ∩ effectiveAuthorization`；最多 20 项。
- sorts 最多 2 个且全在获准 `sortFields`；稳定结果必须由 Adapter 补充上游唯一键排序，但该键不因此可显示。
- page.number 0..100，size 1..100；更大范围返回限制错误，不自动全量导出。

输出 `QueryResult(items, page, total?, observedAt, sourceVersion?)`；`observedAt/sourceVersion`只能透传上游提供且有合同定义的观测/快照事实，Agent 不得用本地时钟伪造数据版本。Adapter 返回的额外字段在结果投影时删除。若上游不提供可靠 total 或 sourceVersion，则对应字段为空，不由 Agent 猜测。

## 9. AGGREGATE 合同

模型计划 payload：

```json
{
  "filters":[],
  "groupBy":["department"],
  "metrics":[{"function":"COUNT","field":null,"alias":"employeeCount"}],
  "orderBy":[{"metric":"employeeCount","direction":"DESC"}],
  "limit":20
}
```

规则：

- filters 与 QUERY 相同；groupBy 最多 2 个且属于获准 groupFields。
- function 只允许 `COUNT|SUM|AVG|MIN|MAX` 与元数据声明的业务指标；除 COUNT 外 field 必填且类型匹配。
- alias 由确定性节点生成或按严格标识符校验，不由模型注入表达式。
- orderBy 只能引用 groupBy 或已声明 metric alias；它与 QUERY `sorts` 是不同合同。
- limit 1..100；首阶段不支持 having、窗口函数、百分位或跨域聚合。

输出 `AggregateResult(columns, rows, observedAt, sourceVersion?)`。数值由上游计算并以明确 decimal/integer 类型返回；金额指标还必须携带合同定义的单位/币种，禁止二进制浮点重算。Agent 不经模型重算、舍入、币种合并或自然语言改写，也不伪造 sourceVersion。

## 10. 详细功能与核心处理流程：校验与映射

```text
PlanCandidate
 -> capability/domain authorization
 -> metadata lookup
 -> field/operator/function/value validation
 -> resource budget validation
 -> canonical ValidatedQuery/ValidatedAggregate
 -> domain adapter mapping
 -> upstream client
 -> response contract validation
 -> result security projection
```

每个域实现一个 Python `BusinessCapabilityClient`，暴露 `query` 和/或 `aggregate`；不建立可动态加载插件。Client 只映射 canonical Pydantic DTO、服务身份和经 02 验证的最小用户授权投影到稳定 Java 上游 DTO，不自行推导权限，不访问数据库，不降级调用写接口。业务上游必须同时验证 Agent 服务 scope 与 subject/tenant/资源范围绑定；固定 query/aggregate 图节点是唯一调用方。

## 11. 接口与契约设计：初始上游落点

| 域 | 当前勘察输入 | 实施要求 |
|---|---|---|
| EMPLOYEE | `employee-service` 的 `/employees`、`/employees/count` 等控制器 | 冻结专用严格只读合同；同时验证 Agent 服务 scope 与用户/tenant/资源范围，避免返回过宽实体 |
| TRANSACTION | `mq-procedure-service` 的 `/txn/query`、`/txn/search`、`/txn/aggregate` | 只勘察`/txn/search|aggregate`；冻结严格 DTO、用户范围绑定、低基数抑制、错误和服务鉴权语义，禁止调用宽`/txn/query` |

这些路径不是最终合同承诺。若需要新增/修改公共 DTO 或接口，必须单独取得上游文档/代码变更授权并验证现有调用方；Agent L2 不擅自修改。

## 12. 权限与推断控制

- filter、select、sort、groupBy、metric field 必须分别与`filterFields/displayFields/sortFields/groupFields/metricFields`用途权限求交；“可过滤”不等于“可显示/排序/分组/聚合”，禁止使用一个通用 fields 集合替代分权。
- 对敏感字段禁止通过排序位置、分组桶、count 差分或详细错误泄漏。低基数阈值由域策略声明并由业务上游在返回前执行；Agent 发现违反阈值的桶时整体返回通用`FORBIDDEN`，不本地合并、不暴露哪个桶触发。
- 结果投影使用当前 `EffectiveAuthorization`；上游返回未知字段、错误 tenant 或无法解析版本时整体失败关闭。
- 上游错误只映射为稳定码，不返回 SQL、字段存在性或资源标识细节。

## 13. 数据生命周期、超时、重试与事务边界

Client 取得剩余 deadline 并设置单次 HTTP 超时。QUERY/AGGREGATE 是只读能力，只有连接建立前失败或上游明确声明幂等时最多重试一次；超时/断连导致结果未知时直接失败。Agent 不对上游分页做隐式循环，不自动扩大 page/limit。

错误分类与调用方可见语义：非法计划为`MODEL_OUTPUT_INVALID`，字段/推断限制为`FORBIDDEN`，上游超时为`TIMEOUT`，稳定 5xx/合同解析失败为`UPSTREAM_UNAVAILABLE`；外部错误不得暴露字段存在性、SQL 或上游正文。权限与安全审计设计继承 02，能力节点只记录域、计划摘要、条数、耗时和安全码。
