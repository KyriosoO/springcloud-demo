## 3. 设计目标与范围

目标是先确定性执行一个可验证的 `EMPLOYEE QUERY` 最小纵切。`TRANSACTION AGGREGATE` 只保留后续阶段的安全与数据所有权约束，不在尚无严格上游合同的情况下预先冻结 DTO、类和方法。`EMPLOYEE AGGREGATE`、`TRANSACTION QUERY` 不属于当前目标合同。最小必要抽象是 Query Validator、固定 Employee Adapter 和严格结果投影，不建立动态插件或通用查询语言。

## 4. 当前实现基线、关联资源与责任边界

新 Agent 能力代码不存在；`employee-service`与`mq-procedure-service`是关联上游。当前`GET /employees`返回过宽业务实体、`GET /employees/count`不支持受控过滤，`POST /txn/aggregate`返回宽松 Map；这些只证明路径存在，不满足目标严格 DTO/错误/授权合同。当前 Employee/Transaction 模型与 Mapper 中均未发现 tenant 行级字段，因此首版只能在部署配置锁定的单一 tenant 下使用`SINGLE_TENANT_ALL`资源范围；任何多租户或资源集合范围必须失败关闭。业务服务唯一负责数据与计算，Agent 只负责计划校验/映射/投影，不负责数据库。阶段 A 先冻结并验证 Employee 专用只读合同；阶段 B 只有在 Transaction 严格聚合合同和时间语义获批后才重新展开实施设计。

## 5. 模块职责、依赖方向与调用边界

`application -> Query/AggregateCapability -> Validator -> BusinessCapabilityAdapter -> upstream`。禁止 Adapter 反向依赖规划候选，禁止能力绕过权限/Validator，禁止模型读取结果。稳定 canonical 合同降低域服务耦合并保持能力内聚。

## 7. 能力元数据

阶段 A 元数据来自受版本控制的配置并在启动时严格校验，不建设动态注册中心：

```yaml
domains:
  EMPLOYEE:
    queryEnabled: false
    queryFields:
      position: {type: STRING, operators: [EQ, IN]}
      workBaseSi: {type: STRING, operators: [EQ, IN]}
    displayFields: [position, workBaseSi]
    sortFields: [position]
```

`queryEnabled`默认关闭，只有专用合同和安全测试通过后才可启用。字段名是 Agent canonical 名称，上游映射由 Employee Adapter 明确维护。权限策略可进一步缩小元数据范围。类型/枚举/别名冲突、未知映射或空 Adapter 在启动时失败。

阶段 B 不复用上述元数据自动开启 Transaction 聚合。届时需以单独修订冻结 `COUNT`、时间语义、低基数策略及上游合同；`SUM_AMOUNT/AVG/MIN/MAX`在金额单位、币种、精度和舍入责任未明确前一律禁止。

## 8. QUERY 合同

模型计划 payload：

```json
{
  "filters":[{"field":"workBaseSi","operator":"EQ","value":"SHANGHAI"}],
  "select":["position","workBaseSi"],
  "sorts":[{"field":"position","direction":"ASC"}],
  "page":{"number":0,"size":20}
}
```

规则：

- filters 最多 10 个，首阶段只支持 AND；不支持任意嵌套逻辑。
- operator 仅 `EQ|IN|GT|GTE|LT|LTE|CONTAINS`，且必须被字段声明；IN 最多 50 项。
- 值先按字段类型严格解析，再做枚举/长度/日期范围校验；不接受脚本、表达式、SQL 片段。
- select 必须非空且全在 `displayFields ∩ effectiveAuthorization`；最多 20 项。
- sorts 最多 2 个且全在获准 `sortFields`；稳定结果必须由 Adapter 补充上游唯一键排序，但该键不因此可显示。
- page.number 0..100，size 1..100；更大范围返回限制错误，不自动全量导出。

输出 `QueryResult(items, page, total?, observedAt, sourceVersion?)`；`observedAt/sourceVersion`只能透传上游提供且有合同定义的观测/快照事实，Agent 不得用本地时钟伪造数据版本。Adapter 返回的额外字段在结果投影时删除。若上游不提供可靠 total 或 sourceVersion，则对应字段为空，不由 Agent 猜测。

## 9. 阶段 B：TRANSACTION AGGREGATE 边界（未冻结实现合同）

阶段 B 的候选最小能力仅为 Transaction 全局 `COUNT`。进入设计展开前必须同时具备：专用上游 DTO、可信的读取时间语义、单租户边界、失败关闭的委托调用认证，以及可执行合同测试。当前不定义请求/响应字段、Java/Python 类型、路径或开关；不得据此编码。

后续修订仍须遵守：结果由业务服务计算；Agent 不经模型重算；未知字段、低基数或单位/币种不明确时失败关闭；不复用宽 `Map` 合同。`EMPLOYEE AGGREGATE` 与 `TRANSACTION QUERY` 需新的业务需求和授权后另行设计。

## 10. 详细功能与核心处理流程：校验与映射

```text
PlanCandidate
 -> capability/domain authorization
 -> metadata lookup
 -> field/operator/function/value validation
 -> resource budget validation
 -> canonical ValidatedQuery
 -> domain adapter mapping
 -> upstream client
 -> response contract validation
 -> result security projection
```

阶段 A 只有固定 Employee Client，暴露 `query`。计划通过后，L2-02 的`authorize`先将部署锁定的 Employee 单租户事实与规划授权上界、`EMPLOYEE QUERY`目的求交；只有形成`EffectiveAuthorization`后才签发一个短时 `typ=agent-business-delegated+jwt` Bearer 凭证，同时承载独立的服务身份声明与最小用户授权范围。请求体不再携带第二份 `authorizationProjection`。Employee 上游在数据库调用前验证签名、typ、aud、sub、jti、digest、exp、domain、capability、tenant 与 `resourceScopeMode=SINGLE_TENANT_ALL`，任一失败即拒绝。固定 query 图节点是唯一调用方。

## 11. 接口与契约设计：初始上游落点

| 域 | 当前勘察输入 | 实施要求 |
|---|---|---|
| EMPLOYEE（阶段 A） | `employee-service` 的 `/employees`、`/employees/count` 等控制器 | 新增专用严格 QUERY 合同；验证单个委托凭证和部署锁定的单 tenant；无行级 tenant 基线时禁止宣称多租户过滤 |
| TRANSACTION（阶段 B） | `mq-procedure-service` 的 `/txn/query`、`/txn/search`、`/txn/aggregate` | 仅作为勘察输入；严格聚合合同未冻结，当前不得实现或调用宽端点 |

这些路径不是最终合同承诺。若需要新增/修改公共 DTO 或接口，必须单独取得上游文档/代码变更授权并验证现有调用方；Agent L2 不擅自修改。

阶段 A 合同使用以下 HTTP/错误语义：400 `AGENT_BUSINESS_INVALID_REQUEST`，401 `AGENT_BUSINESS_UNAUTHORIZED`，403 `AGENT_BUSINESS_FORBIDDEN`，408 `AGENT_BUSINESS_DEADLINE_EXCEEDED`，503 `AGENT_BUSINESS_UNAVAILABLE`，500 `AGENT_BUSINESS_INTERNAL_ERROR`。错误响应只含`requestId/code/message/diagnosticId`，message 是服务端通用模板，不暴露字段存在性、SQL、凭证规则、tenant 或资源 ID。Python Client 对未知 code、未知字段、响应 requestId 不匹配一律失败关闭。

`observedAt`定义为 Employee 服务完成本次数据库读取的 UTC 时刻，只表示读取完成时间，不表示数据库快照版本；`sourceVersion`在业务数据源尚无可证明版本时必须为 null。Transaction 时间语义留待阶段 B 合同冻结。

## 12. 权限与推断控制

- filter、select、sort、groupBy、metric field 必须分别与`filterFields/displayFields/sortFields/groupFields/metricFields`用途权限求交；“可过滤”不等于“可显示/排序/分组/聚合”，禁止使用一个通用 fields 集合替代分权。
- 对敏感字段禁止通过排序位置、分组桶、count 差分或详细错误泄漏。低基数阈值由域策略声明并由业务上游在返回前执行；Agent 发现违反阈值的桶时整体返回通用`FORBIDDEN`，不本地合并、不暴露哪个桶触发。
- 结果投影使用当前 `EffectiveAuthorization`；上游返回未知字段、错误 tenant 或无法解析版本时整体失败关闭。
- 首版业务数据只支持`SINGLE_TENANT_ALL`：授权投影 tenant 必须与 Employee/Transaction 服务各自的`singleTenantRef`配置相等；若授权资源事实为`RESOURCE_SET`、配置缺失或未来数据出现 tenant 行级隔离需求，域能力保持关闭并先修订合同/数据设计。
- 上游错误只映射为稳定码，不返回 SQL、字段存在性或资源标识细节。

## 13. 数据生命周期、超时、重试与事务边界

Client 取得剩余 deadline 并设置单次 HTTP 超时。QUERY/AGGREGATE 是只读能力，只有连接建立前失败或上游明确声明幂等时最多重试一次；超时/断连导致结果未知时直接失败。Agent 不对上游分页做隐式循环，不自动扩大 page/limit。

错误分类与调用方可见语义：非法计划为`MODEL_OUTPUT_INVALID`，字段/推断限制为`FORBIDDEN`，上游超时为`TIMEOUT`，稳定 5xx/合同解析失败为`UPSTREAM_UNAVAILABLE`；外部错误不得暴露字段存在性、SQL 或上游正文。权限与安全审计设计继承 02，能力节点只记录域、计划摘要、条数、耗时和安全码。
