## 3. 设计目标与范围

目标是用官方 Python LangGraph 明确首版控制流，同时严格限制图能力。最小变更/新增抽象仅限 FastAPI/Pydantic 边界、`AgentState`、Graph Builder、固定节点、Validator 和窄 Client；不建设 Java 主编排、动态工作流或通用 Agent 平台。

## 4. 当前实现基线、关联资源与责任边界

新 Python `agent-service` 尚不存在，所有代码路径均为建议新增。网关/Auth/Java 业务服务是关联资源；FastAPI 负责 HTTP，已编译 StateGraph 是唯一流程权威，规划节点只产候选，确定性能力节点只收已校验计划。本文不负责上游公共合同变更，也不宣称 LangGraph PoC 已完成。

## 5. 模块职责、依赖方向与调用边界

依赖方向为 `api -> compiled graph -> nodes -> planning/capabilities/security -> clients`。禁止 Client 反向依赖图，禁止能力节点绕过 Validator，禁止模型节点直接调用 Auth/业务/检索 Client，禁止新增 Java 主编排；该稳定合同保持节点内聚、降低图与上游耦合。

## 7. 接口与契约设计

### 7.1 请求

`POST /api/agent/v1/execute`

```json
{
  "message": "查询研发部在职员工数量",
  "conversation": [{"role":"USER","content":"..."}],
  "timeoutMs": 10000
}
```

| 字段 | 规则 |
|---|---|
| `message` | required，去首尾后 1..4000 字符 |
| `conversation` | optional，最多 10 轮/总计 12000 字符，只允许 USER/ASSISTANT；两种角色都只是调用方提供的不可信转录标签，当前请求不得重复 |
| `timeoutMs` | optional，1000..30000；缺省由服务配置给定 |

`requestId`不属于请求字段，由 ASGI 边界在请求到达时、正文解析前生成并附着到请求上下文；调用方不得提供或覆盖。这样包括 Pydantic 解析失败在内的所有响应都可携带服务端关联 ID，但只有 Schema 通过后才会计算业务 deadline、调用 Auth 或进入 Graph。未知字段、显式非法 null、非法 role、超长或空白 message 返回 `INVALID_REQUEST`。主体、tenant、权限和能力不得由请求体提供。`conversation`不得直接映射为模型的 system/developer/tool 控制消息；即使标签为 ASSISTANT，也必须在规划输入中作为有边界的不可信历史数据编码，并先经过 02 的最小投影。

### 7.2 响应

成功 HTTP 200：

```json
{
  "requestId":"...",
  "type":"QUERY_RESULT",
  "capability":"QUERY",
  "data":{},
  "citations":[],
  "warnings":[]
}
```

`type`只允许 `QUERY_RESULT|AGGREGATE_RESULT|DOCUMENT_ANSWER|DOCUMENT_SUMMARY|CLARIFICATION`。非 DOCUMENT 的 `citations` 必须为空。`warnings`只允许白名单`code`和受限标量参数，展示文本由服务端模板生成，禁止复制模型/上游正文。错误封套：

```json
{"requestId":"...","code":"FORBIDDEN","message":"请求未获授权","retryable":false}
```

HTTP 映射：400 `INVALID_REQUEST`，401 `UNAUTHORIZED`，403 `FORBIDDEN`，408 `TIMEOUT`，422 `UNSUPPORTED|EVIDENCE_INSUFFICIENT`，502 `UPSTREAM_UNAVAILABLE|MODEL_OUTPUT_INVALID`，500 `INTERNAL_ERROR`。CLARIFY 统一返回 HTTP 200、`type=CLARIFICATION`的受限成功载荷；不再并列`CLARIFICATION_REQUIRED`错误。模型输出非法是 Agent 依赖失败，不得映射为调用方 400。`retryable=true`仅表示调用方可重新发起新请求，不授权服务内部重放。

错误`message`也只能由`code`和受限参数映射的服务端模板生成；异常正文、上游响应、模型文本、Prompt 和策略细节不能成为 message 或 warning。

## 8. 规划合同

```json
{
  "schemaVersion":"1",
  "outcome":"EXECUTE",
  "capability":"QUERY",
  "domain":"EMPLOYEE",
  "intent":"按条件查询员工",
  "payload":{}
}
```

`outcome`为 `EXECUTE|CLARIFY|REJECT`。EXECUTE 必须有 capability/domain/payload；CLARIFY 只能有白名单`reasonCode/missingFields/optionKeys`，不得包含自由文本问题或答案选项；REJECT 只能有 `reasonCode`。`safe_response`把这些键映射为服务端模板。所有对象 `additionalProperties=false`。

`intent`是 1..128 字符的诊断标签，只用于内存内校验/指标分类，不参与授权、路由或上游参数构造，也不得按原文写日志；真正执行只读取已校验的 capability/domain/payload。

规划输入由`plan`节点根据当前问题和`planning_authorization`即时构造，只包含：经 02 投影的有限历史、获准 capability/domain 列表、各能力 Schema 摘要和当前日期/时区。该投影是节点内临时值，不写入 Graph State。规划授权只表示 Auth 上界与 Agent 策略的交集，不包含尚未确定的请求目的或资源事实，也不得直接签发下游调用凭据。禁止发送 JWT、权限码全集、隐藏字段、真实数据样本、服务地址、密钥或原生上游合同。

## 9. Graph State 数据设计与生命周期

API 在调用图之前以独立 Agent 服务凭据调用 L2-02 的 Auth facade 一次；用户 JWT 的签名、`kid`、类型、时效和主体校验由 Auth 完成，Python 不持有用户验签 keyset。API 只把严格响应中的可信主体与 Auth 上界写入初始 State；不得信任网关注入的用户头。`AgentState`使用 `TypedDict`或等价显式 schema；HTTP/上游边界使用 Pydantic model。首版字段如下：

| 字段 | 写入节点 | 生命周期/约束 |
|---|---|---|
| `request_id/deadline_at` | api/start | required；全图只读 |
| `request_input` | api/start | `message`与经长度/角色校验的`conversation`；请求级只读，不记录日志/trace，不含调用方提供的 requestId 或控制消息 |
| `trusted_identity/auth_upper_bound` | api/start | Auth facade 单次返回的绑定事实；写入后全图只读，不含原始 JWT 或完整 Auth 响应 |
| `planning_authorization` | auth_context | `trusted_identity/auth_upper_bound ∩ Agent policy`；只供规划和计划校验，不授权上游调用 |
| `plan_candidate` | plan | 模型候选不可信；规划输入投影只在节点内存在，不进入 State |
| `validated_plan/selected_capability` | validate | 只有确定性 validate 可写 |
| `effective_authorization` | authorize | `planning_authorization ∩ validated purpose ∩ capability resource facts`；缺失/冲突时不进入能力分支 |
| `query_result/aggregate_result` | query/aggregate | 互斥严格 DTO；仅所属能力节点可写 |
| `search_hits/evidence_package/model_output` | DOCUMENT 子图 | 仅 DOCUMENT 分支；逐节点收窄且有数量/大小上限 |
| `error/safe_response` | 失败节点/safe_response | 仅白名单模板标识、安全码和受限参数；不含异常正文、模型文本或上游正文 |
| `secured_result/safe_error` | result_security | 互斥的成功/澄清载荷或安全错误载荷，是唯一 Graph 输出；其他节点不得写入 |

JWT、服务密钥、HTTP Client、Prompt 模板、完整原文和模型原始响应不得进入 State。节点只返回自己的局部更新；同一字段不得由两个非终止节点竞争写入。图以封闭 input/output schema 调用`builder.compile(checkpointer=False)`；任何独立编译的嵌套图也必须使用`checkpointer=False`，不得继承父图持久化。output 仅含`request_id/secured_result/safe_error`。不使用 `thread_id`，请求结束后 State 释放，不支持恢复、持久记忆、time travel 或人工中断。LangSmith/第三方 tracing 默认关闭，避免 State/Prompt 外发。

## 10. 详细功能与核心处理流程

### 10.1 固定图拓扑

```text
START -> auth_context -> plan -> validate
validate -> authorize | clarify | reject
authorize -> query | aggregate | document
document -> retrieve -> evidence_gate -> generate_or_summary -> citation_gate
query/aggregate/citation_gate -> result_security -> END
clarify/reject/任一安全失败 -> safe_response -> result_security -> END
```

`auth_context/validate/authorize/query/aggregate/retrieve/evidence_gate/citation_gate/safe_response/result_security`必须是确定性节点；`plan/generate_or_summary`是仅有的模型节点。`authorize`由 L2-02 拥有，只在`validated_plan`产生后解析能力专属资源事实并形成`effective_authorization`；失败直接进入安全终态，任何业务、检索或生成调用计数必须为 0。`safe_response`只能把白名单原因码映射为模板标识和受限参数，禁止复制模型自由文本、上游正文或异常信息；`result_security`是所有 Graph 输出的唯一出口。能力路由条件边只读取封闭枚举并恰好返回一个静态目标，不执行网络调用，不返回目标列表，不使用`Send`或`Command.goto`绕过已声明条件边。图没有返回上游节点的边，没有模型自主 Tool loop，也不在运行时注册节点。

### 10.2 确定性校验流水线

1. 严格 JSON 解析和顶层 outcome 校验；
2. capability/domain 必须在当前授权候选集中；
3. 选择唯一能力 Validator；
4. 能力 Validator 校验字段、操作符、函数、值类型、排序、分页和资源预算；
5. 生成不可变 `ValidatedPlan`，只含 canonical 值；
6. capability 执行器只接收 `ValidatedPlan`，禁止接收模型原始 JSON。

Validator 不做网络调用，不依赖模型，不默默删除非法过滤条件。信息不足形成 `CLARIFY` 决策，并由安全响应链返回 HTTP 200、`type=CLARIFICATION`的受限载荷；违反白名单返回 `MODEL_OUTPUT_INVALID` 或 `FORBIDDEN`，两者不得混淆。

### 10.3 请求执行算法

```text
ASGI request arrival -> generate requestId and receivedAt
 -> FastAPI/Pydantic request validation
 -> derive absolute deadline from receivedAt and validated timeoutMs
 -> call Auth facade once with requestId/deadline + Agent service credential + sensitive user Bearer
 -> build initial AgentState(requestId/deadline/trusted identity/Auth upper bound)
 -> await compiled_graph.ainvoke(state) with checkpointer disabled and without thread_id
 -> graph executes auth_context/plan/validate/authorize/one branch/result security
 -> serialize only secured Graph output; security audit has already been accepted by result_security
```

- 模型规划失败不切换到字符串规则猜测；只有`ModelClient`可对明确的瞬时连接失败重试一次，必须生成新调用并受剩余 deadline 限制，plan 节点和 Graph 不再重试。
- 一个请求只执行一个能力，不跨域 join，不形成模型自主循环。
- `CLARIFY`不调用业务/检索上游；用户回答通过新的 HTTP 请求进入。
- FastAPI 客户端断开或 deadline 到期后取消图调用；每个节点在远调前后检查 deadline，迟到响应不得更新 State。

## 11. 超时预算

`deadline = min(receivedAt + requestedTimeout, receivedAt + configuredMax)`。每次远调超时为 `min(componentMax, deadline-now-safetyMargin)`；不足最小预算时直接 `TIMEOUT`。

首版建议预算比例仅作为配置默认值：Auth 10%、规划 35%、能力执行 35%、结果安全/序列化 20%。代码使用绝对剩余时间，不串联相对 timeout。业务读取最多一次幂等重试；写入、未知发送结果和整个请求不得自动重试。

## 12. 并发、幂等与事务边界

- 接口是只读编排，不提供业务写能力；相同问题的重复请求是独立请求，不承诺去重。
- `requestId`由服务生成，不把调用方 id 当授权或幂等证明。
- Agent 不开启跨上游事务；本地无业务数据库事务。
- httpx 客户端不得持锁等待；`AgentState`不得跨请求共享或写入进程级全局变量。
- LangGraph 节点级 retry policy 首版不设全局默认；需要重试的只读 Client 在自身边界按 AD-09 显式实现。

## 13. 错误分类与安全审计

审计字段：`requestId`、主体不可逆摘要、tenant 引用、capability/domain、策略版本、模型目标 ID、上游服务码、阶段、耗时、结果码、返回条数/引用数。禁止 message/history/plan 原文/结果正文/JWT/secret/完整资源 ID 集合。

安全审计事件的构造、字段校验和本地有界 sink 接受是返回结果的前置门禁；任一失败都失败关闭。默认 profile 不等待远端采集器确认，避免把观测管道可用性变成所有请求的同步依赖。只有 L2-02 明确标记为`PRE_RELEASE_DURABLE`且审计合同获批的 profile，才必须在剩余 deadline 内取得持久确认后返回。普通运行指标/非安全调试日志失败可以降级，但必须产生独立健康指标和告警，且不能影响安全审计字段或正文禁记规则。

## 17. 风险与待确认事项

风险是 LangGraph 版本/API 演进、模型计划稳定性、同步预算和 Python/Java 安全合同。通过锁定兼容版本、图/状态回归、严格 Validator、deadline 指标和实现前 PoC 控制；若硬性 Java-only 约束被证实，只能重新评审 LangGraph4j 备选，不能增加 Java 主编排旁路。

官方依据：`StateGraph`节点以共享 state 传递局部更新，图需 compile 后 invoke；checkpointer 才提供 checkpoint/thread 持久化与恢复。本设计以`checkpointer=False`显式禁止使用或继承：<https://reference.langchain.com/python/langgraph/graph/state/StateGraph/compile>、<https://docs.langchain.com/oss/python/langgraph/persistence>。
