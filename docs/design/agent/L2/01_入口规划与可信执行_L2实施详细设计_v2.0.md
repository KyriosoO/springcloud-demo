## 3. 设计目标与范围

目标是用官方 Python LangGraph 明确首版控制流，同时严格限制图能力。最小变更/新增抽象仅限 FastAPI/Pydantic 边界、`AgentState`、Graph Builder、固定节点、Validator 和窄 Client；不建设 Java 主编排、动态工作流或通用 Agent 平台。

## 4. 当前实现基线、关联资源与责任边界

新 Python `agent-service` 尚不存在，所有代码路径均为建议新增。网关/Auth/Java 业务服务是关联资源；FastAPI 负责 HTTP，已编译 StateGraph 是唯一流程权威，规划节点只产候选，确定性能力节点只收已校验计划。本文不负责上游公共合同变更，也不宣称 LangGraph PoC 已完成。

## 5. 模块职责、依赖方向与调用边界

依赖方向为 `api -> compiled graph -> nodes -> planning/capabilities/security -> clients`。禁止 Client 反向依赖图，禁止能力节点绕过 Validator，禁止模型节点直接调用 Auth/业务/检索 Client，禁止新增 Java 主编排；该稳定合同保持节点内聚、降低图与上游耦合。

## 7. 接口与契约设计

### 3.1 请求

`POST /api/agent/v1/execute`

```json
{
  "message": "查询研发部在职员工数量",
  "conversation": [{"role":"USER","content":"..."}],
  "timeoutMs": 10000
}
```

| 字段 | 规则 |
|---|---|
| `message` | required，去首尾后 1..4000 字符 |
| `conversation` | optional，最多 10 轮/总计 12000 字符，只允许 USER/ASSISTANT；当前请求不得重复 |
| `timeoutMs` | optional，1000..30000；缺省由服务配置给定 |

未知字段、显式非法 null、非法 role、超长或空白 message 返回 `INVALID_REQUEST`。主体、tenant、权限和能力不得由请求体提供。

### 3.2 响应

成功 HTTP 200：

```json
{
  "requestId":"...",
  "type":"QUERY_RESULT",
  "capability":"QUERY",
  "data":{},
  "citations":[],
  "warnings":[]
}
```

`type`只允许 `QUERY_RESULT|AGGREGATE_RESULT|DOCUMENT_ANSWER|DOCUMENT_SUMMARY|CLARIFICATION`。非 DOCUMENT 的 `citations` 必须为空。错误封套：

```json
{"requestId":"...","code":"FORBIDDEN","message":"请求未获授权","retryable":false}
```

HTTP 映射：400 invalid/model-output-invalid，401 unauthenticated，403 forbidden，408 timeout，422 clarification/unsupported/evidence-insufficient，502 upstream-unavailable，500 internal。`retryable=true`仅表示调用方可重新发起新请求，不授权服务内部重放。

## 4. 规划合同

```json
{
  "schemaVersion":"1",
  "outcome":"EXECUTE",
  "capability":"QUERY",
  "domain":"EMPLOYEE",
  "intent":"按条件查询员工",
  "payload":{}
}
```

`outcome`为 `EXECUTE|CLARIFY|REJECT`。EXECUTE 必须有 capability/domain/payload；CLARIFY 只能有 `reasonCode/question/options`；REJECT 只能有 `reasonCode`。所有对象 `additionalProperties=false`。

规划输入只包含：当前问题、经 02 投影的有限历史、获准 capability/domain 列表、各能力 Schema 摘要和当前日期/时区。禁止发送 JWT、权限码全集、隐藏字段、真实数据样本、服务地址、密钥或原生上游合同。

## 9. Graph State 数据设计与生命周期

API 在调用图之前完成 JWT 签名、`kid`、时效和 issuer/audience 校验，只把可信主体写入初始 State；不得信任网关注入的用户头。`AgentState`使用 `TypedDict`或等价显式 schema；HTTP/上游边界使用 Pydantic model。首版字段如下：

| 字段 | 写入节点 | 生命周期/约束 |
|---|---|---|
| `request_id/deadline_at` | api/start | required；全图只读 |
| `trusted_identity/effective_authorization` | auth_context | 最小结构；不含原始 JWT/完整权限响应 |
| `planning_context/plan_candidate` | context/plan | context 最小投影；候选不可信 |
| `validated_plan/selected_capability` | validate | 只有确定性 validate 可写 |
| `query_result/aggregate_result` | query/aggregate | 互斥严格 DTO；仅所属能力节点可写 |
| `search_hits/evidence_package/model_output` | DOCUMENT 子图 | 仅 DOCUMENT 分支；逐节点收窄且有数量/大小上限 |
| `secured_result/error` | result_security/safe_response | Graph 输出唯一来源；error 仅安全码/参数，不含异常正文 |

JWT、服务密钥、HTTP Client、Prompt 模板、完整原文和模型原始响应不得进入 State。节点只返回自己的局部更新；同一字段不得由两个非终止节点竞争写入。图以封闭 input/output schema 调用`builder.compile()`且**不传 checkpointer**；output 仅含`request_id/secured_result/safe_error`。不使用 `thread_id`，请求结束后 State 释放，不支持恢复、持久记忆、time travel 或人工中断。LangSmith/第三方 tracing 默认关闭，避免 State/Prompt 外发。

## 10. 详细功能与核心处理流程

### 10.1 固定图拓扑

```text
START -> auth_context -> plan -> validate
validate -> query | aggregate | document | clarify | reject
document -> retrieve -> evidence_gate -> generate_or_summary -> citation_gate
query/aggregate/citation_gate -> result_security -> END
clarify/reject/任一安全失败 -> safe_response -> END
```

`auth_context/validate/query/aggregate/retrieve/evidence_gate/citation_gate/result_security`必须是确定性节点；`plan/generate_or_summary`是仅有的模型节点。条件边只读取封闭枚举，不执行网络调用。图没有返回上游节点的边，没有模型自主 Tool loop，也不在运行时注册节点。

### 10.2 确定性校验流水线

1. 严格 JSON 解析和顶层 outcome 校验；
2. capability/domain 必须在当前授权候选集中；
3. 选择唯一能力 Validator；
4. 能力 Validator 校验字段、操作符、函数、值类型、排序、分页和资源预算；
5. 生成不可变 `ValidatedPlan`，只含 canonical 值；
6. capability 执行器只接收 `ValidatedPlan`，禁止接收模型原始 JSON。

Validator 不做网络调用，不依赖模型，不默默删除非法过滤条件。信息不足返回 `CLARIFICATION_REQUIRED`；违反白名单返回 `MODEL_OUTPUT_INVALID` 或 `FORBIDDEN`，两者不得混淆。

### 10.3 请求执行算法

```text
FastAPI JWT + Pydantic request validation
 -> build initial AgentState(requestId/deadline)
 -> await compiled_graph.ainvoke(state) without checkpointer/thread_id
 -> graph executes auth/plan/validate/one branch/result security
 -> Pydantic response serialization + audit
```

- 模型规划失败不切换到字符串规则猜测；可对明确的瞬时连接失败重试一次，但必须生成新调用并受剩余 deadline 限制。
- 一个请求只执行一个能力，不跨域 join，不形成模型自主循环。
- `CLARIFY`不调用业务/检索上游；用户回答通过新的 HTTP 请求进入。
- FastAPI 客户端断开或 deadline 到期后取消图调用；每个节点在远调前后检查 deadline，迟到响应不得更新 State。

## 11. 超时预算

`deadline = min(receivedAt + requestedTimeout, receivedAt + configuredMax)`。每次远调超时为 `min(componentMax, deadline-now-safetyMargin)`；不足最小预算时直接 `TIMEOUT`。

首版建议预算比例仅作为配置默认值：Auth 10%、规划 35%、能力执行 35%、结果安全/序列化 20%。代码使用绝对剩余时间，不串联相对 timeout。业务读取最多一次幂等重试；写入、未知发送结果和整个请求不得自动重试。

## 12. 并发、幂等与事务边界

- 接口是只读编排，不提供业务写能力；相同问题的重复请求是独立请求，不承诺去重。
- `requestId`由服务生成，不把调用方 id 当授权或幂等证明。
- Agent 不开启跨上游事务；本地无业务数据库事务。
- httpx 客户端不得持锁等待；`AgentState`不得跨请求共享或写入进程级全局变量。
- LangGraph 节点级 retry policy 首版不设全局默认；需要重试的只读 Client 在自身边界按 AD-09 显式实现。

## 13. 错误分类与安全审计

审计字段：`requestId`、主体不可逆摘要、tenant 引用、capability/domain、策略版本、模型目标 ID、上游服务码、阶段、耗时、结果码、返回条数/引用数。禁止 message/history/plan 原文/结果正文/JWT/secret/完整资源 ID 集合。

无法写普通审计不应返回敏感结果；安全审计后端不可用的具体策略在 02 配置为失败关闭或受控降级，但必须有指标和告警。

## 16. 风险与待确认事项

风险是 LangGraph 版本/API 演进、模型计划稳定性、同步预算和 Python/Java 安全合同。通过锁定兼容版本、图/状态回归、严格 Validator、deadline 指标和实现前 PoC 控制；若硬性 Java-only 约束被证实，只能重新评审 LangGraph4j 备选，不能增加 Java 主编排旁路。

官方依据：`StateGraph`节点以共享 state 传递局部更新，图需 compile 后 invoke；checkpointer 才提供 checkpoint/thread 持久化与恢复。本设计显式不配置：<https://reference.langchain.com/python/langgraph/graph/state/StateGraph>、<https://docs.langchain.com/oss/python/langgraph/persistence>。
