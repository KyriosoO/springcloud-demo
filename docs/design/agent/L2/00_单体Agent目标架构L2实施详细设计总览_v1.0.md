## 6. 目标基线与关键差距

### 6.1 九项目强制映射

| 旧项目 | 历史资产 | 新目标项目 |
|---|---|---|
| `agent-adapter-api` | `agent-adapter-api_alpha` | `agent-adapter-api` |
| `agent-adapter-document` | `agent-adapter-document_alpha` | `agent-adapter-document` |
| `agent-adapter-employee` | `agent-adapter-employee_alpha` | `agent-adapter-employee` |
| `agent-adapter-transaction` | `agent-adapter-transaction_alpha` | `agent-adapter-transaction` |
| `agent-api` | `agent-api_alpha` | `agent-api` |
| `agent-runtime` | `agent-runtime_alpha` | `agent-runtime` |
| `agent-service` | `agent-service_alpha` | `agent-service` |
| `es-query-api` | `es-query-api_alpha` | `es-query-api` |
| `es-query-service` | `es-query-service_alpha` | `es-query-service` |

`*_alpha` 只保存历史项目资产：不得进入根 POM、profile、活动依赖、默认构建、安装、发布、启动、服务注册或活动 CI。新同名项目从空目录建立，不复制旧源码、生成物、配置、依赖或秘密。旧 ES 机制也必须先随项目隔离，之后才能按证据决定重新实现、选择性迁移或退出。

### 6.2 当前关键差距

| 差距 | 当前影响 | 关闭位置 |
|---|---|---|
| `DB-02-001`：两个活动消费者仍编译使用旧 API 类型 | 阻塞 P0 授权和 Preflight；不得通过依赖 alpha 或向空 API 复制旧类型规避 | 单独评审并实施消费者迁移或活动根模块退出方案，形成 `ExternalConsumerResolutionRef` |
| Runtime OpenAPI 存在多份资源及生成链权威不清 | 阻塞跨运行时契约实现 | 01 跨运行时契约与生成治理 |
| 旧检索服务暴露物理索引/裸 DSL，并拥有融合逻辑 | 与逻辑查询、管理隔离和 Agent 编排责任冲突 | 检索查询/管理专题及 DOCUMENT 专题 |
| 生命周期、权限、重试、版本指纹和质量证据尚未形成目标闭环 | 阻塞相应能力实现和生产判断 | 03 及后续条件专题 |

## 7. 责任分解与依赖设计

| 层级/主体 | 唯一责任 | 不承担 |
|---|---|---|
| L2 总览 | 专题编排、门禁、跨专题一致性 | 字段、类、DDL 和实现选择 |
| 02 基线隔离 | 九项目归档、新骨架、活动入口隔离、恢复与验收 | 业务契约迁移、功能实现和数据迁移 |
| 01 契约治理 | Java OpenAPI、生成物、版本与兼容规则 | 生命周期和业务编排 |
| 03 DOCUMENT | Agent 内 DOCUMENT 编排、工具调用和评价 | 检索原子通道实现 |
| 生命周期/安全专题 | 状态、事务、权限、审计、重试和迟到结果 | 扩大上位信任边界 |
| 检索专题 | 查询/管理、索引、manifest、表示和原子召回 | Agent 级融合、精排和回答 |

上述划分以业务能力内聚、跨层契约稳定和最小耦合为判断依据：状态与控制留在 Java，动态编排留在 Python，原子检索留在检索域；不为总览新增运行时抽象。最小变更原则是只新增必要专题和门禁，不在总览中复制专题实现细节。

目标依赖方向固定为：调用方 → Java Agent 控制面 → Python Runtime 编排面 → Java Tool/Adapter → 检索查询面。管理面、数据迁移和历史 `*_alpha` 均不得进入该运行链路。

## 8. 核心流程、实施顺序与设计规则

### 8.1 阶段门禁

| 阶段 | 主要输出 | 进入条件 | 退出条件 |
|---|---|---|---|
| P0 | 02：历史资产隔离、同名空骨架、活动入口和验证报告 | 02 通过评审；`DB-02-001` 已关闭；另行取得代码授权 | 九项目隔离完整；活动图无 alpha；目标骨架无业务/数据能力；报告为 `P0_VERIFIED` |
| P1 | 01：跨运行时契约；03：DOCUMENT；生命周期/状态基础 | P0 已验证且上位输入足够 | 契约、状态、失败和测试追踪闭合 |
| P2 | 查询/管理、索引、表示、安全、上下文和适配器专题 | 对应依赖专题已关闭 | 单一责任、权限和迁移门禁可验证 |
| P3 | 韧性、性能、观测、部署和生产评价 | 功能基线稳定并有目标实跑环境 | SLO、回滚、质量证据和生产批准分别关闭 |

当前状态：P0 设计可继续评审，但因 `DB-02-001` 未关闭，不得执行 P0；P1 及后续专题不得形成可执行实现授权。

### 8.2 设计规则

| 规则编号 | 规则 | 失败结果 |
|---|---|---|
| DR-001 | 权威顺序固定为 L0 → 对应 L1 → 本总览 → 专题 L2；历史文件只作证据 | `DESIGN_AUTHORITY_CONFLICT` |
| DR-002 | 九个旧项目全部按第 6.1 节隔离；目标项目不得原地改造、复制或依赖旧项目 | `TARGET_BASELINE_NOT_ISOLATED` |
| DR-003 | P0 后才可在新 `agent-api`、`agent-runtime` 上冻结唯一契约源、生成物和版本行为 | `RUNTIME_CONTRACT_NOT_FROZEN` |
| DR-004 | 保持 Java → Python → Java Tool → 检索原子能力方向；DOCUMENT、融合、精排和回答归 Agent | `RESPONSIBILITY_LEAKAGE` |
| DR-005 | 状态、权限、事务、重试、查询/管理隔离和迟到结果必须有唯一责任及失败关闭证明 | `IMPLEMENTATION_GATE_NOT_MET` |
| DR-006 | P0 未验证前不得启动其他专题的代码实施；`*_alpha` 不具活动回滚资格 | `PHASE_ORDER_VIOLATION` |
| DR-007 | 不扩大模型、文档源、权限范围或首期 ACL 粒度；缺少事实时失败关闭 | `TRUST_SCOPE_EXPANDED` |
| DR-008 | 固定包、目标实跑、业务代表性结果和生产批准分开记录 | `QUALITY_EVIDENCE_MISUSED` |
| DR-009 | 缺少外部契约、身份载体、manifest、SLO/HA 等关键输入时登记阻塞，不虚构细节 | `DESIGN_INPUT_UNRESOLVED` |
| DR-010 | 实质变更后重新校验当前文档及其下游；历史评审结论不自动继承 | `REVIEW_EVIDENCE_STALE` |

### 8.3 错误分类与调用方可见语义

- 基线/顺序错误：`TARGET_BASELINE_NOT_ISOLATED`、`PHASE_ORDER_VIOLATION`，调用方必须停止后续实施。
- 契约/责任错误：`RUNTIME_CONTRACT_NOT_FROZEN`、`RESPONSIBILITY_LEAKAGE`，专题保持 Draft 并返回对应责任人处理。
- 输入/评审错误：`DESIGN_INPUT_UNRESOLVED`、`REVIEW_EVIDENCE_STALE`，补齐输入或重新评审后才能重试。
- 安全/质量错误：`TRUST_SCOPE_EXPANDED`、`QUALITY_EVIDENCE_MISUSED`，不得降级为警告或生产例外。

## 9. 跨专题工程约束

- 接口：Java OpenAPI 是跨运行时契约唯一权威；Python 模型必须由受控流程生成，不手工漂移。
- 数据：MySQL 是执行状态权威；检索索引/Alias 是派生资产；P0 不执行 SQL、Flyway、ES 或 Alias 写入。
- 一致性：远程调用在事务外执行；终态单调；重试只由指定层负责；迟到结果不得覆盖终态。
- 安全：权限在召回前硬过滤且只能收紧；秘密、正文和业务数据不得进入设计/迁移证据。
- 发布：设计通过、代码实施、目标质量验证和生产批准是四个独立门禁；任何一级不得替代下一级。
- 恢复：阶段动作必须先记录意图、后记录结果；中断后只做只读恢复检查，不自动 `reset`、`clean` 或删除历史资产。
