## 3. 背景、目标与范围

### 3.1 背景与问题

三份新架构文档已经明确采用绿地目标架构：现有 `agent-*`、`es-*` 代码以及 `P1_V2/P2_V3` 只提供现状事实和迁移证据，不能反向成为新设计的默认基线。其中，当前根目录七个 `agent-*` 与两个 `es-*` 项目全部属于旧资产，必须先重命名为对应 `*_alpha`，再以原名称建立全新目标项目；不得在当前原名项目上继续实施、原地改造或建立新目标依赖。旧 Agent 只提供事实证据，旧 ES 内部机制也只能在项目隔离后经门禁选择性迁移。当前仓库同时存在可供行为核对的历史机制和与目标边界冲突的旧实现，例如 Java 契约生成、短事务生命周期已经形成，而检索服务仍暴露物理索引/裸 DSL 接口并拥有混合检索融合逻辑。

若直接按现有包名、接口或历史 L2 继续编码，会产生三类风险：旧边界被无条件继承、同一语义形成多份权威、专题 L2 在外部契约未冻结时虚构字段。本文先冻结 L2 治理和迁移分类，不替代各专题的字段级、状态级和实现级详细设计。

### 3.3 范围内

- 三份 L0/L1 到 L2 的权威关系和冲突处理顺序；
- 当前 Java、Python、Adapter、检索和评价资产的高层差距与迁移分类；
- 七个现存 `agent-*` 与两个现存 `es-*` 的 `_alpha` 隔离映射、同名新项目建立顺序和阶段 0 硬门禁；
- 首批可启动专题、受前置输入阻塞的专题及其边界；
- L2 编写、独立评审、实施授权、迁移和退出的门禁；
- 文档级追踪、验证命令和风险登记。

### 3.4 范围外

- 修改 Java、Python、SQL、OpenAPI、配置、测试、脚本或部署资产；
- 冻结 Runtime、业务服务或检索接口的具体字段和错误码；
- 选择 Agent/检索技术状态的最终表结构、并发算法或数据保留周期；
- 修改 `auth-service`、`employee-service`、`mq-procedure-service` 的公共契约；
- 更新 2026-07-17 的历史评审报告或将 Draft 文档标记为 Approved；
- 执行生产迁移、Alias 切换、Provider 启用或发布。

### 3.5 非目标

- 不把旧 P1/P2 文档重新汇总成另一套架构基线；
- 不为尚未确认的多 Agent、文档级 ACL、写能力或通用工作流预建实现；
- 不把 `_alpha` 重命名本身表述为迁移完成；它只是防止旧资产污染新目标的必要前置，后续仍须按新 L0/L1 和专题 L2 独立建设；
- 不把合成评价包存在或 Oracle 自测通过表述为目标系统质量通过。

### 6.3 迁移分类规则

#### 6.3.1 `agent-*`、`es-*` 强制隔离规则

现存 `agent-*`、`es-*` 均不参与项目级“保留验证/目标改造/隔离退出/待确认”四选一：九个现存项目统一判定为旧项目，必须先整体隔离。阶段 0 按下表执行项目级映射；`_alpha` 固定追加在完整原项目名末尾，任何内部机制的迁移价值都不能豁免项目级隔离。

| 现存旧项目 | 隔离后旧项目 | 隔离后必须新建的目标项目 | 目标项目实施约束 |
|---|---|---|---|
| `agent-adapter-api` | `agent-adapter-api_alpha` | `agent-adapter-api` | 仅按新 L0/L1 与专题 L2 建立，不依赖旧 Adapter API |
| `agent-adapter-document` | `agent-adapter-document_alpha` | `agent-adapter-document` | 重新建立 DOCUMENT Adapter 边界，不继承旧编排所有权 |
| `agent-adapter-employee` | `agent-adapter-employee_alpha` | `agent-adapter-employee` | 依据冻结后的 employee 外部契约重建 |
| `agent-adapter-transaction` | `agent-adapter-transaction_alpha` | `agent-adapter-transaction` | 依据冻结后的 transaction 外部契约重建 |
| `agent-api` | `agent-api_alpha` | `agent-api` | 重新建立 Java 契约权威和生成源，不依赖旧制品 |
| `agent-runtime` | `agent-runtime_alpha` | `agent-runtime` | 重新建立 Python 编排与生成物边界，不复制旧运行时作为起点 |
| `agent-service` | `agent-service_alpha` | `agent-service` | 重新建立 Java 控制/状态面，不原地修改旧服务 |
| `es-query-api` | `es-query-api_alpha` | `es-query-api` | 重新建立类型化逻辑查询/管理契约，不以旧物理索引或裸 DSL 契约为目标基线 |
| `es-query-service` | `es-query-service_alpha` | `es-query-service` | 重新建立原子检索与索引生命周期边界，不拥有融合、精排或回答；旧机制只可在隔离后按证据选择性迁移 |

隔离动作必须覆盖项目目录及所有会与新项目冲突的构建模块、制品坐标、启动脚本、服务注册、配置命名空间、状态表、ES Alias 和可写资源引用。若运行平台不接受下划线服务名，运行时注册名可以采用平台允许的独立 alpha 名称，但项目目录和项目标识仍使用上表 `_alpha`，且不得与新项目共享注册名。`agent-*_alpha` 仅作只读事实证据，不得成为新项目的源码、模块、制品、运行时调用、代码迁移源或默认回滚依赖；`es-*_alpha` 同样必须先隔离，只有其内部机制可经第 6.3.2 节和 02 的证据门禁选择性迁入或重新实现到全新项目，新项目仍不得依赖 `_alpha` 模块、制品或运行时。本文不授权执行实际重命名或新建代码项目。

#### 6.3.2 隔离后 ES 内部机制与其他非目标项目资产分类规则

下列四类只适用于完成项目级隔离后的 `es-*_alpha` 内部机制，以及评价工件、外部适配资产等非目标项目资产；不适用于九个旧项目本身，也不适用于 `agent-*_alpha` 内部代码。即使某项 ES 机制被判定可迁移，也只能在全新 `es-*` 中显式迁入或重新实现并补齐验证，不能直接依赖或原地修改 `es-*_alpha`。

| 分类 | 判定条件 | 允许动作 | 禁止动作 |
|---|---|---|---|
| 保留验证 | 隔离后的 ES 内部机制或其他非目标项目资产，其责任、依赖方向和安全语义与新 L0/L1 一致，且专题 L2 能给出测试证据 | 专题 L2 将该机制列为迁移候选，在全新目标项目中显式迁入或重新实现并补齐必要门禁 | 用于豁免任一旧项目的 `_alpha` 隔离，或形成新项目到 `_alpha` 的依赖 |
| 目标改造 | 隔离后的 ES 内部机制或其他非目标项目资产存在复用价值，但契约、所有权、事务、权限或兼容语义不完整 | 专题 L2 列出迁入新项目后的最小修改点、调用方、测试和回滚 | 原地修改 `_alpha`、直接复制历史 L2 的字段或状态结论 |
| 隔离退出 | 行为违反新边界，或会形成第二权威/绕过路径 | 先阻断新调用，再迁移，最后以引用扫描和运行验证退出 | 未建立替代和回滚证据前删除生产资产 |
| 待确认 | 缺少外部契约、权威选择、生产数据或责任人证据 | 登记影响、关闭条件和是否阻塞 | 以假设填充公共字段、DDL、权限或 SLO |

### 7.3 内聚与耦合判断

总览只拥有治理与迁移判断，不复制专题字段。项目级基线隔离集中在 02，是因为九个旧项目必须以一个原子门禁完成 `_alpha` 映射、冲突清理和同名新项目验收，不能由各业务专题各自决定是否保留；跨运行时契约集中在 01，是因为新 Java 类型、新 OpenAPI、新 Python 生成物和兼容门禁必须一起变化；DOCUMENT 编排和评价集中在 03，是因为召回策略、融合、证据、回答、引用与拒答共同形成一条用户可验证闭环。检索域只提供原子能力，从而避免 Agent 与检索同时拥有融合或排序权威。

#### 8.1.2 输入、输出与前置条件

- 输入必须包含目标专题、对应 L1 主题、当前代码/契约/测试路径、明确的修改权限和已知外部前置。
- 专题开始前先判断其上位约束是否一致；任一 S0/S1 或父级冲突未闭环时停止。
- 除 02 外，专题输入必须包含阶段 0 验收证据：九个 `_alpha` 目录存在、九个原名新项目存在、构建/注册/配置/状态/ES Alias/可写资源无冲突，且新项目无 `_alpha` 依赖。
- 输出至少包含 `REQ/CON → DR → IMPL → TEST → VAL`、资产分类、非责任、风险和当前状态。
- `Draft` 专题可继续设计和自检，但不能作为代码实现或生产变更授权。

#### 8.1.3 正常流程

1. 首先编写并独立评审 02，冻结九个项目映射、所有冲突引用、隔离执行、同名新建、失败恢复、ES Alias/资源隔离和验收命令。
2. 取得单独代码实施授权后执行阶段 0；九个旧项目整体进入 `_alpha`，随后建立九个全新原名项目，不以复制 `_alpha` 目录作为脚手架。
3. 验证新旧构建、模块/制品、启动脚本、服务注册、配置、状态表、ES Alias 和可写资源隔离，并证明新项目无 `_alpha` 依赖。
4. 阶段 0 通过后，从本文清单选择 01、03 或其他无父级阻塞专题；`agent-*_alpha` 只提供最小行为事实，`es-*_alpha` 另提供可选择迁移机制的候选证据，新项目现状才是目标实施落点。
5. 只对隔离后的 ES 内部机制和其他非目标项目资产做四类迁移判定，绝不用于 `agent-*_alpha` 代码；对新 Agent/ES 触点按 L0/L1 独立设计正常、边界、失败、超时、取消、兼容、回滚和验证行为。
6. 完成专题内部自检和严格校验，独立评审后再申请对应实现授权。
7. 实施完成后以新项目代码/契约/测试证据回写专题状态；生产批准仍走独立门禁。

#### 8.1.4 分支与边界条件

- 若一个专题同时需要修改两个 L1 的权威边界，则停止专题，回到三份架构联合治理。
- 若任一专题把当前原名 `agent-*`/`es-*` 或隔离后的 `_alpha` 路径标记为目标 `已存在`、`建议修改` 或实现依赖，立即以 `TARGET_BASELINE_NOT_ISOLATED`/`LEGACY_PROJECT_DEPENDENCY_FORBIDDEN` 阻塞；隔离后的 ES 内部机制只能作为迁移候选，行为相似不能豁免项目级隔离或形成直接依赖。
- 若隔离后的 ES 内部机制或其他非目标项目资产符合目标约束但缺少可失败的测试，只能判为“保留验证”，不能直接判定“无需变更”。
- 若公共契约字段或数据库结构需要变化，专题可记录候选方案，但在未取得明确授权前不得修改契约或 Schema。
- 若旧入口仍有调用方，隔离退出必须先建立调用扫描、兼容窗口、观测和回滚证据，不得直接删除。
- 若固定评价包通过但目标报告缺失，专题可进入设计评审，不得进入系统质量通过或生产批准状态。

## 9. 条件设计章节

### 9.1 接口与跨语言契约

本文不新增或修改运行时接口。阶段 0 通过后，01 专题必须在全新 `agent-api`、`agent-runtime` 中确认：Java 类型是规范源；发布 OpenAPI 只有一个受控产出；测试快照如保留必须由同一产出派生；Python 生成物禁止手改；必填/可空/默认/枚举未知值、错误、deadline/cancellation、版本、指纹、能力、混合版本和回滚均有契约测试。旧 `agent-api_alpha`、`agent-runtime_alpha` 的类型、脚本和制品只能用于差异核对，不能成为新生成链依赖。

### 9.2 数据与生命周期

本文不设计运行时表或索引。02 必须把旧 Agent 状态表以及旧 ES 索引、Alias、配置命名空间、注册名及可写资源纳入阶段 0 冲突清单，确保 `_alpha` 与新同名项目不共享写入权威；生命周期/检索专题再分别给出现有表、索引、Alias、状态记录的所有者、保留/删除、迁移、回滚和退出证据。历史资产在物理删除前必须先从新写入路径隔离；涉及生产数据删除时必须单独授权。

### 9.3 状态、并发与一致性

本文只定义设计治理状态，不定义 Agent 运行时状态。任何生命周期专题都必须保持：本地短事务提交后再远程调用；远程等待不持有数据库事务、锁或不可重入上下文；终态单调；迟到结果只作诊断；重试不延长绝对 deadline；跨服务不使用分布式事务或全局锁。

### 9.4 权限、安全、风控与审计

首期权限范围固定为语料库级，不启用文档级 ACL。Java 组合 RBAC、Agent 字段策略和资源属性，下游只能收紧。迁移扫描和审计只记录路径、稳定 ID、版本、摘要、判断和责任人，不记录密钥、完整 Prompt、正文或敏感业务结果。

### 9.5 性能、容量与资源预算

本文不承诺生产 SLO。专题可设计预算传播和测试方法，但生产延迟、吞吐、并发、重建时长、撤权传播、RTO/RPO 和容量值必须来自责任方和代表性负载；缺失时保持阻塞，不采用当前测试配置默认值。

### 9.6 发布、迁移与回滚

迁移首先执行阶段 0：冻结映射与冲突清单，获得代码实施授权，整体重命名九个旧项目，验证 `_alpha` 可隔离归档，再建立九个原名新项目并证明无旧依赖；只有完成该隔离后，才可对 `es-*_alpha` 内部机制执行选择性迁移判定。任一步失败都应停止后续专题并恢复到不会产生新旧同名冲突的状态；不得以删除旧资产完成回滚。阶段 0 后遵循“双轨验证而非双重权威”：允许在受控环境比较新旧结果，但只有新目标路径可形成未来权威；旧路径不得在异常时自动绕过权限、契约或围栏。每批迁移必须包含前置扫描、兼容窗口、开关/路由、观测、回滚资格、退出条件和删除授权。`_alpha` 不因“历史可用”自动取得生产回滚资格。

### 9.7 日志、监控与告警

设计/迁移证据统一关联目标文档版本、代码提交、契约指纹、资产路径和验证命令。运行时遥测由专题设计稳定 Port；禁止为了 L2 总览引入具体监控后端。告警阈值属于性能/运维专题，当前仅要求能发现契约漂移、旧入口新调用、权限失败、围栏未知和迁移批次失败。
