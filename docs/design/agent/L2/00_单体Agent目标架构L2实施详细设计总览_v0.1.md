## 3. 背景、目标与范围

### 3.1 背景与问题

三份新架构文档已经明确采用绿地目标架构：现有 `agent-*`、`es-*` 代码以及 `P1_V2/P2_V3` 只提供现状事实和迁移证据，不能反向成为新设计的默认基线。当前仓库同时存在可复用机制和与目标边界冲突的历史实现，例如 Java 契约生成、短事务生命周期已经形成，而检索服务仍暴露物理索引/裸 DSL 接口并拥有混合检索融合逻辑。

若直接按现有包名、接口或历史 L2 继续编码，会产生三类风险：旧边界被无条件继承、同一语义形成多份权威、专题 L2 在外部契约未冻结时虚构字段。本文先冻结 L2 治理和迁移分类，不替代各专题的字段级、状态级和实现级详细设计。

### 3.2 目标与验收行为

| 需求编号 | 目标或用户可观察行为 | 验收标准 | 来源 |
|---|---|---|---|
| REQ-001 | 建立唯一 L2 权威入口 | 新任务从本文进入，L0/L1 为上位权威，历史 L2 只作来源证据 | L0 第 4、11～12 节；两份 L1 第 12/13 节 |
| REQ-002 | 冻结首批专题边界和顺序 | 每个专题有唯一责任、上位约束、前置输入、非责任和进入门禁 | 两份 L1 的 L2 下位交付表 |
| REQ-003 | 对当前资产做可验证迁移分类 | 每个关键资产标记为保留验证、目标改造、隔离退出或待确认，不因“已实现”自动保留 | `AD-01`、`DEC-01` |
| REQ-004 | 防止设计越权触发实现或公共契约变化 | 本文不修改代码、契约、DDL、配置和历史文档；专题 L2 与实施分别授权 | 文档治理规则；L1 风险与门禁 |
| REQ-005 | 建立从架构约束到专题、实现和验证的追踪 | 所有范围内设计规则均映射到 `IMPL-*`、`TEST-*` 和 `VAL-*` | L0 第 14 节；两份 L1 一致性章节 |

### 3.3 范围内

- 三份 L0/L1 到 L2 的权威关系和冲突处理顺序；
- 当前 Java、Python、Adapter、检索和评价资产的高层差距与迁移分类；
- 首批可启动专题、受前置输入阻塞的专题及其边界；
- L2 编写、独立评审、实施授权、迁移和退出的门禁；
- 文档级追踪、验证命令和风险登记。

### 3.4 范围外

- 修改 Java、Python、SQL、OpenAPI、配置、测试、脚本或部署资产；
- 冻结 Runtime、业务服务或检索接口的具体字段和错误码；
- 选择 Agent/检索技术状态的最终表结构、并发算法或数据保留周期；
- 修改 `auth-service`、`employee-service`、`mq-procedure-service` 的公共契约；
- 更新 2026-07-17 的历史评审报告或将 Draft 文档标记为 Approved；
- 执行生产迁移、Alias 切换、Provider 启用或发布。

### 3.5 非目标

- 不把旧 P1/P2 文档重新汇总成另一套架构基线；
- 不为尚未确认的多 Agent、文档级 ACL、写能力或通用工作流预建实现；
- 不以目录重组、统一命名或代码美化代替目标边界迁移；
- 不把合成评价包存在或 Oracle 自测通过表述为目标系统质量通过。

## 6. 当前实现基线与变更摘要

### 6.1 当前实现事实

| 编号 | 已验证事实 | 证据 | 目标架构判断 |
|---|---|---|---|
| BASE-001 | Java Runtime 契约类型位于 `agent-api`，OpenAPI 由 Java 类型构建；Python 模型可从主资源 OpenAPI 生成并校验来源哈希 | `agent-api/src/main/java/com/dylan/agent/api/contract/runtime/`、`AgentRuntimeContractOpenApiFactory`、`agent-runtime/scripts/generate_contract_models.py`、`agent-runtime/scripts/check_contract_drift.py` | 机制可作为候选复用，但治理链须由契约专题重新冻结 |
| BASE-002 | 主资源和测试资源各保存一份相同 OpenAPI；Java 更新开关当前只写测试资源，Python 生成器读取主资源 | 两份文件当前 SHA-256 同为 `02EDFCAF...D86`；全仓引用检查 | 存在双制品漂移窗口，不能直接视为目标单一权威 |
| BASE-003 | `AgentOrchestrator` 本身无事务；`ExecutionLifecycleService` 将 start/checkpoint/finalization 委托给短事务服务，Runtime 规划调用在其外部 | `AgentOrchestrator`、`ExecutionLifecycleService`、`StartTxService`、`CheckpointTxService`、`FinalizationTxService` | 与 AD-10 方向一致，可作为验证后复用候选，不代表目标生命周期已冻结 |
| BASE-004 | employee 与 transaction Adapter 已分模块存在 | `agent-adapter-employee`、`agent-adapter-transaction` | 分域边界可作为候选；字段/错误/权限语义仍受外部契约门禁 |
| BASE-005 | `es-query-service` 同一 Controller 同时暴露物理索引裸 DSL、文档写入/重建、向量查询和内部混合检索 | `EsQueryController` 的 `/indexes/{index}/search`、写/重建和 `/internal/document-search/hybrid` | 与逻辑查询、查询/管理隔离和禁止物理索引参数的目标存在差距 |
| BASE-006 | 检索服务内部存在 `DocumentHybridSearchUseCase` 与 `DocumentRrfMerger` | 对应 Java 类及测试 | 跨路融合属于 Agent DOCUMENT 编排，目标实现不得原样继承该所有权 |
| BASE-007 | Java Agent 已存在 DOCUMENT 处理、证据选择、生成和引用校验资产 | `agent-service/.../capability/document/` | 可作为行为证据和候选实现，需按新 Agent/检索边界逐项判定 |
| BASE-008 | v3 合成评价包及报告 Schema/校验脚本存在，但目标系统未实跑 | `evidence/eb-l1-003/`；L0/L1 明示 `target_system_quality_run_executed=false` | 可启动评价框架设计，不可声明系统质量或生产批准通过 |
| BASE-009 | 当前根目录不存在独立 `es-document-service` 模块 | 根目录模块清单 | 符合禁止新建该服务的方向；现有文档责任仍需在 Agent 与 `es-query-service` 间重新分配 |

### 6.2 当前问题与根因

| 差距编号 | 症状 | 直接原因 | 设计根因 | 影响专题 |
|---|---|---|---|---|
| GAP-001 | 两份 OpenAPI 当前相同但更新链路不统一 | Java 生成测试只写 `src/test/resources`，Python 从 `src/main/resources` 读取 | 契约源码、发布制品、测试快照和生成物的唯一关系尚未冻结 | 01 跨运行时契约 |
| GAP-002 | 检索 HTTP 暴露物理索引名和裸 DSL | 历史通用 ES Controller 兼容多类操作 | 旧实现以 ES 能力为中心，不符合逻辑语料库和类型化原子检索目标 | 检索查询契约、迁移隔离 |
| GAP-003 | 查询和管理动作集中在同一 Controller/入口族 | 历史服务按资源操作聚合 | 目标要求契约、身份、入口、资源池和审计隔离 | 检索查询/管理、安全运维 |
| GAP-004 | 混合召回和 RRF 融合位于检索服务 | 历史 DOCUMENT 方案把编排下沉到检索域 | 新架构已把跨路编排、融合和精排归 Agent | 03 DOCUMENT 编排、检索原子通道 |
| GAP-005 | 旧 P1/P2 文档均标记为“已实施”，容易被误作新目标规范 | 文档状态描述旧基线的实现结果 | 新旧权威切换尚无统一 L2 入口和退出清单 | 本文、02 迁移门禁 |
| GAP-006 | 运行时状态、保留/删除、回调和恢复的目标语义尚未完整冻结 | 当前代码采用 Invocation 语义，上位文档使用会话/任务/执行等架构术语 | 目标状态模型需在不被旧命名绑架的前提下独立设计 | 生命周期与持久状态（条件批次） |
| GAP-007 | 固定评价包已存在但没有目标系统实际报告 | 评价工件冻结早于新目标制品实跑 | 评价工件、系统质量和生产代表性属于三个不同门禁 | 03 DOCUMENT/评价、生产批准 |
| GAP-008 | 2026-07-17 评审报告中的目标 SHA-256 已不等于本轮修订后的文档 | 本轮修复了 L0/L1，历史报告保持只读 | 新复核结论尚未持久化为新的报告批次 | 架构治理；不阻塞 Draft L2，阻塞把旧报告作为本轮哈希证据 |

|---|---|---|---|

| 目标改造 | 可复用机制存在，但契约、所有权、事务、权限或兼容语义不完整 | 专题 L2 列出最小修改点、调用方、测试和回滚 | 直接复制历史 L2 的字段或状态结论 |
| 隔离退出 | 行为违反新边界，或会形成第二权威/绕过路径 | 先阻断新调用，再迁移，最后以引用扫描和运行验证退出 | 未建立替代和回滚证据前删除生产资产 |
| 待确认 | 缺少外部契约、权威选择、生产数据或责任人证据 | 登记影响、关闭条件和是否阻塞 | 以假设填充公共字段、DDL、权限或 SLO |

### 6.4 最小变更方案

| 变更项 | 必要性 | 复用内容 | 新增/修改原因 | 不采用的方案及原因 |
|---|---|---|---|---|
| 新增本总览 | 需要唯一的新 L2 入口和迁移规则 | 复用 L0/L1 已冻结 ID 与阶段 | 防止旧 L2/代码反向成为权威 | 不直接改写 P1_V2/P2_V3；会破坏历史事实和扩大范围 |
| 首批只启动 01～03 三个专题 | 这些专题可在现有证据下先形成边界与框架 | Java 契约生成、现有代码触点、固定评价包 | 先关闭跨运行时权威、迁移隔离和 DOCUMENT 所有权三类高风险 | 不一次生成全部 L2；多个外部契约和生产输入尚未冻结 |
| 条件批次保持阻塞登记 | 避免虚构 Auth、业务、manifest、SLO 或状态细节 | 复用现有代码作为发现入口 | 等权威输入具备后再写实现级设计 | 不以旧实现默认值替代新目标决策 |

### 7.2 依赖方向

| 调用方/下位 | 被调用方/上位或契约 | 允许原因 | 禁止绕过路径 | 失败语义 |
|---|---|---|---|---|
| 专题 L2 | 本总览 + 对应 L1 + L0 | 保持约束和责任唯一 | 引用旧 P1/P2 仲裁新架构冲突 | 发现冲突即停止并请求架构治理 |
| Python Runtime | Java OpenAPI 生成的 Python 模型 | 跨语言契约单一来源 | 手写第二套公共模型、直连业务/检索/数据库 | 不兼容或未知字段失败关闭 |
| Java Agent | Python Runtime | 只获取意图/计划或 DOCUMENT 编排结果 | 在远程等待期间持有事务、锁或不可重入上下文 | 超时/取消受 deadline 和栅栏约束 |
| Python DOCUMENT | Java Tool Gateway | Java 独占权限、凭据和外部调用权威 | Python 直连 `es-query-service`/ES/业务服务 | 凭据、权限或围栏不确定时失败关闭 |
| Java Tool Gateway | `es-query-service` 查询面 | 消费类型化逻辑语料库和原子通道 | 物理索引、Alias、裸 DSL、管理端点 | 契约/过滤/兼容/预算失败保持类型化错误 |
| 检索查询面 | ES/Embedding 技术端口 | 执行原子检索 | 融合、Reranker、回答或 RBAC 推断 | 依赖失败按检索域唯一重试预算处理 |

### 7.3 内聚与耦合判断

总览只拥有治理与迁移判断，不复制专题字段。跨运行时契约集中在 01，是因为 Java 类型、OpenAPI、Python 生成物和兼容门禁必须一起变化；迁移清单集中在 02，是因为保留/退出证据跨越多个模块但不拥有其业务规则；DOCUMENT 编排和评价集中在 03，是因为召回策略、融合、证据、回答、引用与拒答共同形成一条用户可验证闭环。检索域只提供原子能力，从而避免 Agent 与检索同时拥有融合或排序权威。

## 8. 详细功能与流程设计

### 8.1 L2 权威接入与专题启动

#### 8.1.1 设计规则

|---|---|---|---|---|

| DR-002 | 每个现有资产必须按“保留验证/目标改造/隔离退出/待确认”四选一分类，并附路径和验证证据 | 专题设计人 | 资产进入实现触点表 | 形成迁移决定，不直接改资产 |
| DR-003 | 首批先冻结跨运行时契约的唯一源码、发布制品、生成物、版本和混合版本行为 | 01 责任人 | 开始 Runtime 相关详细设计 | 关闭 GAP-001 后才能授权对应实现 |

#### 8.1.2 输入、输出与前置条件

- 输入必须包含目标专题、对应 L1 主题、当前代码/契约/测试路径、明确的修改权限和已知外部前置。
- 专题开始前先判断其上位约束是否一致；任一 S0/S1 或父级冲突未闭环时停止。
- 输出至少包含 `REQ/CON → DR → IMPL → TEST → VAL`、资产分类、非责任、风险和当前状态。
- `Draft` 专题可继续设计和自检，但不能作为代码实现或生产变更授权。

#### 8.1.3 正常流程

1. 从本文清单选择一个无父级阻塞的专题，解析对应 L1 约束和同层交接。
2. 读取最小实现调用链、契约源码、生成物、配置和直接测试，记录已存在事实。
3. 对每个触点做四类迁移判定，明确旧行为是否符合目标责任。
4. 设计正常、边界、失败、超时、取消、兼容、回滚和验证行为。
5. 完成专题内部自检和严格校验，独立评审后再申请实现授权。
6. 实施完成后以代码/契约/测试证据回写专题状态；生产批准仍走独立门禁。

#### 8.1.4 分支与边界条件

- 若一个专题同时需要修改两个 L1 的权威边界，则停止专题，回到三份架构联合治理。
- 若现有代码符合目标约束但缺少可失败的测试，只能判为“保留验证”，不能直接判定“无需变更”。
- 若公共契约字段或数据库结构需要变化，专题可记录候选方案，但在未取得明确授权前不得修改契约或 Schema。
- 若旧入口仍有调用方，隔离退出必须先建立调用扫描、兼容窗口、观测和回滚证据，不得直接删除。
- 若固定评价包通过但目标报告缺失，专题可进入设计评审，不得进入系统质量通过或生产批准状态。

#### 8.1.5 异常与终态

| 失败类型 | 触发条件 | 内部表示 | 调用方/流程结果 | 状态/事务影响 | 重试性 | 日志/审计 |
|---|---|---|---|---|---|---|
| 上位冲突 | L0/L1 或同层责任矛盾 | `DESIGN_AUTHORITY_CONFLICT` | 停止专题并请求上位治理 | 无代码/数据变化 | 冲突修复后重启 | 记录文档、章节、冲突约束 |
| 权威缺失 | 公共契约、权限、状态所有者无法确认 | `DESIGN_AUTHORITY_MISSING` | 专题保持 Draft/阻塞 | 无代码/数据变化 | 权威补齐后重启 | 记录责任方和关闭条件 |
| 迁移证据不足 | 旧入口调用方或回滚资格不明 | `MIGRATION_EVIDENCE_INCOMPLETE` | 不允许退出/删除 | 无代码/数据变化 | 补证据后复核 | 记录路径、调用扫描和风险 |
| 越权请求 | 要求在总览阶段改代码/契约/DDL/历史报告 | `SCOPE_AUTHORIZATION_REQUIRED` | 拒绝执行并请求精确授权 | 无代码/数据变化 | 获得授权后按对应任务恢复 | 记录文件与动作边界 |
| 验证失败 | 严格校验、追踪或链接检查失败 | `DESIGN_VALIDATION_FAILED` | 文档不得进入独立评审 | 无运行时事务 | 修复目标文档后重跑 | 保存命令和失败摘要 |

## 9. 条件设计章节

### 9.1 接口与跨语言契约

本文不新增或修改运行时接口。01 专题必须确认：Java 类型是规范源；发布 OpenAPI 只有一个受控产出；测试快照如保留必须由同一产出派生；Python 生成物禁止手改；必填/可空/默认/枚举未知值、错误、deadline/cancellation、版本、指纹、能力、混合版本和回滚均有契约测试。

### 9.2 数据与生命周期

本文不设计运行时表或索引。02 和生命周期/检索专题必须分别给出现有表、索引、Alias、状态记录的所有者、保留/删除、迁移、回滚和退出证据。历史资产在物理删除前必须先从新写入路径隔离；涉及生产数据删除时必须单独授权。

### 9.3 状态、并发与一致性

本文只定义设计治理状态，不定义 Agent 运行时状态。任何生命周期专题都必须保持：本地短事务提交后再远程调用；远程等待不持有数据库事务、锁或不可重入上下文；终态单调；迟到结果只作诊断；重试不延长绝对 deadline；跨服务不使用分布式事务或全局锁。

### 9.4 权限、安全、风控与审计

首期权限范围固定为语料库级，不启用文档级 ACL。Java 组合 RBAC、Agent 字段策略和资源属性，下游只能收紧。迁移扫描和审计只记录路径、稳定 ID、版本、摘要、判断和责任人，不记录密钥、完整 Prompt、正文或敏感业务结果。

### 9.5 性能、容量与资源预算

本文不承诺生产 SLO。专题可设计预算传播和测试方法，但生产延迟、吞吐、并发、重建时长、撤权传播、RTO/RPO 和容量值必须来自责任方和代表性负载；缺失时保持阻塞，不采用当前测试配置默认值。

### 9.6 发布、迁移与回滚

迁移遵循“双轨验证而非双重权威”：允许在受控环境比较新旧结果，但只有新目标路径可形成未来权威；旧路径不得在异常时自动绕过权限、契约或围栏。每批迁移必须包含前置扫描、兼容窗口、开关/路由、观测、回滚资格、退出条件和删除授权。旧资产不因“历史可用”自动取得生产回滚资格。

### 9.7 日志、监控与告警

设计/迁移证据统一关联目标文档版本、代码提交、契约指纹、资产路径和验证命令。运行时遥测由专题设计稳定 Port；禁止为了 L2 总览引入具体监控后端。告警阈值属于性能/运维专题，当前仅要求能发现契约漂移、旧入口新调用、权限失败、围栏未知和迁移批次失败。
