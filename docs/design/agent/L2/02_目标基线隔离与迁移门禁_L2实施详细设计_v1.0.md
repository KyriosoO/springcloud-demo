## 5. 当前事实与阻塞

### 5.1 当前实现事实

- 仓库当前存在七个原名 `agent-*`、两个原名 `es-*` 和一个原名 `document-provider-adapter` 源项目，尚无对应 alpha 目录。
- 九个 Java 当前项目位于 `serviceCenter/pom.xml` 的活动 reactor；`agent-runtime` 是 Python 项目。
- `document-provider-adapter` 直接依赖 `agent-adapter-api`，暴露 DOCUMENT rewrite/embedding/rerank/generation Provider 契约，并回读 `agent-service` 激活信息；它是旧 Agent/DOCUMENT 衍生项目，不是外部业务消费者。
- `document-generation-adapter` 的 8 个跟踪文件已在提交 `28e662a97110f7d3d39211f3ac841a39491fc1b8` 删除，删除前基线为 `b9db2ee0e552d5063aae8bd07ef398532736ed77`；当前同名目录只含未跟踪/已忽略构建残留，不是可移动源项目。
- `employee-service` 拥有员工表、审批变更和消息处理，只是其中 ES 能力直接依赖旧 `es-query-api`；它是业务模块，不得命名为 alpha。
- 默认启动脚本包含 Agent Runtime、Agent Service、ES Query Service；活动工作流 `.github/workflows/agent-contract.yml` 仍验证旧项目。
- 旧 Agent/ES 项目包含状态表、Flyway、ES 索引/Alias 和写入机制；`agent-runtime` 还可能包含被 Git 忽略的 `.env`、`.venv`。
- 父 POM 直接继承 Spring Cloud 相关运行时依赖并配置 Spring Boot 重打包，因此“空 Java 模块”必须显式中和继承能力。

### 5.2 阻塞项 `DB-02-001`

alpha 退出活动构建后，`employee-service` 既不能改依赖 alpha，也不能直接解析到缺少旧类型的新空 `es-query-api`。本文无权选择或实施其公共契约迁移、替代依赖或活动根模块退出方案。`document-provider-adapter` 已纳入 P0 当前项目映射，不再属于本 blocker。

关闭条件：另行形成并通过相关设计，取得独立实施授权，完成消费者变更或模块退出，并提供可追溯的 `ExternalConsumerResolutionRef`。该证据必须证明完整活动 reactor 闭合、无 alpha 依赖、无向新空 API 复制旧类型的假兼容。

当前影响：阻塞 P0 代码授权和 `Preflight`，不阻塞本文继续评审。

受控导出算法固定如下，验证器不得改用工作区检出：

1. 用 `git ls-tree -r --full-tree b9db2ee0e552d5063aae8bd07ef398532736ed77 -- document-generation-adapter` 取得对象模式、对象 ID 和路径；必须与第 5.1 节列出的 8 个普通文件完全一致，模式均为 `100644`，否则 Preflight 失败。
2. 在已解析且仅属于本次 `runId` 的系统临时子目录中执行 `git archive --format=tar --output=<run-temp>/lin-01.tar b9db2ee0e552d5063aae8bd07ef398532736ed77 document-generation-adapter`，再解压到同一临时子目录。禁止使用 `git checkout`、`git restore` 或将内容解压到当前同名残留目录。
3. 对临时导出文件逐项计算 SHA-256，并用对应 Git blob 对象校验字节内容；只有路径、模式、数量和摘要全部匹配且 `document-generation-adapter_alpha/` 不存在时，才将导出根目录一次性移动到 alpha 路径。
4. 仅对 alpha POM 的三个允许点做机械替换：项目 `artifactId`、`name` 及内部依赖 `agent-adapter-api`；替换后再次核对其余 7 个文件字节不变、POM 仅有允许差异。临时目录只在摘要匹配且报告已记录后按精确 `runId` 清理；失败时不得触碰当前忽略残留或其他临时目录。

- 根 POM、任何 profile、活动消费者、默认脚本、活动 CI、安装和发布入口均不得引用 alpha。

Python 空 Runtime 只包含 pyproject.toml、src/agent_runtime/__main__.py 和 tests/test_idle_runtime.py。`project.dependencies` 为空；入口仅使用标准库等待停止信号，不监听端口、不读 `.env`、不创建 HTTP/Tool/图路由或持久状态。测试在受控子进程中验证可启动、可终止且没有项目第三方导入和监听端口。

## 7. 责任分解、关联资源与责任边界

### 7.1 责任分解

| 主体 | 唯一责任 | 禁止行为 |
|---|---|---|
| 实施责任人 | 按授权顺序执行目录、标识、骨架和入口变更 | 跳过阶段日志、自动删除/覆盖或扩大范围 |
| 验证器 | 只读检查现场、写入自身报告并以非零码失败 | 修复项目、代填外部证据或降级失败 |
| alpha 历史资产 | 保存旧事实以供只读核对 | 被构建、依赖、运行、注册、安装、发布或作为目标复制源 |
| 新目标骨架 | 占用原名和目标 GAV并证明绿地边界 | 提供业务兼容、生产流量或外部状态访问 |
| 外部消费者责任人 | 独立关闭 `DB-02-001` | 将消费者切到 alpha 或污染空 API |
| 评审/验收责任人 | 核对文档、授权、报告和阻塞状态 | 把文档通过等同于实施或生产批准 |

### 7.2 依赖方向与调用边界

活动依赖图只允许“根 reactor → 新原名 Java 模块”。alpha、旧脚本/工作流历史文本和 Python Runtime 均不属于 Maven reactor；新 Runtime 在 01 评审前也不进入默认启动或网络链路。

该分解以历史证据内聚、目标能力内聚和活动图最小耦合为判断依据。P0 不新增兼容层、迁移框架或业务抽象；最小变更仅包括释放原名、隔离历史标识、建立空骨架、切断活动入口及增加必要的验证/恢复证据。

### 8.5 验证器最小契约

| Mode | 必填参数 | 成功结果 |
|---|---|---|
| `Preflight` | `OutputPath`、`ExpectedHead`、`AuthorizationRef`、`ExternalConsumerResolutionRef` | 创建 runId，状态 `PREFLIGHT_PASSED` |
| `BeginStage` | `OutputPath`、`RunId`、`Stage`、`ItemId`、`ExpectedEffect` | 在项目动作前持久记录唯一 `STARTED` |
| `Checkpoint` | `OutputPath`、`RunId`、`Stage`、`ItemId` | 后置条件通过后记录 `COMPLETED` |
| `RecoveryCheck` | `OutputPath`、`RunId` | 只读输出现场差异和建议逆序，不修改项目 |
| `PostApply` | `OutputPath`、`RunId` | 核验脚本自有检查及外部证据，写入 `P0_VERIFIED` 或非零失败 |

`Stage` 只允许 `RENAME_PROJECT`、`ARCHIVE_GIT_LINEAGE`、`VERIFY_TARGET_REACTOR`、`CREATE_TARGET_PROJECT`、`ISOLATE_RUNTIME_ENTRY`、`FINAL_VALIDATION`。退出码固定为：`0` 成功、`10` 检查失败、`20` 需要恢复、`30` 参数/schema 非法、`40` 未分类工具错误；调用方不得降级非零码。

全仓候选文件使用 `git ls-files -co --exclude-standard -z` 枚举，并过滤现场实际存在的普通文本文件。alpha 外每个相关命中必须唯一分类为 `must_archive_history`、`must_remain_target`、`evidence_only` 或 `forbidden_active_alpha_reference`；未知、多重分类和任一活动 alpha 引用均失败。忽略文件不读取内容，但新目标项目出现 `.env`、`.venv` 等旧环境资产时直接失败。

### 8.6 错误分类与调用方可见语义

| 失败类型 | 代表错误码/状态 | 调用方动作 |
|---|---|---|
| 前置或授权失败 | `PREFLIGHT_FAILED`、`EXTERNAL_CONSUMER_UNRESOLVED` | 不得开始任何项目动作；修正外部条件后重新 Preflight |
| 映射或完整性失败 | `PROJECT_MAPPING_CONFLICT`、`LEGACY_ASSET_INTEGRITY_FAILED` | 停止当前阶段；不得覆盖、合并或自动修复 |
| 活动图或骨架污染 | `ACTIVE_ALPHA_REFERENCE_FORBIDDEN`、`TARGET_NOT_GREENFIELD` | 阻塞 P0；修复后全量重扫 |
| 外部状态/安全失败 | `EXTERNAL_STATE_WRITE_FORBIDDEN`、`RUNTIME_BASELINE_CONTAMINATED` | 立即停止并保留脱敏证据 |
| 中断或现场不一致 | `RECOVERY_REQUIRED` | 只允许 RecoveryCheck；恢复须再次确认 |
| 工具或 schema 错误 | 退出码 `30`、`40` | 不得降级；修复参数/工具后重跑当前模式 |

## 9. 接口契约、数据生命周期、一致性与安全

### 9.1 接口与契约设计

P0 不修改业务 API、HTTP 路径、字段或错误模型。alpha Maven 标识只用于历史命名空间隔离，不能成为公共依赖；新目标保持原项目标识但不提供旧类型兼容。消费者兼容是 `DB-02-001` 的独立契约设计范围，本文只接受其完成证据。

### 9.2 固定证据

建议新增的权威报告路径为 `docs/design/agent/evidence/baseline-isolation/p0/baseline-isolation-report.json`。报告至少包含：`schemaVersion`、`runId`、`sourceCommit`、上位哈希、授权摘要、`externalConsumerResolutionRef`、状态、当前/待处理阶段、十个当前项目 `items`、LIN-01 `historicalLineage`、阶段转换、检查结果、引用分类、ES 候选、失败码和未决项。

每个项目项至少记录 `itemId`、动作类型、源/目标路径、精确创建路径、前后状态和结果。状态只保存跟踪文件数、忽略资源存在性及非秘密文本 SHA-256；禁止记录密钥、`.env` 内容、完整配置、正文、业务结果、数据库行或 ES 文档。

报告先写同目录 `.tmp`，完成 JSON 和必填字段自检后原子替换；独占锁失败不得写入。未闭合 `STARTED`、报告与现场不一致或只剩临时文件时统一进入 `RECOVERY_REQUIRED`。

### 9.3 数据生命周期与迁移回滚设计

P0 对数据库、索引和 Alias 的生命周期只有“原地保留、禁止写入、只读核对”三种动作；不创建、不复制、不迁移、不删除。旧资源在 alpha 删除前持续保留，后续复用或清理必须由独立专题定义所有权、迁移、回滚和删除授权。

### 9.4 一致性与恢复顺序

P0 依靠干净工作区、单一实施责任人、停止相关进程、报告独占锁和逐动作日志实现排他，不使用数据库事务或生产分布式锁。验证可重复；移动和创建不可盲目重放。

经用户确认后的恢复顺序为：停止本次启动 → 删除本次精确创建且摘要匹配的空骨架 → 恢复本次移动的脚本/CI 历史文本和 alpha POM 标识 → 仅在报告的 LIN-01 路径集/摘要完全匹配时删除本次导出的 `document-generation-adapter_alpha` → 按完成项逆序移动十个当前项目目录。不得触碰当前 `document-generation-adapter/` 忽略残留，不得回退独立授权完成的消费者变更，不得自动上线 alpha。

### 9.5 权限与安全审计设计

- 不自动终止用户管理的进程，不读取生产写凭据，不执行数据库或 ES 写命令。
- `.env`、凭据和完整外部配置只随旧目录物理移动，验证仅记录存在性。
- 旧表、索引、Alias 和本地忽略资源的保留周期不由 P0 决定；删除 alpha 必须另行评审和授权。
- 无获准运行环境时只能证明静态无写路径，不能宣称生产 DB/ES 状态已验证。
