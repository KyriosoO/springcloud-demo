## 3. 设计目标与范围

目标是在最少组件内完成权限只收紧和模型边界安全；范围外如上表。最小必要抽象只增加 Auth/Policy/Projection/Model 四个内聚责任，不建设通用安全平台。

## 4. 当前实现基线、关联资源与责任边界

提交`3e379bc`已形成 Python Agent 安全、Java Auth facade、common-security 独立 purpose/key provider 和 Employee 委托 token 的 P1 最小实现；Auth、common-security 与 Python 相关单元测试已通过。当前仍缺真实 Python→Auth/Adapter HTTP 互操作、完整 sink/注入/结果重验/无秘密 tracing 测试、模型 Client 与供应商门禁。Auth 唯一负责身份/RBAC，LangGraph 的确定性安全节点负责能力/字段/语料库收紧，`agent-employee-adapter`只验证目标委托凭证并转换下游服务身份，业务/文档源负责资源事实，模型不负责授权。

## 5. 模块职责、依赖方向与调用边界

依赖拆为两条单向链：API 边界先经`AuthClient`取得绑定的身份与 Auth 上界，Graph 再按`auth_context -> plan/validate -> authorize -> capability -> result_security`收紧授权；模型链为`plan/generate nodes -> ModelClient -> approved model endpoint`。`auth_context`只形成规划授权上界，`authorize`才在计划确定后结合资源事实形成能力有效授权。确定性安全节点不得依赖或调用 ModelClient；模型节点不得调用 Auth/业务/检索 Client。禁止依赖 Java Agent 编排或旧 common-security 二进制，禁止 Auth Client 返回值或规划授权上界直接成为下游调用授权，禁止条件边或能力节点绕过安全节点。独立 sink DTO 保持内聚并减少安全语义耦合。

## 7. 权威模型

| 事实 | 来源 | 最小字段 | Agent 处理 |
|---|---|---|---|
| 入口身份与 Auth 上界 | `auth-service`目标内部合同`POST /internal/agent/authorization/resolve`；Auth 在一次请求内先用用户 keyset 验签，再解析权限上界 | `trustedIdentity, permissionCodes, allowedCapabilities/domains, identityEvidenceVersion, authEvidenceVersion, validUntil` | API 边界以独立 Agent 服务 token 调用一次；只把严格响应写入初始 State，原始用户 JWT 不入图、不落日志，不接受网关注入头或请求体覆盖 |
| Agent 策略 | 版本化配置 | 权限码到能力/域/字段/操作符/函数/语料库/模型用途的映射 | 只能收紧 |
| 资源事实 | 业务/文档源或检索安全标签 | tenant、资源范围、分类、版本 | 只能增加限制 |
| 请求目的 | 已校验计划 | capability/domain/operation | 不得扩展前述上界 |

授权分两步计算，禁止在计划产生前伪造尚不存在的请求目的或资源事实：

```text
planningAuthorization = trustedIdentity
                      ∩ authUpperBound
                      ∩ agentPolicy(policyVersion)

effectiveAuthorization = planningAuthorization
                       ∩ validatedRequestPurpose
                       ∩ capabilityResourceFacts(sourceVersion)
```

`planningAuthorization`只向规划与确定性计划校验暴露可提议的 capability/domain/字段用途/语料库上界，不是下游调用凭据。`authorize`在`validated_plan`之后解析当前能力所需资源事实：Employee 阶段 A 使用获批准的单租户部署事实，DOCUMENT 使用获批准的 corpus/Profile 事实；后续能力必须各自声明来源。集合为空、未知权限码、未知字段、事实缺失/过期、tenant 不一致、版本不可验证均拒绝，且业务、检索、模型调用计数为 0。不得使用默认 tenant、JWT 本地角色推断或模型补全安全事实。

## 8. 接口与契约设计：Auth 合同与调用

入口认证固定为一个确定性 Auth facade 合同：API 边界调用目标`POST /internal/agent/authorization/resolve`，以独立 Agent 服务 JWT 认证调用方，并在严格请求体的敏感字段中一次性传递用户 Bearer token。Auth 在同一请求内依次完成用户 token 的签名、`kid`、类型、时效和主体校验，再解析 RBAC/权限上界，最后返回绑定同一主体的`TrustedIdentity + AuthUpperBound`、身份/权限证据版本和共同`validUntil`。远程调用只发生一次，但 Auth 内部的身份验证与权限解析仍保持两个责任，不合并事实所有权。

`AgentAuthorizationResolveRequest.userBearerToken`只允许由 API 边界传给 Auth 的用户令牌验证责任，类型和日志格式必须隐藏值；不得进入 Graph State、exception message、审计或 tracing。响应中的身份/权限证据版本只用于新鲜度、排障和授权交集，不是可复用凭据。若目标 facade 合同未获批准，02 的真实认证 PoC 阻塞，禁止回退到共享用户 HMAC 密钥、信任`X-USER-ID`、只解析 JWT 不验签，或重新拆成两个网络调用绕过合同评审。

Python/Java 安全兼容必须形成显式合同夹具：算法、独立 keyset/`kid`、active/previous 密钥轮换、issuer/audience、service subject、scope、签发/过期和错误码。用户令牌验证 keyset、Agent→Auth 服务令牌 keyset、模型 API 凭据三者必须逻辑和秘密隔离；不得复用用户 HMAC 签名密钥作为 Agent 服务令牌密钥。Python 只从相同秘密管理引用读取其被授权的 Agent 服务密钥，不通过 HTTP/Graph State 传递。现有 Auth 单一`JwtDecoder`不满足目标独立服务 keyset，必须按 14.1 节增加专用内部安全链；PoC 未通过前不得宣称现有认证合同可直接复用。

- 超时短于请求剩余预算；不持久缓存正授权；可在同一请求内复用未过期快照。
- 401/403 映射为未认证/禁止；404、未知码、5xx、超时或反序列化失败均失败关闭。
- 现存 Auth 字段级规则不是长期双权威。若目标合同仍返回旧字段，实施时必须明确只采用 Auth 上界字段，Agent 字段策略归本服务；修改 Auth 合同需单独授权并检查调用方。

## 9. 数据设计与生命周期：Agent 策略

首阶段使用受版本控制的 YAML/JSON 配置，不建设策略数据库和控制面。启动时严格校验并冻结不可变快照：

```yaml
version: "1"
permissions:
  EMPLOYEE_READ:
    capabilities: [QUERY, AGGREGATE]
    domains: [EMPLOYEE]
    filterFields: [position, workBaseSi]
    displayFields: [position, workBaseSi]
    sortFields: [position]
    groupFields: [position, workBaseSi]
    metricFields: []
    operators: [EQ, IN]
    functions: [COUNT]
corpora:
  POLICY:
    permissionCodes: [POLICY_DOCUMENT_READ]
    classification: INTERNAL
modelTargets:
  primary-model-candidate:
    enabled: false
    endpoint: "https://approved-model.example/v1"
    model: "approved-model-id"
    credentialRef: "secret://agent/model/primary"
    purposes: [PLAN, DOCUMENT_ANSWER, DOCUMENT_SUMMARY]
    maxClassification: INTERNAL
```

未知顶层项/枚举/引用、重复字段、空 target、非 HTTPS endpoint、白名单外 host、任意 model、内嵌密钥或策略放宽超过 L2 硬上限时启动失败。`credentialRef`只允许秘密管理引用，实际 secret 只装配到`ModelClient`。变更通过配置发布和服务滚动生效；首阶段不做热更新/CAS/审批数据库。生产审批流程属于发布治理，不复制到运行时策略模型。模型 target 默认`enabled: false`；只有供应商数据处理、用途、地域/保留策略和真实效果门禁全部通过后，生产配置才可启用，名称、连通性或兼容协议均不能代替批准证据。

## 10. 详细功能与核心处理流程：数据分级与最小投影

分级只用 `PUBLIC|INTERNAL|RESTRICTED|UNKNOWN`。UNKNOWN 按 RESTRICTED 处理并禁止发送外部模型。结构化字段由 Agent 策略和来源标签共同确定；原始文档由文档源给出分级。用户文本默认 INTERNAL，并经过敏感模式/长度校验；检测器不确定时不发送外部模型。

| sink | 允许 | 禁止 |
|---|---|---|
| `PLANNING` | 问题、有限历史、获准能力/字段 Schema 摘要 | JWT、权限码全集、真实数据、服务地址 |
| `DELEGATED_CALL` | 按目标 audience 绑定一次 Search 或 Business 只读调用的服务身份、subject/tenant、最小数据范围、证据版本和时效 | 用户 JWT、任意 ES/SQL/DSL、其他目标字段、Index/Rebuild 或业务写权限 |
| `DOCUMENT_GENERATION` | 当前问题、获准证据片段、引用 ID | 未授权片段、完整文档、检索安全标签 |
| `FINAL_RESULT` | 当前范围内 DTO 字段和已验证引用 | 隐藏字段、模型额外字段、过期证据 |
| `AUDIT` | IDs 摘要、版本、枚举、数量、耗时 | 正文、Prompt、响应原文、secret |

LangGraph/ASGI/OpenTelemetry/LangSmith 等 callback 或 tracing 不得旁路 sink 投影。首版第三方 tracing 关闭；本地指标只记录节点名、耗时、结果码和数量。启用任何外发 tracing 需要字段级脱敏、供应方数据处理审批、保留期和泄漏负向测试。

每种 sink 使用独立 DTO，不以通用 Map 复用。处理顺序固定为：规划上界校验 → 计划后资源/目的授权 → 字段白名单 → 分级/目的检查 → mask/drop → 数量/长度限制 → 严格序列化。Search 和 Business 调用只有在`effectiveAuthorization`形成后才可签发短时、请求绑定的委托 Bearer JWT。Employee Business token 的接收方是`agent-employee-adapter`；Adapter 同时校验 issuer、audience、固定 typ、Agent 服务 subject、动作 scope、用户范围、证据版本、有效期、`jti=requestId`和请求摘要，随后使用自身服务 token 调 Employee，禁止转发委托 token或用户 token。

Search 使用`typ=agent-search-delegated+jwt`并绑定 logicalIndex/queryText/corpusId/filters/returnFields/page/requestId/deadlineAt；Business 使用`typ=agent-business-delegated+jwt`并绑定目标域严格请求的全部业务字段及`requestId/deadlineAt`。Employee Business audience 固定为`agent-employee-adapter`，Adapter 出站到 Employee 的服务身份固定为`agent-employee-adapter`且 scope 为`agent.employee.query`。首版 Business 的`resourceScopeMode`只允许`SINGLE_TENANT_ALL`；Search/Business audience、typ 和下游服务 token不能交叉使用。

## 11. 模型访问

`ModelClient`输入为 `ModelRequest(purpose, targetId, messages, responseSchema, deadline)`；调用方不能提供 endpoint、API key 或任意 model name。配置将唯一 `targetId` 解析为 endpoint/model/credential reference。

每次发送前检查：target 启用、purpose/domain/分级覆盖、凭据存在、剩余 deadline 足够。失败不自动切换目标。API key 只从环境或秘密管理引用读取，不记录、不放 DTO。ModelClient 只访问配置解析出的 HTTPS 白名单目标，禁止跟随到未批准 host 的重定向。HTTP client 禁止透明写重试；明确未发送的连接失败最多一次新调用。

模型响应必须满足：HTTP/finish reason 合法、大小限制、严格 JSON Schema、未知字段拒绝、枚举/数值/字符串边界、无敏感回显。规划结果还要过 01/03/04 Validator；DOCUMENT 文本还要过引用校验和最终投影。

Prompt injection 控制以权限隔离为主：用户和检索内容都作为数据区输入；系统指令明确不得改变 capability、target、字段和授权；即使检测未命中，模型也没有 Tool/网络/数据库凭据。

## 12. 撤权与结果重验

同一同步请求内可使用未过期 Auth/策略快照。以下情况必须拒绝而非继续：Auth 快照已过 `validUntil`、tenant/主体变化、请求跨越配置版本切换且无法证明旧策略仍有效、文档来源版本/安全标签不一致。

返回前由固定 `result_security`节点以本请求当前有效范围重新投影。由于首阶段无 checkpointer、后台任务和恢复，不设计 execution fence、租约或多副本决定防重放。若以后引入持久图状态，必须先回到 L0/L1 增补 checkpoint、撤权、幂等、重放和清理设计。

## 13. 错误分类与安全审计

安全错误优先使用 `UNAUTHORIZED|FORBIDDEN|MODEL_OUTPUT_INVALID|EVIDENCE_INSUFFICIENT|UPSTREAM_UNAVAILABLE|TIMEOUT`，外部 message 保持通用。内部 `reasonCode`可区分 `SUBJECT_MISMATCH`、`TENANT_UNVERIFIED`、`POLICY_UNKNOWN`、`AUTH_EXPIRED`、`FIELD_FORBIDDEN`、`MODEL_TARGET_DENIED`、`OUTPUT_SCHEMA_INVALID`、`CITATION_INVALID`。

`result_security`必须先构造并校验脱敏审计事件，再交给进程内有界`SecurityAuditSink`接受；事件构造失败、字段越界或本地 sink 拒绝时失败关闭。默认请求路径不等待远端采集器确认，远端投递、重试和保留由部署日志/审计管道负责，不能反向成为所有 Agent 成功响应的可用性依赖。

只有数据分级或外部合规合同明确要求“结果释放前取得持久确认”时，目标 profile 才可配置为`PRE_RELEASE_DURABLE`；该 profile 在已批准的持久审计 sink、SLA、访问控制、保留和删除策略未冻结前保持禁用。开发与测试分别验证默认`LOCAL_ACCEPTED`和显式`PRE_RELEASE_DURABLE`语义，不允许通过假确认启用受限 profile。
