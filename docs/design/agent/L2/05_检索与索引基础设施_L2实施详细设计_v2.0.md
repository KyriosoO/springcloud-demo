## 3. 设计目标与范围

目标是先补齐 Agent 可依赖的稳定 Search 原子能力。范围外/不负责：Agent 规划和问答、原文所有权、默认向量/重排、多写者平台及独立管理服务。当前最小必要抽象只有 Contract、Search 和只读 Registry；Index 与 Rebuild 在前置合同出现后逐阶段增加。

## 4. 当前实现基线、关联资源与责任边界

现状是目标`es-query-api`仅有 POM、`es-query-service`仅有启动类/配置/基础测试；Employee 当前依赖已安装的既有 ES API 产物并由`EmployeeEsService`提供 Search/Vector 编排。该复用只服务 Employee 域查询，不把 Employee Adapter 变成通用检索基础设施，也不证明本 L2 阶段 A Search 已完成。

## 5. 模块职责、依赖方向与调用边界

阶段 A 依赖方向为 `Controller -> Search Service -> read-only Registry -> ES Client`。禁止依赖 Agent 内部类型，禁止绕过 Registry 访问物理索引，禁止 Agent 依赖 ES Client。阶段 B/C 仅在各自准入条件满足后追加 `Index/Source Port` 与 `Rebuild`，不能由阶段 A 预留实现骨架。

内聚与耦合判断：Contract 只因外部 HTTP 合同变化，Search 只因查询/过滤规则变化，Registry 只因逻辑索引和查询 Schema 策略变化。后续 IndexWrite 只因来源版本规则变化，Rebuild 只因来源一致性/发布恢复变化；两者不会预先进入阶段 A。所有能力保留在同一部署单元，不共享 Agent 类型或业务实体。

## 7. 接口与契约设计

跨语言 HTTP 合同的唯一规范源固定为 IMPL-05-J01 指定的 OpenAPI 3.1 文件（复用其 JSON Schema）；Java 服务端类型和 Python `DocumentSearchClient` 类型均由该合同生成或逐字段合同测试约束，不能各自成为第二权威。首版不为“可能出现的 Java 消费者”引入代码生成插件或新生产依赖；是否生成 Java 类型属于后续实现选择，不能改变规范源。

### 7.1 Search

`POST /indexes/{logicalIndex}/search`

```json
{
  "requestId":"018f...",
  "deadlineAt":"2026-07-22T12:00:02Z",
  "queryText":"年假结转",
  "corpusId":"POLICY",
  "filters":[{"field":"documentType","operator":"IN","values":["POLICY"]}],
  "page":{"size":20},
  "returnFields":["title","location","snippet","sourceVersion"]
}
```

约束：logicalIndex/corpus/filter/returnFields 均在服务端 Registry 白名单；queryText 1..4000；filters 最多 10；size 1..100；requestId 为 UUID、deadlineAt 为 UTC RFC 3339 Instant；未知字段、额外 JSON、脚本、正则、任意 sort、cursor/from 深分页和原生 DSL 拒绝。Filter 运算符封闭为`EQ|IN|LT|LTE|GT|GTE`，值在 JSON 中统一为字符串：文本原值、日期用 ISO-8601、数值用无指数规范十进制；EQ/LT/LTE/GT/GTE 恰一值，IN 为 1..50 个同型值，字段类型和允许运算符由 Registry 校验。首阶段仅返回一个受上限约束的结果页，不提供继续翻页；关键词相关度排序，稳定 tie-break 由服务端追加。

HTTP `Authorization`只携带 L2-02 签发的一个短时 `typ=agent-search-delegated+jwt` Bearer 凭证。该凭证同时包含逻辑分离的 Agent 服务身份与本次请求最小用户范围，并绑定 audience、requestId、deadline、logicalIndex、corpus、允许的 securityTags 和规范请求摘要；请求体不重复传授权对象。服务端在访问 ES 前完成签名、keyset purpose、audience、期限、摘要及授权范围校验，任一不一致即失败关闭。规范摘要算法及跨语言夹具由 L2-02 和 OpenAPI 共同冻结；本文不再复制完整 claims 清单或签名实现。

响应每项：`documentId/corpusId/sourceVersion/indexedAt/title/location/snippet/score/classification`，封套返回`requestId/logicalIndexVersion/tookMs/hits`；requestId 必须原样回显并由 Client 校验，`score`必须为 JSON 有限且非负十进制数。`indexedAt`由索引写入事实提供，不能由查询时钟伪造。响应的 hit 数、单 snippet 字符数和序列化总字节受 Registry 硬上限约束；任一 hit 非法时整体失败，不返回物理索引、内部安全表达式或完整原文。

阶段 A 使用严格错误封套`{requestId, code, retryable, message}`且`additionalProperties=false`；稳定错误码仅冻结`INVALID_REQUEST|UNAUTHORIZED|FORBIDDEN|AUTHORIZATION_EXPIRED|INDEX_NOT_READY|UPSTREAM_TIMEOUT|INTERNAL_ERROR`。HTTP 状态、code 和 retryable 映射在 OpenAPI 中唯一声明。外部 message 不暴露物理索引、规则或 ES 原文。仅明确未开始执行的只读连接失败可由唯一 Client 责任方在剩余 deadline 内重试一次，服务端不透明重试。

### 7.2 阶段 B：Index（未冻结实现合同）

阶段 B 只面向一个已批准的权威文档源，提供其最小版本化 upsert/delete；是否需要 bulk 由已验证吞吐需求决定，不预设。进入阶段 B 前必须冻结来源 ID、版本比较、删除事实、重放边界、安全标签与幂等结果；当前不定义路径、DTO 或错误码，不得据此编码。

### 7.3 阶段 C：Rebuild/Cancel/Rollback（未冻结实现合同）

阶段 C 必须先证明来源提供一致快照与连续可重放游标，或提供受审计静默窗口，并明确删除、水位、保留期、切换未知结果与回滚责任。当前不定义任务 API、状态枚举、控制存储和 Alias 操作细节；这些内容需在来源合同与运行约束明确后以单独修订展开。

## 8. Registry 与 Schema

阶段 A `IndexRegistry`只包含 Search 所需的 `logicalIndex/activeAlias/schemaVersion/allowedCorpora/searchableFields/filterFields/returnFields/securityFields/responseLimits`。启动时检查字段映射、securityFields 非空和 Alias 合法；调用方不能看到或指定物理索引。`logicalIndexVersion`来自已存在索引发布事实，Search 只透传，不自行生成。

`sourceAdapter/sourceConsistencyMode/rebuildLimits`属于阶段 B/C，不进入当前配置模型。Schema 不兼容时必须禁用新查询合同并进入后续阶段设计，不能在阶段 A 原地猜测迁移方式。

## 9. 详细功能与核心处理流程：查询实现

1. 验证单个委托 Bearer 的服务身份、用户范围、audience、有效期、requestId/摘要及 logicalIndex/corpus 权限；禁止信任自填用户头、未签名对象或任意 security filter；
2. 严格解析请求并从 Registry 解析字段；
3. 将 queryText 编译为受控 multi-match/等价关键词查询；
4. 将 tenant/securityTags 和业务 filters 作为 bool filter 一并下推；
5. 应用 size、source includes、snippet 长度和绝对 timeout；
6. 严格解析 ES 响应，验证每个 hit 的 corpus/security/version 字段；
7. 返回稳定 DTO。任何安全绑定缺失时整体失败，不返回部分宽结果。

Agent 可在返回后继续裁剪，但不能依赖该裁剪弥补第 4 步缺失。

## 10. 数据生命周期与阶段 B 一致性准入

阶段 A 只查询已存在 Alias，不新增或变更索引数据、Schema、迁移或清理流程；目标 Alias/Schema 不兼容时 Search 保持关闭。Index 设计必须由首个权威来源合同决定稳定 ID、版本顺序、删除事实、摘要与重放语义。最低不变量是：同版本同内容幂等、同版本异内容冲突、旧版本拒绝、删除不被旧事件复活。具体 `_id` 编码、脚本、bulk 与重试策略在阶段 B 冻结，当前不设实现默认值。

## 11. 阶段 C 状态与恢复准入

Rebuild 必须保持单活动所有者、checkpoint 可恢复、切换前无来源缺口、Alias 切换原子、未知结果先读事实再判断、失败不影响旧版本。控制状态使用 ES 隐藏索引、数据库、Redis 或其他机制，须在来源一致性、部署依赖和恢复演练事实明确后选择最小方案；当前不引入控制存储、任务状态机或管理 API。

## 12. 权限与安全审计、运维

- 阶段 A Search 只接受 L2-02 的 `agent-search-delegated+jwt`，使用与用户 keyset 隔离的 Agent 服务 keyset，并以固定 typ/audience/scope 隔离目标用途；在 ES 前校验服务身份与用户范围，不得接受用户 token 或其他用途 token。
- 阶段 B/C 的管理身份、动作 scope 与来源白名单在相应合同展开时定义，不复用 Search 凭证；外部用户和 Agent 请求均不得直接触发管理操作。
- ES 凭据只存在检索服务，Agent 和模型均不可见。
- 日志只记录 query digest、logicalIndex、corpus、过滤数量、耗时、命中数和错误码；不记录 queryText/snippet/content/securityTags 全值。
- 限制请求/响应/bulk/context 大小，并设置 ES timeout、连接池和并发上限。
- 阶段 A 指标：search latency/error/empty-hit、security reject、Alias version。Index conflict、task progress、rollback count 仅在后续阶段出现后增加。

## 13. 当前仓库基线处理与最小变更

当前 `es-query-api`仅见 POM，`es-query-service`仅见启动类/配置/基础测试；完整历史实现位于 `_alpha` 的事实不能自动继承为目标代码。实施阶段应：

1. 对当前模块执行编译和启动基线；
2. 逐项按本 L2 新建最小实现或经审查迁移必要逻辑；
3. 不整体复制 `_alpha`，不恢复旧 Agent/document 依赖；
4. 如需改 employee-service 等现有消费者合同，先取得其范围授权并做兼容测试。
