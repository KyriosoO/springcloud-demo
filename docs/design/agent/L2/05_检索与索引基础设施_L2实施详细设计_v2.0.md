## 3. 设计目标与范围

目标是补齐 Agent 可依赖的稳定原子检索能力。范围外/不负责：Agent 规划和问答、原文所有权、默认向量/重排、多写者平台及独立管理服务。最小必要抽象是 Search/Index/Rebuild/Registry 四个模块。

## 4. 当前实现基线、关联资源与责任边界

现状是当前 `es-query-api`仅有 POM，`es-query-service`仅有启动类/配置/基础测试。关联资源为 ES、文档源和 04 DocumentSearchClient；检索服务负责派生索引，文档源负责原文，Agent 负责问答，不得互改所有权。

## 5. 模块职责、依赖方向与调用边界

`Controller -> Search/Index/Rebuild Service -> Registry/Source Port/ES Client`。禁止依赖 Agent 内部类型，禁止绕过 Registry 访问物理索引，禁止 Agent 依赖 ES Client。稳定 Search DTO 降低 Agent 与 ES 的耦合，各模块按查询/写入/任务保持内聚。

## 7. 接口与契约设计

目标合同可先在 `es-query-api` 定义 DTO；若无第二个编译期消费者，可先由服务 OpenAPI/JSON Schema 管理，避免空模块。最终选择应在实施时根据真实调用方确认。

### 3.1 Search

`POST /indexes/{logicalIndex}/search`

```json
{
  "queryText":"年假结转",
  "corpusId":"POLICY",
  "filters":[{"field":"documentType","operator":"IN","values":["POLICY"]}],
  "securityFilter":{"tenantRef":"T1","allowedTags":["POLICY_READ"]},
  "page":{"size":20},
  "returnFields":["title","location","snippet","sourceVersion"]
}
```

约束：logicalIndex/corpus/filter/returnFields 均在服务端 Registry 白名单；queryText 1..4000；filters 最多 10；size 1..100；未知字段、额外 JSON、脚本、正则、任意 sort、from 深分页和原生 DSL 拒绝。首阶段仅关键词相关度排序，稳定 tie-break 由服务端追加。

响应每项：`documentId/corpusId/sourceVersion/title/location/snippet/score/classification`，并返回 `logicalIndexVersion/tookMs/hasMore`。不返回物理索引、内部安全表达式或完整原文。

### 3.2 Index write

- `PUT /indexes/{logicalIndex}/documents/{documentId}`：幂等 upsert；
- `DELETE /indexes/{logicalIndex}/documents/{documentId}?sourceVersion=...`：版本化删除；
- `POST /indexes/{logicalIndex}/documents:bulk`：最多配置上限的独立 item，逐项结果，不以部分成功冒充整体成功。

文档 DTO：`documentId, corpusId, sourceVersion, title, content, location, classification, securityTags, updatedAt`。服务端根据 Registry 决定映射；调用方不能传 index mapping 或 ingest script。重复同版本且内容摘要相同返回幂等成功；同版本不同内容、旧版本或缺安全标签拒绝。

### 3.3 Rebuild

- `POST /indexes/{logicalIndex}/rebuilds`，body 只允许 `FULL|INCREMENTAL` 和受控 source cursor；
- `GET /rebuilds/{taskId}`；
- `POST /rebuilds/{taskId}/cancel`仅在切换前有效；
- 回滚由受限管理接口将 Alias 指回已验证上一版本，不能由 Agent 请求触发。

任务状态：`PENDING|RUNNING|VALIDATING|SWITCHED|SUCCEEDED|FAILED|CANCELLED|ROLLED_BACK`。状态是运维合同，不等同 Agent execution 状态。

## 4. Registry 与 Schema

`IndexRegistry`配置包含：`logicalIndex/activeAlias/schemaVersion/allowedCorpora/searchableFields/filterFields/returnFields/securityFields/sourceAdapter/rebuildLimits`。启动时检查所有字段在 mapping 模板存在、securityFields 非空、Alias 名合法、sourceAdapter 唯一。

物理索引命名由服务生成，例如 `<logical>-v<schema>-<timestamp>`；外部不得依赖名称。Schema 不兼容变更必须走全量重建和 Alias 切换，不能原地更改导致旧查询漂移。

## 9. 详细功能与核心处理流程：查询实现

1. 鉴别服务调用方并校验其 logicalIndex/corpus 权限；
2. 严格解析请求并从 Registry 解析字段；
3. 将 queryText 编译为受控 multi-match/等价关键词查询；
4. 将 tenant/securityTags 和业务 filters 作为 bool filter 一并下推；
5. 应用 size、source includes、snippet 长度和绝对 timeout；
6. 严格解析 ES 响应，验证每个 hit 的 corpus/security/version 字段；
7. 返回稳定 DTO。任何安全绑定缺失时整体失败，不返回部分宽结果。

Agent 可在返回后继续裁剪，但不能依赖该裁剪弥补第 4 步缺失。

## 10. 数据设计与生命周期：写入一致性

以 `documentId` 为 ES `_id`，同时持久化可比较 `sourceVersion`和 tombstone/version registry。写脚本或外部版本控制必须原子实现：

- incoming > current：写入或删除；
- incoming == current 且 digest 相同：幂等成功；
- incoming == current 且 digest 不同：冲突；
- incoming < current：拒绝旧事件。

单文档错误不重试未知写结果；调用方可用相同 id/version/digest 重发并得到幂等结果。bulk 返回每项状态，重试只选失败且幂等可判定的项。

## 11. 状态模型、事务边界、重建与迁移回滚

1. 通过唯一约束获得 logicalIndex 单活动任务；
2. 创建新物理索引并记录目标 schema/source snapshot；
3. 分页读取权威源，按版本化 upsert 导入，记录 checkpoint；
4. 校验文档数范围、必需字段、安全字段、重复键和固定样例查询；
5. 原子更新 Alias，记录 previous/new index 和操作者服务身份；
6. 观察窗口内比较错误率、空命中和样例查询；
7. 严重异常回切 previous index；稳定后到保留期再清理旧索引。

数据库/锁只保护任务协调和 checkpoint，不持事务等待 ES/源服务。任务恢复从已确认 checkpoint 继续；状态不一致时标记 FAILED 并人工重启，禁止猜测已切换。

## 12. 权限与安全审计、运维

- Search 与 Index/Rebuild 使用不同服务权限；外部用户不得直达管理接口。
- ES 凭据只存在检索服务，Agent 和模型均不可见。
- 日志只记录 query digest、logicalIndex、corpus、过滤数量、耗时、命中数和错误码；不记录 queryText/snippet/content/securityTags 全值。
- 限制请求/响应/bulk/context 大小，并设置 ES timeout、连接池和并发上限。
- 指标：search latency/error/empty-hit、security reject、index conflict、task progress、Alias version、rollback count。

## 13. 当前仓库基线处理与最小变更

当前 `es-query-api`仅见 POM，`es-query-service`仅见启动类/配置/基础测试；完整历史实现位于 `_alpha` 的事实不能自动继承为目标代码。实施阶段应：

1. 对当前模块执行编译和启动基线；
2. 逐项按本 L2 新建最小实现或经审查迁移必要逻辑；
3. 不整体复制 `_alpha`，不恢复旧 Agent/document 依赖；
4. 如需改 employee-service 等现有消费者合同，先取得其范围授权并做兼容测试。
