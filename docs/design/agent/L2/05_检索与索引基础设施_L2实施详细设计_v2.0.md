## 3. 设计目标与范围

目标是补齐 Agent 可依赖的稳定原子检索能力。范围外/不负责：Agent 规划和问答、原文所有权、默认向量/重排、多写者平台及独立管理服务。最小必要抽象是 Search/Index/Rebuild/Registry 四个模块。

## 4. 当前实现基线、关联资源与责任边界

现状是当前 `es-query-api`仅有 POM，`es-query-service`仅有启动类/配置/基础测试。关联资源为 ES、文档源和 04 DocumentSearchClient；检索服务负责派生索引，文档源负责原文，Agent 负责问答，不得互改所有权。

## 5. 模块职责、依赖方向与调用边界

`Controller -> Search/Index/Rebuild Service -> Registry/Source Port/ES Client`。禁止依赖 Agent 内部类型，禁止绕过 Registry 访问物理索引，禁止 Agent 依赖 ES Client。稳定 Search DTO 降低 Agent 与 ES 的耦合，各模块按查询/写入/任务保持内聚。

内聚与耦合判断：Contract 只因外部 HTTP 合同变化，Search 只因查询/过滤规则变化，IndexWrite 只因投影版本规则变化，Rebuild 只因源一致性/发布恢复变化，Registry 只因逻辑索引和 Schema 策略变化；它们保留在同一部署单元，通过严格 DTO 与端口单向连接，不共享 Agent 类型或业务实体。Source Adapter 只调用获准上游 API，不下沉为通用数据访问层，也不直连业务数据库。

## 7. 接口与契约设计

跨语言 HTTP 合同的唯一规范源固定为 IMPL-05-01 指定的 OpenAPI 3.1 文件（复用其 JSON Schema）；Java 服务端类型和 Python `DocumentSearchClient` 类型均由该合同生成或逐字段合同测试约束，不能各自成为第二权威。首版不为“可能出现的 Java 消费者”引入代码生成插件或新生产依赖；是否生成 Java 类型属于后续实现选择，不能改变规范源。

### 7.1 Search

`POST /indexes/{logicalIndex}/search`

```json
{
  "requestId":"018f...",
  "deadlineAt":"2026-07-22T12:00:02Z",
  "queryText":"年假结转",
  "corpusId":"POLICY",
  "filters":[{"field":"documentType","operator":"IN","values":["POLICY"]}],
  "authorizationProjection":"<compact-JWS>",
  "page":{"size":20},
  "returnFields":["title","location","snippet","sourceVersion"]
}
```

约束：logicalIndex/corpus/filter/returnFields 均在服务端 Registry 白名单；queryText 1..4000；filters 最多 10；size 1..100；requestId、deadlineAt 必填；未知字段、额外 JSON、脚本、正则、任意 sort、cursor/from 深分页和原生 DSL 拒绝。首阶段仅返回一个受上限约束的结果页，不提供继续翻页；关键词相关度排序，稳定 tie-break 由服务端追加。

`authorizationProjection`是 02 的确定性 projector 生成的短时 compact JWS。受保护头必须含固定`typ=agent-search-authz+jwt`、算法白名单值和`kid`；payload 必需 claims 为`iss/aud/sub/subjectRef/tenantRef/logicalIndex/allowedCorpora/allowedSecurityTags/evidenceVersion/iat/exp/jti/requestDigest`。`aud`固定为本检索服务，HTTP 服务身份 subject 必须等于`sub`，requestId 必须等于`jti`；`requestDigest`固定为 base64url(SHA-256(RFC 8785 JCS(request fields)))，request fields 精确为`logicalIndex/queryText/corpusId/filters/returnFields/page/requestId/deadlineAt`且不含 authorizationProjection。HTTP Authorization 中的服务身份仍独立校验，JWS 不能代替服务认证；身份/请求绑定、签名、有效期或 kid 任一不一致时，在访问 ES 前失败关闭。首版不维护全局 nonce 库；在短有效期内，只有相同已认证服务才能精确重放同一只读请求，JWS 不得用于 Index/Rebuild。

响应每项：`documentId/corpusId/sourceVersion/indexedAt/title/location/snippet/score/classification`，封套只返回`logicalIndexVersion/tookMs/hits`。`indexedAt`由索引写入事实提供，不能由查询时钟伪造。响应的 hit 数、单 snippet 字符数和序列化总字节受 Registry 硬上限约束；不返回物理索引、内部安全表达式或完整原文。

所有接口使用同一严格错误封套`{requestId, code, retryable, message}`且`additionalProperties=false`。稳定错误码至少包括通用`INVALID_REQUEST|UNAUTHORIZED|FORBIDDEN|UPSTREAM_TIMEOUT|INTERNAL_ERROR`、查询`AUTHORIZATION_EXPIRED|INDEX_NOT_READY`、写入`VERSION_CONFLICT|STALE_VERSION|REBUILD_CUTOVER_IN_PROGRESS`和重建`REBUILD_ACTIVE|SOURCE_GAP|CONTROL_STATE_UNAVAILABLE|ALIAS_STATE_UNKNOWN`；HTTP 状态、code 和 retryable 映射在 OpenAPI 中唯一声明。外部 message 不暴露物理索引、规则或 ES 原文。仅明确未开始执行的只读连接失败可由唯一 Client 责任方在剩余 deadline 内重试一次，服务端不透明重试。

### 7.2 Index write

- `PUT /indexes/{logicalIndex}/corpora/{corpusId}/documents/{documentId}`：幂等 upsert；
- `POST /indexes/{logicalIndex}/corpora/{corpusId}/documents/{documentId}:delete`：严格 body 携带 requestId/sourceVersion 的版本化删除；
- `POST /indexes/{logicalIndex}/documents:bulk`：最多配置上限的独立 item，逐项结果，不以部分成功冒充整体成功。

文档 DTO：`requestId, documentId, corpusId, sourceVersion, title, content, location, classification, securityTags, updatedAt`。首版`sourceVersion`是 JSON 字符串承载的`0..9223372036854775807`十进制整数，按数值比较；updatedAt 只用于展示，不能参与新旧判断。路径 corpusId/documentId 必须与 body 一致。服务端根据 Registry 决定映射；调用方不能传 index mapping 或 ingest script。重复同版本且规范字段摘要相同返回幂等成功；同版本不同摘要、旧版本或缺安全标签拒绝。bulk 每项都携带 request item id，整体响应明确 total/succeeded/failed 和逐项 code，任一失败时不得返回整体成功语义。

### 7.3 Rebuild

- `POST /indexes/{logicalIndex}/rebuilds`，body 只允许 `mode=FULL|INCREMENTAL` 和 Registry 枚举的 `reasonCode`；source cursor 只能由 Source Adapter/控制索引产生，调用方不能指定或回退；
- `GET /rebuilds/{taskId}`；
- `POST /rebuilds/{taskId}/cancel`仅在切换前有效；
- 回滚由受限管理接口将 Alias 指回已验证上一版本，不能由 Agent 请求触发。

任务状态：`PENDING|RUNNING|CATCHING_UP|VALIDATING|SWITCHED|SUCCEEDED|FAILED|CANCELLED|ROLLED_BACK`。FULL 可经过 SWITCHED；INCREMENTAL 只追平当前 Alias，不创建/切换物理索引。状态是运维合同，不等同 Agent execution 状态；未知或非法迁移拒绝，不能靠覆盖状态“修复”。

## 8. Registry 与 Schema

`IndexRegistry`配置包含：`logicalIndex/activeAlias/schemaVersion/allowedCorpora/searchableFields/filterFields/returnFields/securityFields/sourceAdapter/sourceConsistencyMode/rebuildLimits`。`sourceConsistencyMode`只能为`SNAPSHOT_WITH_REPLAY|QUIESCED_WINDOW`：前者要求源提供一致快照游标、顺序可比较且可重放的变更游标、包含删除事实的 tombstone/version watermark 及明确保留期；后者要求经审计的源静默窗口。启动时检查所有字段在 mapping 模板存在、securityFields 非空、Alias 名合法、sourceAdapter 唯一；上述源合同未通过合同测试时，对应 logicalIndex 的 Rebuild 保持禁用。

物理索引命名由服务生成，例如 `<logical>-v<schema>-<taskId>`；外部不得依赖名称。每次成功发布生成不含物理名称的 opaque `logicalIndexVersion`（绑定 schemaVersion/publishId），在控制状态、Search 封套和审计中一致使用；回滚恢复 previous 对应版本，不能用查询时钟临时生成。Schema 不兼容变更必须走全量重建和 Alias 切换，不能原地更改导致旧查询漂移。

## 9. 详细功能与核心处理流程：查询实现

1. 鉴别 Agent 服务调用方，验证授权投影 JWS 的 typ/alg/kid、签名、iss/aud/sub、subject/tenant、jti/requestDigest、有效期及 logicalIndex/corpus 权限，并确认 HTTP 服务 subject 与 sub、requestId 与 jti 相等；禁止信任自填用户头、未签名对象或任意 security filter；
2. 严格解析请求并从 Registry 解析字段；
3. 将 queryText 编译为受控 multi-match/等价关键词查询；
4. 将 tenant/securityTags 和业务 filters 作为 bool filter 一并下推；
5. 应用 size、source includes、snippet 长度和绝对 timeout；
6. 严格解析 ES 响应，验证每个 hit 的 corpus/security/version 字段；
7. 返回稳定 DTO。任何安全绑定缺失时整体失败，不返回部分宽结果。

Agent 可在返回后继续裁剪，但不能依赖该裁剪弥补第 4 步缺失。

## 10. 数据设计与生命周期：写入一致性

ES `_id`固定为无 padding base64url(UTF-8 corpusId) + `.` + 无 padding base64url(UTF-8 documentId)，同时持久化原始两字段、数值可比较`sourceVersion`、规范字段 SHA-256 digest 和 deleted tombstone marker。禁止仅用`documentId`或分隔符未编码拼接导致碰撞。写脚本在同一 ES 文档上原子实现：

- incoming > current：写入或删除；
- incoming == current 且 digest 相同：幂等成功；
- incoming == current 且 digest 不同：冲突；
- incoming < current：拒绝旧事件。

单文档错误不重试未知写结果；调用方可用相同 id/version/digest 重发并得到幂等结果。bulk 返回每项状态，重试只选失败且幂等可判定的项。

## 11. 状态模型、事务边界、重建与迁移回滚

首版不引入关系数据库或 Redis。检索服务在同一 ES 集群拥有设置`index.hidden=true`的控制索引`es-query-control-v1`，仅保存 Registry 运行版本、任务、租约、checkpoint、source high-water、active/previous 物理版本和审计摘要，不保存正文或安全标签全集。以 ES `seq_no/primary_term` CAS 和带到期时间的 lease 保证每个 logicalIndex 单活动任务；lease 只协调任务，不跨网络调用持有事务。控制索引不可用时 Search 可继续读取已存在 Alias，Index/Rebuild/回滚/清理全部失败关闭；控制索引丢失时必须从 Alias 与权威源完成受审计对账/全量重建后才能恢复管理写入，不能猜测任务状态。

FULL 固定流程：

1. CAS 获得 logicalIndex lease，记录 active/previous、目标 schema 和 Source Adapter 合同版本；
2. 创建新物理索引；从当前 active 索引复制 tombstone/version marker，再从权威源取得一致快照及快照游标 C0，按版本规则导入并记录 checkpoint；
3. `SNAPSHOT_WITH_REPLAY`模式按游标重放 `(C0,C1]`，进入短切换屏障后拒绝该 logicalIndex 的新 Index 请求为可重试`REBUILD_CUTOVER_IN_PROGRESS`，再次取得 high-water C2 并重放至 C2；`QUIESCED_WINDOW`模式则验证已获授权的源静默证明，不能用应用内布尔开关冒充；
4. 只有在 source high-water、applied cursor、文档/删除数、必需/安全字段、重复键和固定样例查询全部一致时进入 VALIDATING；无法证明无游标缺口时 FAILED，Alias 保持不变；
5. 使用一次 ES Alias action 原子地移除旧目标并添加新目标，记录 previous/new index、C2/静默证明和操作者服务身份，再解除屏障；切换 API 结果未知时先读取 Alias 事实再迁移状态，禁止盲重试；
6. 观察窗口内比较错误率、空命中和样例查询；严重异常以同样 CAS/审计流程回切 previous；稳定且超过保留期后，清理任务再次证明目标既非 active 也非 previous 才删除。

INCREMENTAL 从控制索引保存的 lastAppliedCursor 读取连续变更并写当前 Alias；每一页确认后才推进 checkpoint，发现断档、过期游标或不兼容 schema 时 FAILED 并要求 FULL，不能跳过缺口。任务恢复从已确认 checkpoint 继续；接管者先核对 lease、Alias 和 source high-water。任何不一致均 FAILED/告警并等待显式重启或对账。

## 12. 权限与安全审计、运维

- Search 与 Index/Rebuild 使用不同服务权限；外部用户不得直达管理接口。
- Registry 必须声明`sourceService -> logicalIndex/corpusId/action`白名单；写入、删除、重建和回滚逐项校验，禁止跨语料库管理操作。
- ES 凭据只存在检索服务，Agent 和模型均不可见。
- 日志只记录 query digest、logicalIndex、corpus、过滤数量、耗时、命中数和错误码；不记录 queryText/snippet/content/securityTags 全值。
- 限制请求/响应/bulk/context 大小，并设置 ES timeout、连接池和并发上限。
- 指标：search latency/error/empty-hit、security reject、index conflict、task progress、Alias version、rollback count。

## 13. 当前仓库基线处理与最小变更

当前 `es-query-api`仅见 POM，`es-query-service`仅见启动类/配置/基础测试；完整历史实现位于 `_alpha` 的事实不能自动继承为目标代码。实施阶段应：

1. 对当前模块执行编译和启动基线；

4. 如需改 employee-service 等现有消费者合同，先取得其范围授权并做兼容测试。
