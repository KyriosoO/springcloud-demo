## 3. 背景、目标与范围

### 3.1 背景与根因

03 已冻结 `execution/attempt/deadline/cancellation/fence/terminal state`，并要求创建、重试、恢复和接受结果前调用 04 提供的可信 continuation decision。当前目标 `agent-service` 尚无权限组合、字段策略、数据分类或模型准入实现；唯一 Runtime OpenAPI 只有 M1 readiness/error，没有业务或安全投影 Schema。

实施前，`auth-service` 的 `/internal/agent/permissions/resolve` 已使用 `agent-service` 服务身份和 `agent.permission.resolve` scope，响应带 `evidenceId/version/resolvedAt`，但仍同时返回字段规则，且没有可信 tenant、显式 `permissionCodes` 或有效期。本轮已以加法兼容方式补入 `tenantRef/permissionCodes/validUntil`，同时保留 `filterableFields/displayableFields/allowedOperators/allowedFunctions` 等旧字段供迁移对比；Agent现已通过common-security服务JWT和有界、无重试、无正缓存的HTTP Adapter完成真实Auth服务边界接线，3个已知主体集成验证通过，并补齐受控策略管理和可重复退出判定基础。12A观察窗口和真实独立退出审批尚未形成。这仍要求严格维持“Auth 拥有身份/角色/RBAC 上界，Agent 拥有字段策略和最终组合”的目标边界。直接复制 alpha 结构或继续长期消费 Auth 字段规则会形成双重字段权威；直接省略 tenant、分类或目标证明又会把不确定事实默认为允许。

本设计的最小修正是：保留当前 Auth 内部服务身份与请求/安全错误封套作为迁移输入，把 Auth 响应拆成“RBAC 上界事实”和“仅用于迁移对比的旧字段视图”；在 Java Agent 内建立版本化字段策略、模型目标证据目录和单次模型发送决策；所有不确定、冲突、过期或不可验证事实失败关闭。

### 3.3 范围内

- Auth 权限上界消费契约、版本/新鲜度/主体绑定和失败映射。
- Agent 版本化字段策略、permission code 到字段规则的映射和只收紧交集算法。
- 数据分类、自由文本敏感实体检测和模型目标信任矩阵。
- `ModelAccessDecision`、单次发送安全投影、决策失效和 Runtime 目标约束。
- 创建、重试、恢复、Tool 边界、模型发送和结果接受的 continuation decision。
- Auth 旧字段规则的种子、双读、差异审计、退出和安全回滚。
- 模型输出、业务结果、DOCUMENT 候选/引用的安全终检接口边界。
- 策略持久化、审计、配置、测试和 01 契约贡献要求。

### 3.4 范围外

- 重定义 03 的状态、deadline、取消、attempt/fence、终态或重试预算。
- 定义 05 的 Runtime 固定服务身份、短期 `capabilityId`、防重放或 Tool 白名单载体。
- 定义 06～10 的 Route/Plan、业务字段 Schema、Adapter、检索融合、回答或引用算法。
- 本轮授权覆盖 `OPEN-04-001` Auth/Agent代码、脚本、依赖、配置、受控SQL源及3306数据库对齐、测试、非代码证据、关联文档和Git提交推送；不修改OpenAPI、Python Runtime、CI、模型目标或生产状态，不启用策略或业务流量。
- 启用任何模型目标、Runtime/Tool 监听、服务发现、业务流量或生产发布。
- 以历史 `agent-service_alpha`/`agent-runtime_alpha` 或旧设计作为目标权威。

### 3.5 非目标

- 不建设通用 IAM、ABAC 规则引擎、DLP 平台或新的凭据体系。
- 不把模型输出、用户自称域、Runtime 推断或检索候选当作授权/分类权威。
- 不允许通过“可用性降级”切换到更低信任模型、无过滤上下文或更宽字段范围。
- 不把编写期自检、设计评审或合成 PoC 解释为目标系统质量或生产批准。

### 7.3 内聚与耦合判断

权限交集、分类、模型准入和投影共同保护“数据能否以何种形态进入哪个处理目标”这一单一安全责任，因此位于 Java `security` 域；但 Auth、资源属性、模型调用和生命周期分别通过 Port 隔离。`AuthorizationIntersectionService` 是纯决定组件，不兼任远程调用、策略存储或结果序列化；`SecurityProjectionService` 只处理已授权 scope，不重新授权。Runtime 只消费决定和投影，不拥有字段策略或目标选择权。

## 8. 详细功能与流程设计

### 8.1 安全事实模型与只收紧交集

#### 8.1.1 设计规则

| 规则编号 | 规则 | 责任主体 | 触发条件 | 输出/状态效果 |
|---|---|---|---|---|
| DR-04-001 | `AuthAuthorizationFacts` 只包含 Auth 权威的 subject、tenantRef、permissionCodes、capability/domain/context 上界、evidenceId、version、resolvedAt、validUntil；完整 JWT、role 列表和旧字段规则不进入最终 scope | Auth Adapter | 每次授权重验 | Auth 上界或失败 |
| DR-04-002 | `AgentSecurityPolicySnapshot` 以 permission code 映射字段可查询/展示/运算/模型投影、目的、mask、分类和目标准入；不得保存用户/角色关系 | Policy Repository | 读取 active policy | Agent 唯一字段策略 |
| DR-04-003 | 最终 capability/domain/context/field/operator/function/purpose/resource scope 均为各适用输入的集合交集；空集是拒绝或显式空上下文，不允许 union、默认补齐或“管理员全放行” | Intersection Service | 任一决定 | `EffectiveSecurityScope`/deny |
| DR-04-004 | subject/tenant/evidence/version/validity/resource fence 任一缺失、冲突、过期或不可验证，返回失败关闭；Runtime、模型、Adapter、检索均不得补全 | Security Domain | 事实校验 | typed deny/failure |
| DR-04-005 | 首期 DOCUMENT 只允许策略中固定的 `document-default` 逻辑语料库及统一语料库级权限；文档级 ACL 字段不得参与授权或准入 | Intersection Service | DOCUMENT scope | corpus allow/deny |
| DR-04-006 | Auth 正向授权事实不跨决定缓存；每个重验点重新调用 Auth。单次调用内只可复用同一不可变响应；调用结束即失效 | Auth Adapter | 创建/重试/恢复/模型发送/Tool边界/结果接受 | 无陈旧正缓存 |
| DR-04-037 | 外部用户入口只接受 `common-security` 已验证且 `token_type=user` 的认证对象，以 JWT `sub` 形成 `TrustedRequestIdentity.subjectRef`；body/header 中的 subject、role、tenant 仅可作为待比对提示，不能成为权威。内部回调/恢复只接受后续 05 冻结的服务身份，并从 03 已持久化 execution 读取 subjectRef 后重新向 Auth 求证；用户令牌和服务令牌不得互换 | Ingress Security + Identity Resolver | 创建、回调、恢复 | typed identity 或请求拒绝 |
| DR-04-038 | 创建 execution 前仅允许一次 Auth 解析尝试，受调用方 absolute deadline、入口超时和限流约束，默认不重试、不缓存；此时 execution 尚不存在，不伪造 03 reservation。execution 创建后，每次 Auth、资源事实、Runtime、模型、Tool 或业务远调均先消耗一个 03 dependency-call reservation；能力 L2 必须按最坏合法调用图冻结 `dependencyCode` 序列和 `callBudgetLimit`，预算不足时不创建/不启动对应 execution | Ingress + Lifecycle + Capability Policy | 创建前鉴权、创建后任一远调 | bounded preflight 或预算预约/拒绝 |

#### 8.1.2 目标 Auth 契约与当前兼容分区

目标 Auth 上界至少需要：

| 字段 | 语义 | required/nullable/default | 校验与失败 |
|---|---|---|---|
| `subject` | Auth 证明的主体类型和稳定 ID | required；非 nullable；无默认 | 必须与入口已验证主体一致，否则 `SECURITY_SUBJECT_MISMATCH` |
| `tenantRef` | Auth 证明的租户上界 | required；非 nullable；无默认 | 缺失或不一致为 `SECURITY_TENANT_UNVERIFIED`；禁止默认租户 |
| `permissionCodes` | Auth RBAC 计算后的封闭权限码集合 | required；非 nullable；空集合表示无授权 | 未知码不得推断；Agent 可忽略未知码但不得因此扩大 |
| `allowedCapabilityIds/allowedDomains` | RBAC 能力/域上界 | required；非 nullable；空集合拒绝相应能力 | 与 Agent/资源范围取交集 |
| `readableContextTypes/writableContextTypes` | RBAC 上界；不直接定义字段内容 | required；非 nullable；空集合拒绝 | 与 Agent 策略取交集 |
| `evidenceId/version` | Auth 决策证据和版本 | required；非 nullable；无默认 | 空/格式错误失败关闭 |
| `resolvedAt/validUntil` | 事实生成和最迟有效时间 | required；非 nullable；无默认 | `resolvedAt <= now < min(validUntil, deadline)`；未来时间/过期失败 |

当前兼容响应中的 `filterableFields/displayableFields/allowedOperators/allowedFunctions/attributes` 已被隔离为 `LegacyAuthFieldView`，只用于 DR-04-025～027 的迁移交集和差异审计，不得被映射成最终 Auth 权威模型。`tenantRef/permissionCodes/validUntil` 已落地到 Auth DTO 和静态 RBAC 投影，Agent运行时已通过服务令牌HTTP Adapter完成真实Auth边界验证；但当前仍无业务入口身份实现、活动Agent策略或12A观察窗口，因此不得据此声明tenant-scoped业务execution已可用。`subject` 必须等于 `TrustedRequestIdentity.subjectRef`。若入口有经验证的 tenant claim/路由 tenant，则必须与 `tenantRef` 相等；若入口没有 tenant，Auth 返回值是唯一候选，但多租户主体必须由目标 Auth 契约要求显式、受鉴别的 tenant context，否则失败关闭。

#### 8.1.3 资源授权事实与安全版本向量

`ResourceAuthorizationFacts` 是各业务 Adapter、文档源/检索安全契约提供的只读事实，不是 Agent 复制的资源主数据。每批事实至少包含：

| 字段 | 语义 | 校验/失败关闭 |
|---|---|---|
| `resourceSetDigest` | 本次 scope 内稳定 resource refs 的 canonical SHA-256 | 缺失或集合变化使旧决定失效；不把完整资源 ID 列表写日志 |
| `tenantRef/domain/resourceScope` | 来源证明的 tenant、业务域和最小资源/语料库范围 | 与 Auth/execution 不一致立即拒绝 |
| `requiredPermissionCodes` | 访问该范围必须具备的 Auth 权限码；只能增加要求 | Auth codes 未完整包含即拒绝；资源源不能授予新码 |
| `fieldClassifications/contentClassification` | 来源字段/正文分类及其证据 | 未知字段、未知等级或缺证据为 UNCLASSIFIED |
| `sourceVersion/revocationFence` | 来源业务版本和撤权围栏 | 乱序、未知或低于当前全局围栏失败关闭 |
| `resolvedAt/validUntil/evidenceDigest` | 事实时间边界和可复算摘要 | 未来、过期、摘要漂移失败关闭 |

多来源输入按稳定 source type+source ref 排序后，使用 RFC 8785 canonical JSON 计算单一 `resourceEvidenceDigest`。`SecurityVersionVector` 固定包含 Auth `evidenceId/version/validUntil`、Agent `policyVersion/policyEpoch/policyDigest`、`resourceEvidenceDigest`，以及模型目标 `targetEvidenceDigest/runtimeCatalogFingerprint/deploymentTargetSetDigest/targetAuthorizationDigest`；该向量整体参与 decision/projection canonical digest。不得只保存“最新 resourceVersion”、忽略部署 kill-switch 集合或遗漏某个来源版本。

#### 8.1.4 Agent 安全策略封闭结构

`policy_payload` 的版本化 Schema 只允许以下顶层对象，`additionalProperties=false`：

| 对象 | 必需内容 | 禁止内容 |
|---|---|---|
| `permissionCodePolicies` | code；capability/domain/context 上限；字段规则引用 | 用户、角色、JWT claim |
| `fieldPolicies` | canonical domain+field；classification；allowed purposes；filter/display/aggregate flags；operators/functions；每个 sink 的 `DROP/MASK/ANONYMIZE/AGGREGATE/ALLOW` | 任意脚本、表达式、动态类名 |
| `corpusPolicies` | 固定逻辑语料库、所需 permission codes、允许 purpose/classification | 物理索引、任意 ACL、用户列表 |
| `modelTargets` | 第 8.7 节 target entry 和 evidence refs | endpoint secret、API key、用户可选 URL |
| `modelTargetBindings` | 以 capabilityId+domain+purpose+classification/ceiling 为完整键，值为唯一 targetId；键和值均为封闭引用 | 动态权重、随机路由、隐式默认目标、跨信任 fallback |
| `sensitiveEntityPolicies` | detector rule version、实体类别和对应 sink action | 原始样例正文/真实敏感值 |
| `policyLimits` | 各 sink 最大字段/条数/bytes/token 上界引用 | 放宽能力 L2/03 已固化预算的默认值 |

字段策略引用不存在、同一 canonical field 重复、permission code 指向未知字段/能力、分类或 action 未知、模型目标证据引用缺失、limits 超出上位/能力硬上限时，策略不得 STAGED 或 ACTIVE。Schema 只定义确定性数据，不允许通用规则语言；新增顶层对象或 action 需策略 Schema 版本升级和独立评审。

#### 8.1.5 交集算法

1. 校验 03 lifecycle snapshot 的 execution/attempt/fence/deadline，终态或过期直接交回 03 裁决。
2. 事务外读取当前 Auth 上界、Agent active policy epoch/snapshot、资源属性/撤权围栏和 execution intent。
3. 按 subject、tenant、capability、domain、purpose、context type 逐层校验；任一拒绝优先于后续裁剪。
4. 用 `permissionCodes` 选择 Agent 字段规则，再与资源可用字段/分类和 execution 最小目的取交集。
5. 双读阶段再与 `LegacyAuthFieldView` 取交集；退出后旧字段视图完全不参与决定。
6. 生成稳定排序的 scope canonical form 和 SHA-256 `scopeDigest`；摘要只持久化/比较，不进指标标签或普通异常。
7. 不得把“字段被裁空”自动解释为允许：必需输入为空时拒绝；可选 context 为空时只产生显式空投影。

#### 8.3.2 正常流程

1. 能力层声明一个封闭 `ModelCallIntent`，含 purpose、所需域、输入类型和预算；不含 endpoint、model name 或凭据。
2. Java 在事务外执行 8.1 交集、8.2 分类，按 DR-04-039 取得唯一 policy target binding，再按 DR-04-040 对策略、部署、证据和 Runtime 状态做四方交集；绑定缺失、重复或任一侧不满足均拒绝。
3. Java 按 03 预约一个 `RUNTIME_MODEL_DISPATCH` dependency call，得到与当前 execution/attempt/fence 绑定的唯一 reservationId；预约失败不生成 ALLOW。
4. Java 为该 reservationId/modelCallId 生成各 sink 投影，计算摘要，追加 `ALLOW` 审计；审计写入失败则不发送。
5. Java 通过后续获批的 generated contract 把决定和投影发送给 Runtime，明确禁用同决定的客户端/代理自动重试；不发送 Auth 原响应、策略正文、资源权限表达式或目标秘密。
6. Runtime extra-forbid 校验所有绑定，先执行进程内 first-use guard，再核对本地 catalog fingerprint，仅按 targetId 解析目标；不接受 URL/model override。
7. Runtime Provider Adapter 只对 first-use 决定执行一次真实发送；重复、决定过期、绑定不一致、重启后不可证明未消费或目标不 ready 均拒绝。Provider 调用结果未知时不重发。
8. Provider 候选返回后按 8.5 处理；不能把原始候选直接进入历史、日志、持久结果或下一次模型输入。

连续两次模型调用之间如果没有新的可信 Java 边界，首期一律禁止。DOCUMENT 中 Tool 返回后的 Rerank/Generate 必须由 Java Tool 边界提供下一次发送所需的新决定，或由 10 将流程拆成新的 Java→Runtime operation；具体 wire 由 05/10 与 01 共同贡献，不能由 Runtime 自行续签。

#### 8.3.3 失效条件

- execution/attempt/fence/deadline 变化或进入终态；
- Auth version/evidence/validity、Agent policy epoch、resource version/revocation fence 变化；
- classification、purpose、domain、projection digest、target evidence 或 Runtime catalog fingerprint 变化；
- 已发送、过期、Runtime restart 后无法证明未发送，或任何绑定不可验证。

失效决定只能拒绝，不能刷新部分字段；必须从当前事实重新执行完整决定。

`issuedAt` 使用 Java UTC `Clock`。`expiresAt` 固定取 absolute deadline、Auth `validUntil`、资源事实 `validUntil`、模型目标证据 `validUntil` 和能力策略允许的单次调用过期时间中的最早值；任一来源没有可验证上界则不得产生 ALLOW。`decisionId` 与 `modelCallId` 均由 Java 生成不可猜测的唯一值，但不作为凭据或授权事实；安全性来自完整绑定和 Runtime 严格校验，不能只校验 ID。

兼容演进顺序固定为：先在当前内部接口以加法方式提供 tenantRef/permissionCodes/validUntil，并保持旧字段，目标 Adapter 对新字段 strict、对已知旧字段隔离；完成 B/C 后才申请删除旧字段。若现有消费者不能兼容加法字段，必须新增版本化内部 operation，不得原地破坏。旧字段删除是 breaking change，必须有调用方清单、契约版本、灰度和回滚证明；不能因 alpha 已隔离而省略当前 Auth 自身及未知消费者扫描。

### 9.3 状态、并发与一致性

- policy version 永不原地修改；active pointer 是唯一可变策略权威。
- Auth/资源远程事实不与 MySQL 组成分布式事务。先事务外获取事实，再以 version/epoch/digest 形成决定；发送前和结果接受前重新确认当前 epoch/lifecycle。
- 审计 ALLOW 成功提交后才能发送；同一决定只允许一个禁自动重试的 Runtime dispatch。发送结果未知由 03 call reservation/attempt 处理，04 不猜测是否已调用，也不以同决定查询/重发。
- 旧 policy epoch、旧 Auth version 或旧 fence 不因重试自动刷新；新重试执行完整重验并生成新 modelCallId/decisionId。
- 本设计不引入正向授权缓存。后续如为性能新增缓存，必须另行评审证明最大陈旧窗口、跨实例撤权和不可扩权；默认不得实施。

### 9.4 权限、安全、风控与审计

主体、tenant、capability、domain、purpose、resource scope、字段和 sink 是一次决定的完整授权维度。高风险动作包括策略创建/激活/回滚、目标启用/停用和 Auth 字段迁移退出，均需已鉴别操作人身份、与变更摘要绑定的独立批准证据和审计；普通用户请求不得触发。当前批准证据权威尚待 12A 冻结，因此 12A 接入前管理 Port 必须失败关闭，不得用任意 `approval_ref` 字符串放行。安全错误只返回稳定 code、安全 message 和 diagnosticId，不返回被拒字段、规则文本、目标 endpoint 或供应商错误正文。

### 9.5 性能、容量与资源预算

- 创建 execution 前的 Auth 解析固定最多一次，计入同一请求 absolute deadline，但因 execution 尚不存在而不计入/伪造 03 持久调用预约；入口超时或 Auth 失败直接不创建 execution。
- execution 创建后的 Auth/资源事实/Runtime/模型/Tool/业务服务每个实际远调均计入 03 absolute deadline 和 `callBudgetLimit`，由 Java 在调用前逐个预约，默认不重试。能力策略必须列出最坏合法调用图和每个 `dependencyCode` 次数；`callBudgetLimit` 小于必需调用数时 capability readiness=false。03 的 `baseline-no-retry-v1`（1/1）只允许创建后最多一次远调，不足以承载“重验 + Runtime/模型”等多调用流程。
- policy active pointer 为本地 MySQL 小查询；策略 payload 可按 `(version,digest)` 进程内不可变缓存，但每次先读/确认 active epoch，缓存未命中或摘要不符失败关闭。
- 投影必须在能力 L2 给出的字段/条数/token/bytes 上限内进一步收紧；04 不自建更宽默认值。
- 分类/DLP 超时不能跳过；以 typed security failure 结束。吞吐、P95、舱壁和告警阈值由 12/12A 量化。

### 9.6 发布、迁移与回滚

1. 交付 SQL/验证/回滚脚本，由 DB 责任人执行；应用启动不得迁移生产库。
2. 先部署只读 policy/target catalog 与 fail-closed readiness，不启用业务目标。
3. 完成 Auth 目标契约和 Agent seed，进入双读交集；旧实例若不能理解新安全 Schema，不得接对应流量。
4. 完成全量 diff、负向测试、观察窗口和独立评审后退出旧字段决定路径。
5. 每个模型目标独立补齐证据、contract/runtime catalog 测试和回滚演练；未完成的目标保持 disabled，不影响其他目标状态但对应业务域不可用。
6. 目标停用先发布 Runtime 新 fingerprint/不 ready 以拒绝旧决定，再滚动 Java 收紧 enabled 集合；启用顺序相反，Runtime 先就绪但 Java 仍禁用，最后才激活已批准 binding/部署集合。不得在进程内热改目录或 enabled 集合。
7. 回滚仅回到仍满足当前 Auth/资源撤权和目标证据的兼容版本；不得回滚到 alpha、恢复旧 Auth 字段权威或跨信任目标。

### 9.7 日志、监控与告警

低基数指标至少包括：

- `security_authorization_decision_total{result,reason}`；
- `security_projection_total{sink,result}`；

### 9.8 配置语义

| 配置键 | 默认 | 校验与生效 | 回滚/安全边界 |
|---|---|---|---|
| `agent.security.auth.resolve-path` | `/internal/agent/permissions/resolve` | 仅内部相对路径；base URL/服务身份由获批部署配置提供 | 路径错误 readiness 失败，不回退 JWT role |
| `agent.security.auth.positive-cache-enabled` | `false` | 必须保持 false；未来启用需新设计评审 | 不允许热启用 |
| `agent.security.policy.required` | `true` | 无 active policy、摘要或 DB 时 security readiness 失败 | 不允许改 false 接流量 |
| `agent.security.auth-field-migration-mode` | `SEED_ONLY` | 仅允许第 8.6.2 节四值；状态前进须有证据 | 回退不能从 C/D 恢复旧字段放行 |
| `agent.security.model-targets.enabled` | 空集合 | 仅作为部署收紧/kill-switch 集合；启动时 stable sort+canonical digest，targetId 还必须由 active policy 唯一绑定、证据完整且 Runtime fingerprint/readiness 匹配 | 禁止热改；配置增加不能单独授予；空集合安全禁用全部目标 |
| Runtime `AGENT_MODEL_TARGET_CATALOG_FINGERPRINT` | 无默认 | 必须与 Java 决定一致 | 缺失/漂移 readiness/request 均拒绝 |

秘密、endpoint 和 API key 不进入本表或策略 payload；由部署/secret 专题提供受控引用。配置不能代替目标证据、策略批准或 OpenAPI 授权。
