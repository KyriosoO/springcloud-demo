## 3. 架构目标、非目标与职责边界

检索基础设施的目标边界可向 Agent 和其他上游提供少量稳定原子能力：受控关键词检索，以及在来源合同具备后逐步增加的文档写入/删除和重建。它不理解对话意图、不调用生成模型、不决定最终回答，也不拥有原始文档。

当前阶段 A 只在现有 `es-query-*` 边界形成 Search 只读纵切，不创建 Agent 专属 document service、provider adapter 或检索控制面。Index 等待首个权威来源合同，Rebuild 等待来源一致性合同；若现有实现为空壳或 Search 合同不足，应按 L2 补齐或由上游负责人修订，不能把 `_alpha` 复制为目标基线。

不负责 Agent 意图、回答、模型访问和原始文档所有权；非目标包括首阶段默认向量/重排、独立查询面/管理面和多写者控制平台。

## 6. 模块职责与依赖方向

| 组件 | 责任 |
|---|---|
| Search API | 接收封闭查询、短时请求绑定授权投影和受限单页上限，返回命中和版本 |
| 后续 Index API | 来源版本/删除合同获批后，提供该来源所需的最小幂等写入；当前阶段 A 不存在 |
| 后续 Rebuild Service | 来源快照/游标/静默证明获批后承担构建、校验、切换和回滚；当前阶段 A 不存在 |
| 后续 Source Reader | 仅随获准来源合同建立，不预设通用读取框架 |
| Index Registry | `logicalIndex -> active physical index/schemaVersion`，禁止调用方传物理名 |
| Metrics/Audit | 延迟、错误、空命中、任务进度、切换和回滚摘要 |

当前阶段 A 只有 Search 查询面，不创建管理接口或独立管理部署单元。后续 Index/Rebuild 获准并出现管理接口时，先在同一部署单元以独立服务身份和管理权限隔离；只有出现独立运维团队、显著容量差异或多写者后再评估拆分。

禁止依赖 Agent 内部计划/模型类型；Agent 也不得反向依赖 ES Client 或物理索引。双方只通过稳定 Search DTO 协作。

## 7. 核心数据流与调用边界

### 7.1 查询流

1. Agent 根据获准 `corpusId` 和权限事实形成封闭 `SearchRequest`。
2. Search API 校验目标受限、短时且绑定本请求的委托调用凭据；凭据必须同时证明调用服务身份和经授权的最小用户范围，二者任一缺失、冲突或过期均失败关闭。令牌格式、claims 和摘要算法由 L2-02/05 共同冻结，禁止信任调用方自填用户头、未签名权限对象或任意 security filter。
3. 授权过滤与业务过滤共同进入 ES 查询；禁止先宽召回后仅在 Agent 侧过滤。
4. 服务解析当前 Alias，执行关键词检索并返回稳定命中。
5. Agent 再做只收紧过滤、证据选择和引用；索引服务的命中不是最终授权证明。

### 7.2 索引流

### 7.2.1 增量写入

- 文档键使用无歧义编码的 `corpusId + documentId`；`sourceVersion` 必须在该文档键内单调可比较。
- 相同键和版本的重复 upsert 必须幂等；较旧版本拒绝并记录。
- 删除使用带版本的 tombstone 或等价机制，防止旧事件复活文档。
- 内容、标题、来源定位和 `securityTags` 由源提供；检索服务不推导业务权限。

### 7.2.2 全量重建

```text
create new physical index
 -> load source snapshot and tombstone/version markers
 -> replay to source high-water or verify an authorized quiesced window
 -> validate counts/schema/sample queries
 -> atomically switch logical alias
 -> observe
 -> delete old index after rollback window
```

失败时旧 Alias 保持不变。无法证明快照后变更已追平，或无法证明源处于经授权静默窗口时，禁止切换。切换后发现严重问题，回切上一物理索引；若源版本已发生不可兼容变化，应重新构建而不是手工修改索引。

旧物理索引只能在观察期和回滚窗口结束、确认既非 active 也非 previous 后由受控清理任务删除；清理动作记录 logicalIndex、物理版本、操作者服务身份和结果，禁止调用方按物理索引名直接删除。

## 8. 安全约束

- 调用方只能选择获准 `logicalIndex/corpusId`，不能传 ES endpoint、物理索引、脚本或原生 DSL。
- 可过滤/可排序/可返回字段由索引 Schema 白名单定义；未知字段和额外 JSON 属性拒绝。
- 查询接口必须同时使用已认证服务身份和可验证、绑定本请求的最小用户授权投影；管理接口仅接受具备独立管理权限的服务身份，不接受用户投影代替管理授权。
- Index/Rebuild 调用方还必须匹配 Registry 中的`sourceService -> logicalIndex/corpusId/action`白名单；一个源服务不得写入、删除或重建未分配语料库。
- 返回片段有长度、数量和总字节上限；日志不记录原文、搜索全文或安全标签表达式。
- 安全过滤字段缺失、Schema 版本不匹配或权限事实过期时失败关闭。

## 9. 状态模型、一致性与并发

首阶段采用“源数据强权威、索引最终一致”。响应返回 `sourceVersion/logicalIndexVersion/indexedAt`，Agent 可显示数据时效但不得把索引结果用于写事务判断。

- upsert/delete 以文档键和 `sourceVersion` 做乐观并发；
- 每个 `logicalIndex` 同时最多一个活动重建所有者；具体协调存储、CAS/lease/checkpoint 机制只能在源一致性合同确认后由 L2-05 选择，当前阶段 A 不得因此预先引入数据库、Redis 或第二控制面；
- Alias 切换是唯一发布点；不建立自定义 publish fence、manifest 签名或双控制面；
- 失联恢复从任务检查点继续或安全重启，不让调用方猜测任务状态。

## 10. 扩展风险与触发器

| 扩展 | 触发条件 | 进入前证据 |
|---|---|---|
| 向量召回 | 关键词 Recall 明确不达标 | 固定语料、Recall@K、延迟和成本对比 |
| 重排 | 候选相关性影响答案且向量/关键词不足 | NDCG/答案正确率净收益 |
| 混合融合 | 单通道不能满足多类语料 | 可复现评测和降级策略 |
| 文档级 ACL | 语料库权限粒度不足 | 权限模型、过滤前置、撤权时延测试 |
| 独立管理面 | 运维/容量/权限隔离成为真实瓶颈 | 负载和职责证据 |
| 多写者控制 | 两个以上权威写入方 | 冲突所有权和一致性设计 |

## 11. 架构决策

| 编号 | 决策 |
|---|---|
| RET-DEC-01 | 复用独立 `es-query-*` 边界，不建立 Agent 专属检索项目。 |
| RET-DEC-02 | 原始文档是权威，ES 只是可重建派生物。 |
| RET-DEC-03 | 首阶段关键词检索优先，向量/重排按效果证据引入。 |
| RET-DEC-04 | 权限过滤进入检索条件，Agent 返回前再只收紧。 |
| RET-DEC-05 | 调用方只见逻辑索引，物理索引和 Alias 归基础设施。 |
| RET-DEC-06 | 单部署单元内提供查询和管理 API，以权限隔离而非服务拆分。 |
| RET-DEC-07 | 版本化幂等写入、单活动重建、Alias 原子切换构成最小一致性方案。 |
| RET-DEC-08 | 当前代码存在不等于能力可用，实施时必须做合同和效果验证。 |

## 12. 关联 L1 与协作边界

关联 L1“单体 Agent 应用与能力架构”拥有 corpus 选择、证据上下文和回答；本 L1 只保证 SearchHit 和索引任务合同。两者不得共享数据库、ES Client、物理索引名或内部实体。

## 13. 质量门禁

- 合同：extra-forbid、字段白名单、稳定错误码、受限单页和大小限制；
- 安全：越权 corpus、缺失过滤、旧权限、原生 DSL、物理索引注入均被拒绝；
- 一致性：重复/乱序 upsert、删除后旧写、并发重建、切换失败和回滚；
- 效果：固定语料的 Recall@K、空命中、引用定位可复现；
- 运维：任务进度、索引版本、Alias、延迟和错误可观察。
