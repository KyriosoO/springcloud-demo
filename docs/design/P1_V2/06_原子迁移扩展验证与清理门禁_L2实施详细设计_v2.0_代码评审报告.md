## 4. 代码问题清单

| 编号 | 级别 | 类型 | 文件 | 问题描述 | 影响 | 处理结果 |
|---|---|---|---|---|---|---|
| CR-001 | high | authority_http_fail_closed | `AuthServiceUserPermissionAuthorityAdapter.java`、配置类 | 401/403 仍解析不可信 body；响应无字节/集合/标识上限；未来 `resolvedAt` 可接受；阶段 timeout 在绝对 deadline 前被误映射；固定 read timeout 可越过 Invocation 剩余 deadline | 服务身份事故可能接受伪诊断信息；恶意/异常权威响应可造成内存与解析压力；超时语义和执行时限不一致 | 统一 bounded stream（默认 64 KiB）；401/403 使用本地诊断码；增加 canonical id/enum/map/set/attribute 上限；拒绝未来时间；区分阶段超时与绝对超时；每次请求取 `min(readTimeout, remainingDeadline)` 创建 client；新增负向测试 |
| CR-002 | high | artifact_integrity | `AuthorizationSnapshot.java`、`PlanningArtifactCanonicalizer.java`、`PlanningCheckpoint.java` | PAI 和 checkpoint 只保存可预测的 `snapshotId`，没有绑定快照安全语义和 Effective limits reference | 同 snapshotId 的替换快照无法由 PAI/checkpoint 摘要识别，削弱 G4 防替换与审计语义 | 新增 `ASR-1:<sha256>` length-prefixed canonical 安全引用，覆盖主体/Owner/Scope、精确 Profile/Policy/Permission、授权范围、外部处理 evidence、Context 权限、deadline、Domain evidence 和资源限额 ContractRef/digest/invocation/registration；PAI 与 checkpoint 统一消费该引用 |
| CR-003 | high | deployment_configuration | `config-service/.../agent-service.yml` | Config Server 未覆盖 auth-service 地址，部署态仍继承本地 `http://localhost:8090` | 容器/服务环境会访问 agent-service 自身回环地址，唯一权限权威源不可用，所有请求 fail closed | 增加 `http://auth-service`、内部 path、connect/read timeout 与 64 KiB 响应上限；本地开发默认保持不变 |
