## 4. 背景与目标

当前实现和旧设计把 corpus/index、query Profile、validation/rollout 混在一起：

- retrievalProfile、schema/index/model 版本在每个 chunk 重复，索引随 Agent Profile 变化而重建；
- RebuildRequest 接收 sourceUrl、targetIndex、indexDefinition/sourceParams 自由 Map，调用方可影响出站地址、物理索引和 mapping；
- RebuildTask 同时保存 build 与 validation 状态，EsIndexAliasService 又写独立 alias audit；
- 直接 switch/rollback HTTP endpoint 绕过 07 的 Gold/权限/容量/回退 Gate；
- read alias 只校验名称，没有把一次 hybrid request 绑定到唯一 physical index/manifest/report；
- task 缺少可靠幂等、租约恢复、稳定 content digest 和 orphan retention 边界。
- 通用 raw search/index/delete/bulk/rebuild endpoint 接收 caller `{index}`/free DTO，可绕过 Document ACL、server target、schema/seal 和 release gate。

目标是形成一个与 Agent Invocation/Document Profile 解耦的 corpus 基础设施：一个 DocumentCorpusKey 对应一个受控 read alias/schema contract；source connector 形成不可变 snapshot；rebuild 只写 server-generated physical index；成功后 sealed manifest 提供 07 验证输入；07 授权后写入一次 release attestation 并调用 alias 技术原语；在线检索每个请求解析一次唯一 ResolvedIndexTargetRef。

- 供 07 使用的 orphan list/delete technical primitive；
- es-query-api/service、配置、数据库逻辑模型、测试与迁移清单。

### 5.2 范围外

- Document Profile 选择、query feature/resource limits（02）；
- ACL 权威解析、runtime protected filter 和 candidate security（03）；
- hybrid DSL、RRF、dedup/context 与跨 corpus orchestration（04）；
- Gold Query、质量/权限/容量 Gate、change state、rollout/rollback 决策、report/audit/retention approval（07）；
- Agent Core、Runtime、Context、Result Security 或 Multi-Agent 状态机。

## 6. 上级文档约束

1. es-query-service 位于 DocumentRetrievableAdapter 后；Agent Core/Runtime 不直连 Elasticsearch。
2. Canonical Domain Metadata 是业务字段语义权威；index mapping 只声明物理可索引结构，不能反向成为 Agent field policy。
3. ACL projection 是检索过滤事实，不是最终授权结论；缺失/非法必须 fail closed。
4. Java/typed DTO 是跨服务结构权威；sourceParams/indexDefinition/metadata 自由 Map 不得穿透管理边界。
5. P2_V3/00 已冻结 Profile 不拥有 alias/schema；CorpusKey→readAlias/schema contract 由本文唯一负责。
6. 01 只提供 alias technical primitive；07 是 validation report、rollout decision、audit/reconciliation 和 retention approval 的唯一所有者。
7. 当前单 Agent 与 future Multi-Agent 复用同一 corpus/index contract；本文不保存 Invocation Owner/Scope/Task/Run 字段。
8. 系统未投产，不保留 v1/v2 双写/双读或 direct alias compatibility facade；破坏性 contract/DDL 仍需实施授权。

## 8. 设计边界与不变量

| 不变量 | 强制规则 |
|---|---|
| 一个 Corpus 一个 alias | DocumentCorpusKey(domain,materialType) 唯一映射 readAlias/schema contract；alias 不来自 Runtime/Profile/HTTP caller |
| 一次请求一个 target | read alias 必须解析为恰好一个 sealed+attested physical index；0/多 target 均 fail closed |
| Server 分配 physical index | caller 不提供 targetPhysicalIndex；命名由 corpus/schema/buildId 生成并校验 |
| Source 受控 | caller 不提供 URL/header/credential/free params；只选择 corpus 和 connector 可验证的 SourceSnapshotRef |
| Schema 最小化 | chunk 不重复 retrievalProfile/schema/index/model/dimension/snippet/context；这些事实分别归 Profile、manifest 或查询期投影 |
| ACL fail closed | tenant/ACL/version/visibility/status 必需，conditional principal lists 闭合；无 chunk override 隐式继承 |
| Build 与 release 分离 | SUCCESS 只表示 sealed index 完成；VALIDATED/ACTIVE/ROLLED_BACK 不进入 rebuild status |
| Alias 无双状态 | 07 持久化 change/report/audit；01 只执行技术动作并返回 typed actual state |
| 无伪 CAS | Elasticsearch atomic alias action 不等于数据库 CAS；依赖 07 exclusive lease、expected-state check、must_exist remove 和 mandatory post-read |
| 删除需授权 | 失败/旧 physical index 只进入 quarantine/candidate list；01 不自主删除 |
| Document 专用入口 | 通用 raw search/index/delete/bulk/rebuild/alias endpoint 遇到 document alias/physical prefix 一律拒绝；非文档行为保持原契约 |

## 9. 总体设计

~~~text
DocumentCorpusCatalogSnapshot
  DocumentCorpusKey(domain, materialType)
    -> readAlias + schema/analyzer/vector/source-connector refs

Authorized management request
  -> validate corpus + SourceSnapshotRef + idempotency
  -> persist PENDING task and server-generated physical index name
  -> acquire lease -> connector stable snapshot pages
  -> normalize -> deterministic chunk -> schema/ACL validate
  -> bounded idempotent bulk into physical index
  -> refresh/count/mapping check -> seal DocumentPhysicalIndexManifest
  -> task SUCCESS + IndexTechnicalValidationEvidence
  -> P2_V3/07 Gold/security/capacity validation
  -> 07 asks 01 to attach one release attestation
  -> 07 exclusive change lease
  -> 01 guarded compare-and-switch + mandatory read-current
  -> 07 persists outcome/reconciliation/audit

Online hybrid request
  DocumentCorpusKey -> catalog readAlias
  -> read alias once -> exactly one physical target
  -> verify sealed manifest + release attestation
  -> ResolvedIndexTargetRef
  -> all channels query that physical index
~~~

## 10. 详细功能设计

### 10.1 Corpus Catalog 与权威类型

~~~java
public record DocumentCorpusKey(String domain, String materialType) {}

public record DocumentSchemaRef(String name, String version, String canonicalDigest) {}

public record DocumentCorpusDefinition(
    DocumentCorpusKey corpusKey,
    String readAlias,
    DocumentSchemaRef schemaRef,
    String analyzerRef,
    DocumentVectorIndexPolicy vectorPolicy,
    String chunkStrategyRef,
    String sourceConnectorId,
    Set<String> indexedBusinessFields) {}

public record DocumentCorpusCatalogSnapshot(
    String catalogVersion,
    String canonicalDigest,
    Map<DocumentCorpusKey, DocumentCorpusDefinition> definitions) {}
~~~

DocumentCorpusKey 的 domain/materialType 使用与 P1 Canonical Domain Metadata 相同的 canonical identifier 规则，禁止别名和自由大小写。readAlias 只允许小写 `[a-z0-9-]`、长度不超过 128，格式 `agent-doc-<domain-slug>-<material-type-slug>-read`；slug 由受控 canonicalizer 生成，不直接拼接未校验输入。

`DocumentCorpusKey` 是一个逻辑 contract，不要求 Agent Adapter API 依赖 ES wire API：Agent 侧在 `agent-adapter-api` 保存 Spring-free `DocumentCorpusKey(domain,materialType)`，ES 管理/检索 wire 侧在 `es-query-api` 保存字段等价的 `DocumentCorpusKeyDto`。二者必须使用同一 canonical identifier validator、字段顺序和 `DCK-1 = domain + U+001F + materialType` canonical bytes；`agent-adapter-document` 是在线请求/响应唯一 mapper。contract test 必须覆盖双向映射、非法大小写/别名/空值、canonical bytes一致和unknown field拒绝。不得让 `agent-adapter-api` 依赖 `es-query-api`，也不为一个两字段 value 新建公共模块。

Catalog candidate builder 必须校验 key/alias 唯一、schema/analyzer/vector/chunk strategy/source connector 引用闭合、business fields 无重复且在 schema technical allowlist 内。跨 Agent Domain Metadata 的业务语义闭合由 07 release gate 校验；01 不调用 agent-service metadata。Catalog 作为一个 immutable snapshot 原子发布；reload 失败保留旧 snapshot，不部分替换。Catalog 保存 alias 名称和允许的 schema contract，不保存 current physical target、release report 或 rollout state。

### 10.2 Source Connector 与不可变 Snapshot

~~~java
public interface DocumentSourceConnector {
    String connectorId();
    SourceSnapshotDescriptor assertSnapshot(SourceSnapshotRef ref, Instant deadline);
    DocumentSourcePage readPage(
        SourceSnapshotRef ref,
        ProtectedSourceCursor cursor,
        int pageSize,
        Instant deadline,
        RebuildCancellationSignal cancellation);
}
~~~

SourceSnapshotRef 只包含 connector 可验证的 safe identifier/version/canonical digest，不包含 URL、query、header、token、credential 或自由 params。connector endpoint/credential 只在 composition root 注入；registry 按 DocumentCorpusDefinition.sourceConnectorId 精确解析唯一 connector。unknown/duplicate connector、snapshot digest 变化、keyset order 不稳定、deadline/cancel 或权威源不可用均使 task fail closed。

connector 必须按稳定 `(tenantId,documentId,documentVersion)` keyset 顺序分页；同一 SourceSnapshotRef 的内容和顺序不可变化。cursor 是 opaque protected value，只用于该 task/connector/snapshot，持久化时加密并绑定 AAD，禁止日志输出。当前 `RebuildRequest.sourceUrl/sourceParams` 和 `DocumentSourceUrlPolicy` 不是目标边界，原子迁移后删除。

### 10.3 Normalized Document 与最小 Chunk Schema v3

一个 physical index 只承载一个 DocumentCorpusKey，因此 corpusKey/schema/index/profile/model 等 index-level facts 只写 sealed manifest，不在每个 chunk 重复。

`DocumentNormalizer.normalize(SourceDocument,DocumentCorpusDefinition)` 只接受 connector typed document，执行 Unicode/line-ending/whitespace canonicalization、safe URI 清理、business field allowlist 与完整 ACL projection；不读取 Agent Profile。`DocumentChunker.chunk(NormalizedDocument,chunkStrategyRef)` 使用版本化 deterministic strategy，按字符边界生成稳定 chunkIndex/offset；同一 normalized document + strategy 必须得到同一 chunk 序列。Normalizer/Chunker 不访问 ES、Provider 或 Runtime；未知 source field、无 ACL、不可净化 URI、超长文本或不稳定结果均使 task FAILED。

| 字段组 | 字段 | 必填/条件 | 约束 |
|---|---|---:|---|
| Tenant/identity | tenantId、documentId、documentVersion、chunkId、chunkIndex | 是 | keyword；非空；chunkIndex 非负 |
| Offset | charStart、charEnd | 是 | 非负且 start < end；基于 canonical normalized document |
| Text | content | 是 | 非空、有长度上限；text analyzer 由 corpus schema 固定 |
| Display | title、section、page | 否 | title/section 是 text；page 非负整数；缺失不伪造 |
| Source | safeSourceUri、sourceUpdatedAt | 否/按 connector | URI 已去 query/fragment/credential；date 使用 UTC |
| Integrity | chunkContentHash | 是 | SHA-256 lowercase hex，覆盖 canonical normalized chunk content |
| Lifecycle | status | 是 | ACTIVE/REVOKED/DELETED/EXPIRED/BLOCKED；online 只允许 ACTIVE |
| ACL | aclRef、aclVersion、visibility | 是 | keyword；visibility 只允许 TENANT/USER/DEPARTMENT/ROLE/ATTRIBUTE/PUBLIC，PUBLIC 仍受 tenantId 约束 |
| ACL principals | userIds/departmentIds/roleIds/attributeKeys | 条件 | 对应 visibility 时必须非空、有界、去重稳定排序；其他 visibility 时必须为空 |
| Business | indexedBusinessFields 中的显式字段 | 否 | 每个字段有 schema 固定类型；禁止 metadata Map |
| Vector | embedding | vector enabled 时 | dense_vector；维度/model 只由 physical manifest 固定；字段从 `_source` 排除 |

目标 schema 不保存 retrievalProfile、schemaVersion、indexVersion、embeddingModel、embeddingDimension、snippet、contextBefore/contextAfter、raw ACL expression/token、original binary 或 provider request/response。safeSnippet 由 03 在 ACL 后从当前安全 content/highlight 投影；context window 由 04 使用相邻 chunkId/chunkIndex 有界读取，禁止每个 chunk 复制上下文全文。

DocumentChunkSchemaValidator 必须执行 required/conditional 字段、类型/长度、ID/hash、offset、ACL closure、unknown field 和 vector finite/dimension 校验。当前 chunkAclOverride 隐式继承路径删除；每个 chunk 都携带完整规范化 ACL projection，同一 document/version 的 ACL digest 不一致时整次 build 失败。

### 10.4 Mapping 与 Schema v3

DocumentIndexDefinitionRegistry 按 DocumentSchemaRef 返回 immutable typed definition；管理 caller 不提交 indexDefinition。mapping 强制 `dynamic: strict`，核心类型如下：

| 字段 | ES 类型/设置 |
|---|---|
| tenantId/documentId/documentVersion/chunkId/aclRef/aclVersion/visibility/status | keyword，无 analyzer |
| userIds/departmentIds/roleIds/attributeKeys | keyword array，doc_values enabled |
| chunkIndex/charStart/charEnd/page | integer |
| content/title/section | text；仅 schema 明确允许的字段有 keyword subfield |
| sourceUpdatedAt | date，UTC |
| safeSourceUri/chunkContentHash | keyword；safeSourceUri `index:false` |
| business fields | schema 明确的 keyword/text/date/integer/boolean；禁止 runtime dynamic mapping |
| embedding | dense_vector，固定 dims/similarity；`_source.excludes` 包含 embedding |

DocumentIndexDefinitionValidator 只校验 technical schema：required mappings、dynamic strict、analyzer registry、vector policy、ACL keyword filterability、source excludes 和 unknown field。Canonical Domain Metadata 与 indexedBusinessFields 的语义/权限闭合由 07 通过 agent-service evidence 校验，避免 es-query-service 建第二份 Domain Catalog。

### 10.5 稳定 ID 与 Canonical Digest

- chunkId = base64url(SHA-256(CHUNK-1 + tenantId + documentId + documentVersion + chunkIndex + charStart + charEnd + chunkStrategyRef))；
- ES `_id` 等于 chunkId；同一 snapshot retry 覆盖同一文档，不产生重复 hit；
- chunkContentHash = SHA-256(CONTENT-1 + canonical UTF-8 content/title/section/business field projection)；
- schema digest 由 typed DocumentIndexDefinition canonicalizer 生成，禁止 Map iteration/hashCode；
- indexContentDigest = SHA-256(ICD-1 + corpusKey + sourceSnapshotDigest + schemaDigest + 按稳定 keyset 顺序的 chunkId:chunkContentHash 流)；
- manifestDigest = SHA-256(MANIFEST-1 + 第 10.8 节所有语义字段)。

connector 顺序、chunk strategy 或 canonical form 变化必须产生新 version/ref；不能复用旧 digest。任一 chunk 校验/写入失败均不得形成 contentDigest/manifest/SUCCESS。

### 10.6 Document 专用 Rebuild 请求与内部写入边界

~~~java
public record StartDocumentRebuildRequest(
    String requestId,
    String idempotencyKey,
    SourceSnapshotRef sourceSnapshotRef,
    DocumentSchemaRef expectedSchemaRef,
    Long expectedDocumentCount) {}

public record DocumentRebuildTaskView(
    String taskId,
    DocumentCorpusKey corpusKey,
    String targetPhysicalIndexSafeRef,
    DocumentRebuildStatus status,
    long documentsRead,
    long chunksIndexed,
    String failureCode,
    String diagnosticId,
    Instant createdAt,
    Instant updatedAt) {}
~~~

caller 不能提交 requestedBy/operatorRef、release/change/report ref、source URL/header/params、targetPhysicalIndex、mapping/analyzer/vector model、documents、cursor 或 credential。主体来自管理服务认证上下文；Corpus Catalog 决定 connector/schema/chunk/vector policy；服务端在 idempotency row 创建事务中生成 taskId/buildId/physical index。expectedSchemaRef 只是防止 caller 在 catalog reload 后误建旧 schema 的 optimistic assertion，必须等于当前 catalog 值，不能选择 schema。

当前 Document v3 只支持 FULL_SNAPSHOT build：每个 SourceSnapshotRef 生成一个全新 physical index。不存在 active index 的 incremental write、document-level public upsert/delete 或 generic incrementalRebuild compatibility path；source 删除通过新 snapshot 中缺失并切换新 index 生效。future incremental 只有在定义 copy-on-write/new-physical-index、snapshot closure、delete tombstone、digest 和 rollback 证明后才能增加，不能原地更新 active index。

物理索引格式 `agent-doc-<domain-slug>-<material-type-slug>-s<schema-major>-<build-id>`，长度不超过 255，buildId 使用 server 生成的受控标识。Start 返回 202 + task view；相同 idempotency key/semantic request 返回原 task，不同 request 返回 409 IDEMPOTENCY_CONFLICT。

DocumentIndexRebuildService 使用独立的 typed endpoint/use case：`POST /document-corpora/{domain}/{materialType}/rebuilds`；DocumentCorpusKey 只来自 canonicalized path，body 不再复制 domain/materialType。现有 generic RebuildRequest/RebuildTask/IndexRebuildService 只保留给非文档 index，不得作为 Document compatibility facade。

DocumentIndexAccessGuard 以 Corpus Catalog alias、physical naming canonicalizer 和 sealed manifest 三类证据识别 Document target。通用 `/indexes/{index}/search|documents|bulk|rebuild/*` 以及 direct alias endpoint 对任何 Document alias/physical target 返回受控 `DOCUMENT_SPECIALIZED_ENDPOINT_REQUIRED`，且不执行 raw DSL、write/delete/bulk/source URL/rebuild。guard 必须检查 path index 和 request 内全部 target-like 字段；任一命中 Document、path/body target 不一致或未知但以受控 document prefix 开头均拒绝。对未知 alias 还须读取实际 targets/manifest；任一 target 是 Document physical index 即拒绝，防止以非文档 alias 或非文档 path + Document targetIndex 绕过。

IndexBuildWriter 是 service internal port，只接收 task-issued IndexBuildTargetHandle、validated chunk batch 和 task lease；无 public controller/DTO。它不接受任意 index 名称。非文档 generic endpoint/service 不持有该 handle，也不能调用 Document writer。

### 10.7 Rebuild 算法、状态、取消与恢复

状态固定为 PENDING、RUNNING、SUCCESS、FAILED、CANCELLED；VALIDATED/ACTIVE/ROLLED_BACK 属于 07 report/change，不进入 task enum。

执行顺序：

1. start 事务按 idempotency digest 插入 PENDING task 并分配 physical index；
2. worker CAS 获取 `(taskId,rowVersion,status,leaseExpiresAt)`，进入/续持 RUNNING lease；
3. 创建 typed mapping，写入未 sealed build metadata；
4. connector assertSnapshot，按稳定 keyset/cursor 读取；
5. normalize/chunk/validate 全批通过后 bulk；任一业务无效 chunk 立即 FAILED，不跳过；
6. ES transient bulk failure 可按 offline rebuild operational policy 有界重试，attempt 可观测且 deterministic `_id` 幂等；这不复用 Agent Invocation 的 Provider attempt policy；
7. 每批成功后 CAS 更新 protected cursor/counts/heartbeat/rowVersion；lease loser 立即停止；
8. cancel_requested 在页/批次边界检查；已提交 bulk 必须先确认结果，再进入 CANCELLED；
9. source snapshot/current digest 漂移、partial bulk unresolved、count mismatch 或 deadline/lease 不可恢复时 FAILED；
10. 全量完成后 refresh、count、mapping/ACL/vector validation、content digest，写入 sealed manifest；只有全部成功才 CAS SUCCESS。

进程崩溃后，recovery worker 只可重新获取过期 RUNNING lease并从 protected cursor 继续；deterministic `_id` 保证已提交批次重放不重复。若上一次 bulk outcome unknown，必须按 `_id`/batch evidence 读取确认后再继续，不能盲目增加 count。FAILED/CANCELLED physical index 保持 quarantine，不自动删除。

### 10.8 Sealed Manifest、Technical Evidence 与 Release Attestation

~~~java
public record DocumentPhysicalIndexManifest(
    String physicalIndex,
    DocumentCorpusKey corpusKey,
    DocumentSchemaRef schemaRef,
    String analyzerRef,
    String vectorPolicyRef,
    String chunkStrategyRef,
    String sourceSnapshotRef,
    String sourceSnapshotDigest,
    String taskId,
    long documentCount,
    long chunkCount,
    String indexContentDigest,
    Instant sealedAt,
    String manifestDigest) {}

public record DocumentReleaseAttestation(
    String validationReportRef,
    String validationReportDigest,
    String manifestDigest,
    Instant attestedAt,
    String attestationDigest) {}
~~~

Manifest 在 SUCCESS 前一次写入 physical index mapping `_meta.agent_document_manifest` 并在 task row 保存 manifestDigest，随后设置 `index.blocks.write=true` 并回读 manifest/settings/count；seal 后拒绝 document 与 schema mapping 写入。唯一例外是 07 授权的 one-time release attestation metadata 更新，更新时必须原样保留 manifest 并再次回读校验。IndexTechnicalValidationEvidence 返回 manifest、mapping/ACL/vector/count 验证结果和 diagnostic refs，供 07 生成 Gold/security/capacity report；它不是 release approval。

07 的 report 全部通过后，通过受控内部命令调用 `attachReleaseAttestation`。01 只验证 attestation 与 manifest/report command binding 并执行 absent→present 一次写入；已存在同 digest 幂等返回，存在不同值冲突。attestation 绑定 physical manifest 与 immutable validation report，不绑定某一次 rollout change；多个 07 change 可在 report 仍有效且 Gate 重新确认时引用同一 attestation。若必须更换 report，则构建新 physical index，不在原 index 改写 attestation。attestation 是 07 权威 report 的只读运行投影，不是 01 的第二 report/audit repository。未 sealed、未 attested 或 binding 不一致的 physical index 不可成为 read target。

### 10.9 在线 Read Target 解析

`DocumentIndexTargetResolver.resolve(DocumentCorpusKey key)` 每个 hybrid request 固定执行一次：

1. 从同一 immutable Corpus Catalog snapshot 解析唯一 readAlias/schema contract；
2. 查询 ES alias 实际 target；0 个返回 TARGET_MISSING，多于 1 个返回 TARGET_AMBIGUOUS 并告警；
3. 读取唯一 physical index 的 manifest + release attestation；
4. 校验 corpusKey/schema/manifest/attestation/report ref 完整绑定且 index 已 sealed；
5. 返回 `ResolvedIndexTargetRef(alias,physicalIndex,schemaVersion,indexContentDigest,manifestDigest,validationReportRef,attestationDigest)`；
6. 04 的同一 hybrid request 所有 BM25/phrase/vector/context channel 只使用该 physicalIndex，不再读 alias。

Resolver 不接受 alias/physical index 作为用户或 Agent caller 输入，不缓存跨请求 current target。alias 在解析后切换不影响当前请求；下一请求重新解析。physicalIndex、manifest/report full digest 不进入用户响应或高基数 metrics。

### 10.10 Alias Guarded Compare-and-Switch

Elasticsearch `_aliases` 只保证一个 action list 原子应用，不提供完整 compare-and-set。目标语义由 07 serialized exclusive change lease + 01 技术原语共同构成：

1. `DocumentRolloutCoordinator` 在 07 持久化 PREPARED change 并取得 CorpusKey exclusive lease；
2. 通过 package-private factory 构造 `AuthorizedAliasChangeCommand(changeId,corpusKey,expectedState,targetPhysicalIndex,manifestDigest,reportRef,attestationDigest,deadline)`；无 JSON/public builder；
3. 01 pre-read actual alias state，要求等于 expected NONE 或 SINGLE(index)；AMBIGUOUS 立即拒绝；
4. 验证 target sealed/attested、CorpusKey/schema/report/manifest binding 和非当前 alias foreign target；
5. SINGLE 时提交 `remove(expected,alias,must_exist=true)+add(target,alias)` 一个 atomic action；NONE initial activation 只允许持有 07 exclusive lease；
6. 无论 HTTP 成功、异常或 timeout 都 post-read actual state；
7. 返回 APPLIED/ALREADY_APPLIED/CONFLICT/UNKNOWN/AMBIGUOUS typed result；ALREADY_APPLIED 仅在 target 与全部 binding 相同；
8. 07 持久化 result 或进入 reconciliation；UNKNOWN/AMBIGUOUS 不自动重试或猜测 rollback。

switch 与 rollback 复用同一 `compareAndSwitch`，只有 expected/target 不同，不保留两套 service/endpoint。01 不写 rollout intent/history/current state；技术日志只记录 changeId、alias safe ref、result/reason/duration，不记录 operator/正文。当前 `/indexes/{index}/aliases/read/switch|rollback` direct endpoint 和 caller-created AliasSwitchRequest 在原子迁移后删除；后续管理入口由 07 唯一提供。

### 10.11 Physical Index 保留与删除技术原语

01 可提供 `listPhysicalIndexCandidates(corpusKey)`、`inspectReferences(physicalIndex)` 和 `deletePhysicalIndex(AuthorizedIndexDeletionCommand)`。07 根据 active alias、pending/unknown change、report/audit、rollback window 和 legal retention 形成授权命令；01 再次读取 alias，任何 alias 引用、未终结 task、command binding 不一致或 authority 不可确认均拒绝删除。

本文不启用自动清理 job，不按年龄直接删 FAILED/CANCELLED/旧 index。物理删除、已有表/数据迁移和本地测试数据重建属于破坏性实施动作，必须在 M0 单独获用户授权。

## 12. 数据与配置设计

### 12.1 Elasticsearch physical index

- 一个 physical index 只对应一个 CorpusKey、schemaRef 和 source snapshot；
- mapping `_meta` 保存 sealed manifest 与 optional one-time release attestation；
- `_source` 不保存 embedding、raw ACL token、original binary、query/provider payload、snippet/context 副本或自由 metadata；
- read alias 始终期望一个 target；多 target 是高危异常，不作为正常 fan-out；
- alias 实际状态以 ES read-current 为外部事实，数据库不复制“当前 target”作为查询权威。

### 12.2 document_index_rebuild_task 逻辑字段基线

## 13. 状态流转设计

### 13.1 Rebuild task

~~~text
PENDING -> RUNNING -> SUCCESS
                   -> FAILED
                   -> CANCELLED
PENDING ----------> CANCELLED
RUNNING -- lease expired --> RUNNING (new lease owner, same task)
~~~

SUCCESS 不转 VALIDATED/ACTIVE。validation report、release attestation、rollout change 是独立事实，由 07 管理。FAILED/CANCELLED 不自动重启；同一 idempotency request 返回原 terminal task，新任务需要新 idempotency key/source snapshot。

### 13.2 Alias operation result

APPLIED、ALREADY_APPLIED、CONFLICT、UNKNOWN、AMBIGUOUS 是一次技术调用结果，不持久化为 01 业务状态机。07 将其映射到自己的 change/reconciliation 状态。

## 14. 幂等、事务与一致性设计

- idempotencyDigest = SHA-256(IDEMKEY-1 + authenticated management scope + validated idempotencyKey)，作为 unique scope key；
- requestDigest = SHA-256(IDEMREQ-1 + corpusKey + sourceSnapshotRef/digest + expectedSchemaRef + expectedCount)；rebuild 与 rollout change/report 解耦；
- start 事务原子完成 unique idempotencyDigest insert、requestDigest/task/target allocation；unique 冲突后同 requestDigest 返回原 task，不同 requestDigest 返回 409；
- task progress/lease/cancel/terminal 更新全部使用 status + rowVersion CAS；lost update 不覆盖；
- connector snapshot 和 stable keyset 保证 resume；bulk 使用 deterministic `_id`，unknown outcome 先查后重放；
- SUCCESS 必须与 manifestDigest/contentDigest/counts 同一 CAS 提交；manifest 未写成功不得 SUCCESS；
- release attestation 使用 absent→present CAS 语义；同 digest 幂等，不同 digest 冲突；
- alias compare-and-switch 由 07 exclusive lease 串行化，01 pre/post-read；UNKNOWN 必须由 07 reconciliation 收敛；
- alias operation 与 07 DB 不能形成跨 ES/DB 事务，故使用 intent→operation→actual-read→result 模式，不宣称强事务；
- online read target 以 ES actual + physical manifest/attestation 为准，不信任数据库缓存。

## 15. 权限、风控与审计设计

- rebuild start/status/cancel 使用独立管理服务身份和最小 scope；不转发 Agent 用户 JWT；
- authenticated principal/request scope 由 server context 注入，request body 不接受 operatorRef/requestedBy；
- source connector 只访问注册 endpoint，防 SSRF/DNS rebinding/redirect 到非 allowlisted target；credential 不进入 DTO/task/cursor/log；
- caller 不能指定 physical index、mapping、analyzer、vector model、alias、release report 或 deletion target；
- DocumentIndexAccessGuard 必须先于通用 raw search/write/delete/bulk/rebuild 的业务校验、ES/HTTP 调用和任务创建；命中 Document target 时不得使用 caller DSL、document Map、source URL 或 idField；HTTP body 大小/JSON 结构仍由统一入口限制；
- generic Elasticsearch client credential 的 index privilege 排除 `agent-doc-*`；Document hybrid/build/alias technical client 使用独立最小 service role，且不暴露给 generic controller。应用 guard 与 ES privilege 必须同时存在，避免 alias/代码缺陷旁路；
- chunk ACL required/conditional closure 不成立时整次 build 失败；PUBLIC 仍必须 tenant-scoped；
- physical manifest/attestation/digest 只证明完整性和发布绑定，不替代 03 current ACL 或 P1 Result Security；
- audit 所有者：01 记录 safe technical task/operation facts；07 保存 report/change/operator/rollout/rollback/retention audit。禁止双写 current state；
- 日志不记录正文、source URI、cursor、principal lists、ACL ref full value、physical index full list、operator identity、secret 或 raw ES response。

## 16. 性能与容量设计

- rebuild batchSize、pageSize、bulk bytes、in-flight batches、lease duration、offline bulk attempts 都有 deployment hard cap；caller 只能更小收窄；
- normalize/chunk/digest 流式处理，不把完整 corpus 或全部 chunk hash 常驻内存；稳定顺序直接更新 streaming digest；
- unknown bulk verification 按 batch `_id` 有界查询；禁止全索引 scan 作为正常 retry；
- mapping/count/ACL technical validation 可使用 `_count`/bounded aggregation；完整 Gold/permission query 属于 07；
- online 每个 hybrid request 一次 alias read + manifest/attestation 校验，随后所有 channel 使用 physical target；不跨请求缓存 current target；
- content/title/section 不复制 snippet/context；embedding 排除 `_source`，减少 response/heap；
- metrics label 只用 corpus safe family/schema major/result，不使用 tenant/document/task/physical index/digest 全值。

## 17. 兼容性与扩展性设计

- schema/mapping 不在 active physical index 原地修改；新 schema/source/vector/chunk strategy 构建新 physical index并经 07 gate 切换；
- 当前 Document build 只有 FULL_SNAPSHOT；generic incrementalRebuild 对 Document target 被 guard 拒绝。future 增量仍必须产出新 physical index，不允许 active index 原地 patch；
- 当前 schema v3 是唯一 reader/writer，不保留 v1/v2 dual read/write；旧 fixture 只保留为 migration negative test；
- 新 domain/materialType 只新增 Corpus Definition、source connector binding、schema/business field evidence和新 index，不复制 rebuild/alias service；
- 当前一个 Validated Document Plan/hybrid request 只允许一个 DocumentCorpusKey，alias 本身不做 multi-target fan-out；未来多 materialType 必须由上层 coordinator/Multi Agent 为每个 Corpus 建立独立 child Invocation、Authorization 与 ResourceLimit 后协调，不属于 01 target resolver 或 04 leaf retrieval；
- 新 source system 实现同一 DocumentSourceConnector；不扩展 RebuildRequest 为 URL/free Map；
- future Multi-Agent 复用同一 CorpusKey/ResolvedIndexTargetRef；index/task 不增加 Run/Task/Owner/Delegation 字段，授权仍在 Agent execution boundary；
- public management contract 破坏性替换不保留长期 facade；实施必须一次更新 caller、tests、OpenAPI/DTO 和 direct alias endpoint 删除。
- 非文档 generic search/index/delete/bulk/rebuild 不在本文重构；只增加 Document target deny guard 和回归测试，避免无关影响。

## 21. 风险与待确认事项

| 风险 | 触发场景 | 影响 | 处理 | 是否阻塞 |
|---|---|---|---|---:|
| Document API 切换 | 现有 caller 可能用 generic rebuild/direct alias 管理 Document target | 加 guard 后旧调用失败 | M0 清点 caller，新增 Document typed client/endpoint 后与 guard/direct alias 删除同一 candidate 激活；非文档 generic 不变 | 阻塞实施 |
| 数据库/已有数据 | V1～V3 已创建 task/alias audit | migration 失败或丢历史 | 用户授权后做数据预检，选择 V4 forward migration 或明确本地重建 | 阻塞实施 |
| Source connector 未冻结 | 当前依赖 caller sourceUrl | 无安全数据源入口 | 先实现/选定 registered connector；未就绪 corpus 不启用 rebuild | 阻塞对应 corpus |
| ES client role 未分离 | generic raw endpoint 与 Document technical path 共用 credential | 应用 guard 缺陷可泄露/修改 Document index | M0 授权 secret/role/config，generic role 排除 agent-doc，Document role 最小化 | 阻塞实施 |
| ES alias 非真 CAS | initial activation 或外部手工改 alias | 多 target/unknown | 07 exclusive lease + must_exist + post-read；异常 freeze/reconcile | 阻塞 07 |
| analyzer/vector 模型待选 | corpus schema 尚无真实技术参数 | 无法产出有效 physical index | registry 支持 disabled vector；真实参数进入 07 validation | 不阻塞文档 |
| Physical index 清理 | FAILED/旧 index 占空间 | 容量增长 | 07 retention decision + 01 authorized delete；无授权不自动删 | 不阻塞文档 |
| Domain field evidence | es-query 不读取 P1 Catalog | schema 与 Agent field semantics 可能漂移 | 07 release gate 比较 schema evidence 与 agent-service metadata evidence | 阻塞 07 |
