## 4. 背景与目标

文档检索的权限风险不只发生在查询入口：用户 filter 可试图扩大范围；某一 channel 可能漏掉 ACL；alias 切换可能使通道落到不同 target；RRF/dedup/context 可能合并未绑定 hit；rerank/generation 可能看到 ACL 主体列表、全文或内部索引；检索完成后权限或 emergency state 还可能变化。

当前实现还存在具体缺口：

- `DocumentAclScope` 暴露 user/department/role/attribute 列表给 Adapter；
- `DocumentAclFilterFactory` 以 `Map<String,Object>` 构建 DSL，并包含 schema v3 已不存在的 corpus/profile 字段；
- `DocumentRetrievalMapper` 自行合并用户/ACL Map，任一重构都可能丢掉 protected filter；
- ACL client 发送 retrievalProfile/profileVersion/indexAlias，并用自由 Map 解析响应；
- `DocumentRevocationGuard` 直接读取 `AgentProperties.blocklist`，与 07 emergency control state 双权威；
- 缺少 response target/filter/evidence binding 和 candidate 级 ACL object currentness。

目标是形成从 current authority 到最终输出的不可放大链：一个 Invocation/Corpus 对应一个 current ACL evidence 和一个 canonical protected filter；es-query-service 在所有 channel 强制复用；raw hit 在算法前先验证 target/filter/evidence；Provider 只接收安全投影；Result Security 紧邻序列化前完成 candidate ACL object 与 07 emergency state currentness 复检。

## 8. 设计边界与不变量

| 不变量 | 强制规则 |
|---|---|
| P1 current first | 只有 P1 Execution authorization recheck 成功后才能解析 Document ACL scope |
| exact binding | ACL evidence 必须绑定 invocation/correlation/registration/subject/Corpus/Profile projection/Permission/limit reference |
| 一个 Corpus 一份 evidence | 当前一个 Validated Plan/Hybrid request 只允许一个 `DocumentCorpusKey`、一个 ACL evidence 和一个 protected filter digest |
| typed authority | request/response 不使用 Map/free predicate；unknown field/subtype fail closed |
| no profile/index input | ACL authority request 不含 profileName、indexAlias、physicalIndex、schema 或 Provider facts |
| protected/caller 分离 | caller filter 永远不能承载、替换、删除或 merge protected filter；两者只在 es-query-service 顶层 AND |
| every channel | BM25/phrase/vector/context fallback 等所有实际 ES query 使用同一 compiled protected filter object |
| target/filter response binding | 每个 retrieval response/hit 必须匹配 Corpus、target binding、filter digest 和 ACL evidence digest |
| no raw ACL downstream | raw scope/principal lists 不进入 Runtime、Provider、Context、candidate、result、checkpoint 或日志；只有最小 compiled terms 进入受信 es-query-service |
| Safe 不等于 final | `SafeDocumentCandidate` 只表示可进入 04/05/06 内部链，仍需 citation/Result Security/final currentness |
| no positive allow cache | 当前阶段不跨 Invocation 缓存 ALLOW scope/currentness；authority 每次解析并在 final batch 复检 |
| whole-result fail closed | permission version change、candidate revoked、emergency blocked 或 currentness unavailable 时整体拒绝，不静默删除候选后返回部分结果 |
| governance split | 07 持久化 emergency state；03 Guard 读取 current view 并作 Invocation 级决策；无 AgentProperties local blocklist |
| no second state machine | 所有步骤只作 Invocation 内对象/trace，不持久化 Document execution 状态或发 event bus |

## 9. 总体设计

~~~text
P1 Execution authorization/current limits recheck
  -> DocumentAclScopePort.resolve(current permission evidence + selected Corpus)
  -> DocumentAclExecutionEvidenceFactory
  -> DocumentProtectedFilterFactory (closed AST + DAF-1 digest)
  -> DocumentRetrievalCommand
       callerFilters (typed, separate)
       protectedFilterBinding (required, immutable)
  -> agent-adapter-document maps typed-to-typed
  -> es-query-service validates binding and compiles protected filter once
       AND caller filter
       -> same physical target + same protected filter for every channel/context read
       -> DocumentChannelHitBindingValidator -> BoundDocumentChannelHit
       -> 04-owned RRF/dedup/context implementation (bound hits only)
  -> fused retrieval response carries Corpus/target/filter binding
  -> Adapter DocumentRetrievalResponseBindingValidator -> AclBoundDocumentHit
  -> DocumentCandidateSecurityProjector -> SafeDocumentCandidate
  -> optional rerank / 05 evidence / 06 generation
  -> 04 Handler final candidate set fixed
       DocumentRevocationGuard external current check:
         ACL scope version + candidate aclRef/aclVersion batch currentness
         07 emergency control current view
       -> short-lived candidate-set-bound ALLOW decision
  -> DocumentResultSecurityProjector
       local decision freshness/binding recheck
  -> ALLOW final payload or whole-result fail closed
~~~

filter digest 用于稳定完整性绑定和跨通道一致性检查，不是授权签名。跨服务调用还必须使用专用服务身份、TLS、最小 `document:hybrid-search` scope 和 Document target guard；未知/普通 generic caller 不能提交 protected filter 访问 Document index。

## 10. 详细功能设计

### 10.1 ACL Authority Port 与 typed outcome

~~~java
public record DocumentAclScopeRequest(
    CapabilityOperationContext operationContext,
    String registrationIdentity,
    ExecutionSubjectRef subjectRef,
    DocumentCorpusKey corpusKey,
    DocumentOperation operation,
    PermissionEvidenceReference permissionEvidence,
    String profileProjectionDigest)
    implements CapabilityOperationRequest {}

public sealed interface DocumentAclScopeResolution
    permits DocumentAclScopeAllowed, DocumentAclScopeDenied,
            DocumentAclScopeFailed {}

public record DocumentAclScopeAllowed(
    DocumentAclScopeSnapshot scope,
    CapabilityOperationMetadata metadata)
    implements DocumentAclScopeResolution {}

public record DocumentAclScopeDenied(
    DocumentAclDenyReason reason,
    String decisionEvidenceRef,
    CapabilityOperationMetadata metadata)
    implements DocumentAclScopeResolution {}

public record DocumentAclScopeFailed(
    DocumentAclFailureCode code,
    String diagnosticId,
    CapabilityOperationMetadata metadata)
    implements DocumentAclScopeResolution {}

public interface DocumentAclScopePort {
    DocumentAclScopeResolution resolve(DocumentAclScopeRequest request);
}
~~~

request 的 invocationId/requestCorrelationId/capabilityId/operationId/deadline/cancellation/limits 和 `ResourceLimitReference` 从 `CapabilityOperationContext` 取得，禁止再传第二份独立 deadline/limit/ref。subjectRef 与 permission evidence 只能来自 current `ExecutionScope`；caller/Runtime/Provider 不能提供。

ACL authority endpoint/credential 使用独立 `DocumentAclAuthorityCredentialProvider`，不得复用 LLM/Embedding Provider credential/header。client 最多一次 outbound attempt，自动 retry 关闭；timeout=`min(aclOperationalStageCap, absoluteDeadline-now)`；本地 client 形成 operation metadata。HTTP null/unknown/oversize/body binding mismatch/5xx/timeout/cancel/late response 形成 typed failure并整体拒绝，不用 exception message 生成用户文本。

### 10.2 Scope Snapshot 的封闭模型

~~~java
public record DocumentAclScopeSnapshot(
    String tenantId,
    String subjectPrincipalId,
    Set<String> departmentIds,
    Set<String> roleIds,
    Set<String> attributeKeys,
    DocumentIdConstraint documentIdConstraint,
    Set<String> deniedDocumentIds,
    String authorityVersion,
    String permissionVersion,
    Instant issuedAt,
    Instant expiresAt,
    String authorityEvidenceRef,
    String locallyComputedCanonicalDigest) {}

public sealed interface DocumentIdConstraint
    permits AllPrincipalVisibleDocuments, OnlyDocumentIds {}

public record AllPrincipalVisibleDocuments() implements DocumentIdConstraint {}
public record OnlyDocumentIds(Set<String> documentIds) implements DocumentIdConstraint {}
~~~

Scope 不接受任意 field/operator/predicate/DSL/role expression。`OnlyDocumentIds` 必须非空；authority 完全拒绝时返回 `DocumentAclScopeDenied`，不返回空 scope 或 `match_none` 伪装成功。全部 set 非 null、去重、稳定排序，并满足 parser hard cap；tenant/subject/authorityVersion/permissionVersion/evidenceRef 非空，`issuedAt <= now < expiresAt` 且 `expiresAt-issuedAt <= maxAuthorityEvidenceTtl`。TTL cap 是 03 authority client 的 operational/security cap，不与本次较短 absoluteDeadline 混为一值；实际调用仍受 absoluteDeadline 限制。

authority wire 可以提供声明的 payload digest，但 agent-service 必须对 strict parsed/canonicalized scope 使用 `DAS-1` 本地重算；声明缺失时使用本地值，声明存在但不一致时 `DocumentAclScopeFailed(INVALID_RESPONSE)`。`DocumentAclScopeSnapshot` 只保存 locally computed digest，不信任 authority 自报的 canonical bytes/hash。

authority response 的 permissionVersion 必须精确等于 P1 current permission evidence version，不能只比较递增大小；ACL authorityVersion 必须满足受控 canonical/version 格式。版本回退、无法比较、响应 subject/corpus/operation/binding 不匹配均拒绝。

### 10.3 DocumentAclExecutionEvidence

raw scope 仅在 agent-service ACL 包内短暂存在。`DocumentAclExecutionEvidenceFactory` 使用 trusted request、scope 和 operation metadata 构造：

~~~java
public record DocumentAclExecutionEvidence(
    String invocationId,
    String requestCorrelationId,
    String registrationIdentity,
    ExecutionSubjectRef subjectRef,
    DocumentCorpusKey corpusKey,
    DocumentOperation operation,
    PermissionEvidenceReference permissionEvidence,
    String aclAuthorityVersion,
    String aclScopeDigest,
    String resolveOperationMetadataDigest,
    String profileProjectionDigest,
    ResourceLimitReference resourceLimitReference,
    Instant issuedAt,
    Instant expiresAt,
    String canonicalDigest) {}
~~~

canonical form 使用 `DAE-1`，覆盖全部 binding 与 `resolveOperationMetadataDigest`；该 metadata digest 只由本地 client 对 operationId/type/attempt/termination/limit reference/diagnostic safe fields 形成。DAE-1 使用 SHA-256 lowercase hex、固定字段顺序。Evidence 不含 principal/documentId 列表或 raw scope。它进入 protected filter/candidate/currentness binding，但不持久化完整对象；checkpoint/audit 只保存 canonical digest、authority/permission safe version 和 diagnosticId。

同一 Invocation 若因 bug 解析两次 ALLOW scope，必须得到相同 authorityVersion/scopeDigest；不一致整体拒绝并告警。当前不以第二次 resolve 作为 retry/fallback。

### 10.4 Protected Filter AST

protected filter 使用封闭逻辑 AST，不暴露 ES DSL：

~~~java
public sealed interface DocumentProtectedFilterNode
    permits DocumentAllOf, DocumentAnyOf,
            DocumentExactTerm, DocumentAnyTerms, DocumentNoneTerms {}

public record DocumentAllOf(List<DocumentProtectedFilterNode> children)
    implements DocumentProtectedFilterNode {}
public record DocumentAnyOf(List<DocumentProtectedFilterNode> children)
    implements DocumentProtectedFilterNode {}
public record DocumentExactTerm(DocumentAclIndexField field, String value)
    implements DocumentProtectedFilterNode {}
public record DocumentAnyTerms(DocumentAclIndexField field, Set<String> values)
    implements DocumentProtectedFilterNode {}
public record DocumentNoneTerms(DocumentAclIndexField field, Set<String> values)
    implements DocumentProtectedFilterNode {}

public enum DocumentAclIndexField {
    TENANT_ID, STATUS, VISIBILITY, USER_IDS,
    DEPARTMENT_IDS, ROLE_IDS, ATTRIBUTE_KEYS, DOCUMENT_ID
}

public record DocumentProtectedFilterBinding(
    DocumentCorpusKey corpusKey,
    DocumentProtectedFilterNode root,
    String filterDigest,
    String aclEvidenceDigest,
    String profileProjectionDigest,
    ResourceLimitReference resourceLimitReference) {}
~~~

AST 位于 Spring-free `agent-adapter-api`。它没有 MatchAll、script、query_string、range、nested、raw field name、boost、minimumShouldMatch 参数或自由 Map。`DocumentAnyOf` 语义固定为至少一个 child；AllOf/AnyOf children 非空。leaf field/operator 组合由 validator 固定：STATUS/TENANT/VISIBILITY 只允许 Exact；principal/documentId 只允许 AnyTerms；DocumentNoneTerms 只允许 DOCUMENT_ID。

### 10.5 Filter 构建算法

`DocumentProtectedFilterFactory.build(scope,evidence,schemaRef)` 只按 01 schema v3 生成：

~~~text
ALL_OF
  EXACT tenantId = scope.tenantId
  EXACT status = ACTIVE
  optional ANY_TERMS documentId = OnlyDocumentIds.ids
  ANY_OF
    ALL_OF(EXACT visibility=PUBLIC)
    ALL_OF(EXACT visibility=TENANT)
    ALL_OF(EXACT visibility=USER,       ANY_TERMS userIds={subjectPrincipalId})
    optional ALL_OF(EXACT visibility=DEPARTMENT, ANY_TERMS departmentIds=scope.departmentIds)
    optional ALL_OF(EXACT visibility=ROLE,       ANY_TERMS roleIds=scope.roleIds)
    optional ALL_OF(EXACT visibility=ATTRIBUTE,  ANY_TERMS attributeKeys=scope.attributeKeys)
  optional NONE_TERMS documentId = deniedDocumentIds
~~~

PUBLIC 仍受顶层 tenantId 约束。空 principal set 对应分支完全不生成；不能把空 terms 解释为全部。Profile、domain/materialType 不编译成 chunk term：一个 physical index 只承载一个 CorpusKey，Corpus/target 由 01 request boundary 绑定；schema v3 不保存 retrievalProfile/corpusId/materialType per chunk。

`DocumentProtectedFilterCanonicalizer` 使用 `DAF-1`：enum 使用稳定名称，set 稳定排序，AllOf/AnyOf child 按 child canonical bytes 排序并去重，值执行长度/字符 canonical validation。digest 覆盖 CorpusKey、root、ACL evidence/profile/limit binding。不同 AST、evidence 或 Corpus 必须产生不同 digest；禁止 Jackson bytes、Map order、`hashCode` 或 ES JSON 作为 canonical source。

### 10.6 Compiler Security Caps

`DocumentAclCompilerLimits` 是 agent-service 与 es-query-service 都配置并在 07 readiness 中比对的 operational/security cap：

| cap | 语义 |
|---|---|
| maxDepartments/maxRoles/maxAttributes | scope principal set 最大项数 |
| maxAllowedDocumentIds/maxDeniedDocumentIds | explicit document ID set 最大项数 |
| maxAstNodes/maxAstDepth/maxTerms | canonical AST 结构/terms 上限 |
| maxCanonicalBytes/maxWireBytes | canonical/wire payload 上限 |
| maxCurrentnessCandidates | final candidate ACL object batch 上限 |

这些值不属于 `DocumentResourceLimit`，不受 caller request narrowing，也不表示授权范围。agent-service cap 必须小于或等于 authority/es-query-service 接受 cap；任何超限整体拒绝，不截断 principal/document IDs、不删除 deny、不降低过滤精度、不改用 match-all。若业务规模超过 cap，必须另行设计受控 terms-set reference/authority contract，当前不临时创建 lookup index 或 cache state。

### 10.7 Protected 与 Caller Filter 分离

04 的 `DocumentRetrievalCommand` 固定分字段携带：

~~~java
public record DocumentRetrievalCommand(
    DocumentCorpusKey corpusKey,
    List<ValidatedDocumentCallerFilter> callerFilters,
    DocumentProtectedFilterBinding protectedFilter,
    DocumentPreparedQuery preparedQuery,
    DocumentRetrievalChannels channels,
    DocumentFusionSpec fusion,
    DocumentDedupSpec dedup,
    DocumentContextSpec context) {}
~~~

`callerFilters` 已由 DocumentPlanValidator 按 Domain Metadata/Profile/02 `maxCallerFilterCount` 校验；`ValidatedDocumentCallerFilter` 与 command 中的 prepared query/channel/spec/security values 都位于 Spring-free agent-adapter-api，不能引用 ACL index field或 agent-service Profile/provider类。`protectedFilter` 必填且无 public setter/Map merge；Adapter 不接收 raw scope、ExecutionScope、JWT 或 Profile。

retrieval command 不实现 `CapabilityOperationRequest` 且不内嵌 operation context。Handler 遵守 P1 Domain Adapter SPI，调用 `DocumentRetrievableAdapter.retrieve(command, operationContext)`；Adapter 先核对 command execution/filter/evidence/limit binding 与 context，再映射 safe operation metadata。03 的 ACL authority/currentness 仍属于 capability-local ports，其 typed request继续内嵌 operation context，两类 seam 不混用。

Agent 侧 `DocumentCorpusKey` 位于 agent-adapter-api；es-query-api 使用字段/canonical规则等价的 wire DTO，由 agent-adapter-document 唯一 mapper转换并做 contract test。不得让 agent-adapter-api 依赖 es-query-api，也不新建只承载一个 record 的公共模块。

agent-adapter-document 只执行 typed-to-typed mapping：caller filter 映射为 es-query-api caller DTO，protected AST 映射为封闭 protected DTO，两个字段不合并。现有 `DocumentAclFilterFactory.merge(Map,Map)` 和 `DocumentRetrievalMapper.filterDsl()` 不属于目标设计。

es-query-service request boundary 执行：

1. 专用服务身份/scope 与 Document target guard；
2. CorpusKey→alias/schema、一次 target resolve；
3. protected DTO strict parse、DAF-1 重算、binding/digest/cap/schema field 校验；
4. caller filters 独立 strict parse，拒绝 ACL field；
5. protected AST 编译一次为 ES `bool.filter` fragment；
6. 每个 BM25/phrase/vector/context query 都以顶层 AND 复用同一 fragment 与 caller fragment；
7. 任一 channel 尝试 null/drop/recompile/mutate protected object，整个 request 拒绝。

无 protected filter 的 Document query 永远拒绝，包括无 caller filter、fallback、context neighbor、count/debug/preview；generic raw search endpoint 由 01 guard 禁止访问 Document target。

### 10.8 跨服务 Filter Contract

`agent-adapter-api` 的 logical AST 是 Agent/Adapter 内部权威；`es-query-api` 使用结构等价的 strict DTO union。`DocumentProtectedFilterRequestMapper` 是唯一 mapper，contract test 必须证明：

- 每个允许 node round-trip 后 DAF-1 canonical bytes/digest 相同；
- unknown discriminator/field/operator/value shape 拒绝；
- DTO 没有 rawJson/filterDsl/Map/extensions；
- resource/profile/ACL evidence/Corpus binding 不丢字段；
- protected 和 caller filter 在 wire contract 中仍是两个 required/optional 独立字段。

filter digest 不能替代服务认证或 ACL authority currentness。若内部 HTTP DTO 的新增/替换影响公共生成物或现有 caller，实施前按 P1_V2/06 M0 清点和授权；不得长期保留 Map 与 typed 双协议。

### 10.9 Retrieval Response Binding

es-query-service 返回的 Document response envelope 必须包含：requestCorrelation/operation safe id、DocumentCorpusKey、`DocumentTargetBindingReference`、protected filter digest、schema/content/report safe refs 和 per-channel diagnostics。`DocumentTargetBindingReference` 从 01 `ResolvedIndexTargetRef` 派生，只包含 schemaVersion/indexContentDigest/releaseAttestationRef/targetBindingDigest；不向 Provider/final output暴露 physical index 或 credential。

ES 每个 raw hit 必须能投影出 documentId/documentVersion/chunkId/chunkIndex、content/title/section/page/safeSourceUri、typed business field values、aclRef/aclVersion、channel/score 和当前 request binding；不得包含 userIds/departmentIds/roleIds/attributeKeys、embedding/queryVector、score explanation、internal index 或 arbitrary metadata。

es-query-service 的 `DocumentChannelHitBindingValidator` 在任何 RRF/dedup/context 前校验并输出内部 `BoundDocumentChannelHit`：

- raw hit 与 request Corpus、resolved target、compiled filter/profile/limit/operation binding 一致；
- target ref 与 01 sealed+attested response 匹配；
- hit status 为 ACTIVE，identity/offset/ACL ref/version/URI/field/type/count 合法；
- raw hit 没有 prohibited fields，score finite；
- context neighbor response 使用同一 target/filter binding。

04-owned es-query-service RRF/dedup/context 只能处理 `BoundDocumentChannelHit`。完成算法后，fused response 仍携带完整 envelope 与每个 hit 的 target/filter/evidence/channel-rank binding。agent-adapter-document 的 `DocumentRetrievalResponseBindingValidator` 在跨服务反序列化后再次核对 request/response Corpus、target/filter/profile/limit/operation/evidence、可见 RRF score/order、count/truncation、context 和 prohibited fields，输出 `AclBoundDocumentHit`。它不重跑 channel/RRF，也不能恢复被 ES 截断的候选集合。

两个 validator 复用同一 canonical binding 字段和 reason code：前者防止未绑定 ES hit 进入算法，后者防止跨服务传输/mapper/response 漂移进入 Agent。任一错配都使整个 retrieval contract/security failure，不丢弃单 hit 后继续排序，防止通过 count/rank/coverage 暴露异常对象存在性。

### 10.10 RRF、dedup 与 context 的安全前置

04 的 RRF/dedup/context 算法所有权不等于算法必须在 agent-service。目标唯一实现位于 es-query-service，只能对 `BoundDocumentChannelHit` 操作；Agent 侧 04 接收 Adapter 输出的最终有序 `AclBoundDocumentHit`，不保留第二 merger。dedup 合并条件至少包含相同 documentId/documentVersion/aclRef/aclVersion/Corpus/target/filter/evidence binding；任一不一致整体拒绝，不取“更宽”的 chunk。

context neighbor 查询必须重新经过同一 es-query request boundary，使用同一 Corpus、Resolved target、protected filter binding 和 caller filter；只允许基于已绑定 documentId/chunkIndex 的有界相邻读取。不能从本地 cache/raw `_source` 或无 ACL endpoint 拼接前后文。

RRF/dedup 只决定排序与选择，不改变 ACL evidence、aclRef/version、fields、URI 或文本。coverage/diagnostics 只统计通过 protected filter 且 binding 有效的 hits；不得报告被过滤/拒绝/撤权的数量、channel 或文档存在性。

### 10.12 Provider 最小投影

rerank 只能从 Safe candidate 派生 `candidateId/title/bounded snippet/optional section/fused score`；generation 只能接收 05 `EvidenceContextPackage`。两个 Provider 均不接收 `DocumentCandidateIdentity`、sourceUri、business fields 全集、target/filter/ACL evidence 或 security binding 正文。

Provider 返回的 candidateId 必须是输入子集且无重复；返回文本/score/citation id 不继承 Safe 身份。06 本地 operation metadata + 05 candidate factory 才能重新绑定 current Invocation/evidence/limits。Provider 声称“authorized”“ACL checked”或回传 filter/permission/version 一律忽略并按 prohibited field 拒绝。

### 10.13 Scope 与 Candidate Currentness

`DocumentAclCurrentnessPort` 提供两个 typed operation；operation context 必须内嵌于 request，禁止以 `(evidence, context)` 两参数传入后发生 Invocation/limit/deadline 错配：

~~~java
public interface DocumentAclCurrentnessPort {
    DocumentAclCurrentnessDecision verifyScope(
        DocumentAclScopeCurrentnessRequest request);

    DocumentAclCurrentnessDecision verifyCandidates(
        DocumentAclCandidateCurrentnessRequest request);
}

public record DocumentAclScopeCurrentnessRequest(
    DocumentAclExecutionEvidence evidence,
    CapabilityOperationContext operationContext)
    implements CapabilityOperationRequest {}

public record DocumentAclCandidateCurrentnessRequest(
    DocumentAclExecutionEvidence evidence,
    List<DocumentAclObjectRef> candidates,
    String candidateSetDigest,
    CapabilityOperationContext operationContext)
    implements CapabilityOperationRequest {}
~~~

执行顺序：scope resolve/evidence/filter 完成后、调用 retrieval Adapter 前执行 `verifyScope`；Result Security 紧邻序列化前对最终候选去重后的 bounded ACL object refs 执行 `verifyCandidates`。final batch 数不超过 `min(maxCurrentnessCandidates, effective.maxEvidenceCount/maxReturnedDocuments 对应上限)`；不允许为超限而截断候选并继续。

`DocumentAclCurrentnessDecision` 的 outcome 为 `ALLOW/DENY/FAILURE`；DENY 表示 current authority 的业务拒绝，FAILURE 表示 authority unavailable/invalid/partial/late 等不能形成授权结论，两者都 fail closed但内部 reasonCode/metrics 分开。currentness 必须确认 permissionVersion、authorityVersion、scope/evidence binding 未变化且每个 aclRef/aclVersion 仍 current/allowed。任何版本变化、candidate denied/revoked、unknown ref、过期、timeout/5xx/late/cancel/partial response 均整体拒绝；不重新检索、不重做 Plan、不静默删除个别 candidate、不返回 partial coverage。

当前不跨 Invocation 缓存 ALLOW scope/currentness/candidate decision，也不使用 stale-while-revalidate。未来正向缓存必须先由 L1/ADR 定义撤权窗口、紧急绕过、version push/invalidations 和一致性证明；本版本不预留可启用的 allow-cache 配置。DENY 缓存也不作为正确性依赖。

### 10.14 DocumentRevocationGuard 与 07 边界

`DocumentRevocationGuard.evaluate(FinalDocumentCurrentnessRequest)` 是 03 唯一 external final decision 算法。04 Handler 在 evidence/citation/fallback 后、最终候选集合已经固定且尚未返回 Core 时调用；request 内嵌由当前 `ExecutionContext` 创建的 operation context，limit reference 只从该 context 派生并与所有 candidate/evidence 核对。算法组合：

1. candidate security bindings 与同一 ACL evidence/target/profile/limit 的完整性校验；
2. `DocumentAclCurrentnessPort.verifyCandidates` current decision；
3. P2_V3/07 `DocumentEmergencyControlReadPort.readCurrent(targets,deadline)` 返回的 current governance view；
4. deadline/cancellation 与 operation binding。

07 state target 至少支持 CorpusKey、profile safe ref、target binding digest 和相关 Provider safe ref；03 只读取并判断，不创建/更新/持久化 state。07 只管理 state/change/audit/SLA，不复制 Guard 规则。`DocumentRevocationGuard` 不读取 `AgentProperties.blocklist`、indexAlias 或 local latest config。

~~~java
public record DocumentFinalCurrentnessDecision(
    DocumentCurrentnessOutcome outcome,
    String invocationId,
    String operationId,
    String permissionVersion,
    String candidateSetDigest,
    String authorizationBindingDigest,
    ResourceLimitReference resourceLimitReference,
    String aclDecisionVersion,
    String emergencyViewVersion,
    Instant checkedAt,
    Instant validUntil,
    String decisionDigest,
    DocumentSecurityReasonCode reasonCode) {}
~~~

authority/emergency view 不可用、目标被 block、candidate binding 不一致或 permission/ACL version 变化均 DENY。`validUntil=min(absoluteDeadline, checkedAt+finalDecisionMaxAge)`；maxAge 是很短的本地安全 cap，只能提前过期。ALLOW decision 仅对当前 exact candidate set、Invocation/authorization/limit binding 和紧邻的 Result Security 调用有效，不跨 Invocation 缓存。

`DocumentFinalCurrentnessDecisionVerifier` 由 Document Result projector 本地调用，核对 ALLOW、candidateSetDigest、invocation/permission/authorization/limit binding、checkedAt/validUntil 和 decisionDigest；不访问网络、不读取 07 state、不创建新的 operation context。这样保持 P1 `ResultSecurityPort.secure(candidate, outputContract, scope, limits)` 通用接口不变。

candidate set canonical form 使用 `DCS-1`，覆盖稳定输出顺序中的 candidateId、每个 `DocumentCandidateSecurityBinding`、最终 evidence/citation reference IDs 和 output ContractRef，不覆盖将由 Result Security 做值级 Mask/字符裁剪的文本或 field value。Projector 可以在不改变 candidate/evidence/citation identity set 的前提下做字段 Mask/值裁剪；增加、删除、替换或重排 identity set 会改变 digest 并整体拒绝。

系统不宣称跨独立 authority/DB/HTTP 的线性化强事务；通过“Handler 外部 final check→同步返回 candidate→Projector 本地短效复核→serialization”无异步 gap、全失败封闭和 07 撤权 SLA/告警，控制不可消除的网络时序窗口。

### 10.15 Result Security 接入

`DocumentResultSecurityProjector` 在执行 output ContractRef、field/mask、citation、URI、text/count/bytes 检查前后都不得丢失 candidate security binding。Handler 必须在所有将要输出的 evidence/citation 集合确定后调用一次 external Guard，并把 ALLOW decision 作为 Document candidate security evidence；Projector 在序列化前调用 `DocumentFinalCurrentnessDecisionVerifier` 做本地复核。

Projector 若在字段/Mask/citation 投影中改变了 candidate/evidence/citation set，必须以最终输出集合重算 candidateSetDigest 并与 decision 一致；若不一致整体拒绝，不得在 Projector 内发起没有 deadline/cancellation 的补查。推荐 Handler 传入已按 output policy 确定的候选集合，Projector 只做不增加元素的裁剪；任何裁剪导致 digest 变化仍需拒绝，防止 decision 与输出对象错配。

若 final currentness DENY，整个 Document result 返回 P1 受控 `PERMISSION_CHANGED/ACCESS_REVOKED` 安全错误模板；用户不可区分 domain 不存在、document 被过滤、ACL version 变化或 emergency block。失败响应不含 partial answer/evidence/citation/coverage/query parameters 或 candidate count。

## 13. 状态流转设计

~~~text
P1_CURRENT_AUTHORIZED
  -> ACL_SCOPE_RESOLVED
  -> ACL_EVIDENCE_BOUND
  -> PROTECTED_FILTER_BUILT
  -> SCOPE_CURRENT_VERIFIED
  -> RETRIEVAL_FILTER_ENFORCED
  -> RESPONSE_BOUND

  -> FINAL_CURRENTNESS_DECISION_BOUND
  -> RESULT_SECURITY_DECISION_REVERIFIED
  -> RESULT_SECURITY_ALLOWED
~~~

这些是 trace stage，不增加 Invocation 状态、数据库 status 或消息事件。任一步 DENY/FAILURE 进入 P1 Lifecycle 的统一失败终结；不得从失败 stage 回退到无 ACL 检索、fallback channel、旧 cache 或 local blocklist。

## 14. 幂等、事务与一致性设计

- 同一 exact scope/evidence/schema 生成相同 DAE-1/DAF-1 digest；集合重排不改变，任一 principal/document/版本/binding 变化必须改变；
- filter AST immutable；Adapter mapper/ES compiler 不原地修改；所有 channel 复用同一 compiled object；
- authority resolve/currentness 每 operation 最多一次 outbound attempt，无 hidden retry；operationId 只作幂等诊断，不授权 replay；
- one request one Corpus/target/filter；alias 在请求中只解析一次，响应绑定该 target；
- currentness response 必须覆盖完整 candidate ACL object set；partial/duplicate/unknown/missing item 整体拒绝；
- P1/ACL/07 是不同权威系统，不宣称分布式事务；Execution start 与 final guard 两次 fail-closed current check 收敛；
- final ALLOW 只对当前 candidate set/Invocation/authorization/limit 与 `validUntil` 内同步 serialization 有效，不能复用于下一次响应；
- candidate 不跨 Invocation 缓存，filter/evidence 不写 Context。

## 15. 权限、风控与审计设计

- ACL authority service identity、es-query Document search identity、07 governance read identity 使用不同最小 scope/credential；Provider credential 不复用；
- caller/Runtime 不提供 subject、permission evidence、Profile/limit binding、tenant/principal 或 protected filter；
- es-query Document endpoint 只接受专用 service scope，generic endpoint/credential 不能读取 Document target；
- protected AST 只允许 schema v3 ACL fields/closed operators，caller filter 明确禁止这些字段；
- scope oversized/unknown、filter compile mismatch、response prohibited field、candidate binding mismatch、currentness unavailable 全部 fail closed；
- error reason 内部区分 `ACL_DENIED/SCOPE_INVALID/FILTER_TOO_LARGE/BINDING_MISMATCH/PERMISSION_CHANGED/OBJECT_REVOKED/EMERGENCY_BLOCKED/CURRENTNESS_UNAVAILABLE`，外部统一安全模板；
- DENY 不返回 partial result，也不在 timing/coverage/metrics 中暴露被过滤对象数量；
- production wiring 不允许 `MockDocumentAclScopeController`、allow-all scope、local principal defaults 或 runtime-disabled fallback。

## 16. 性能与容量设计

- authority scope/currentness 每 Invocation 各最多一次 resolve、一次 pre-retrieval check、一次 final bounded batch check；不逐 candidate 发 N 次请求；scope evidence TTL 独立受 `maxAuthorityEvidenceTtl` 限制；
- protected AST/canonical/filter compile 对有界节点/terms 线性；ES fragment 编译一次并在通道复用；
- response binding/projection 对有界 hits 线性；RRF/dedup 复杂度归 04；
- currentness batch 数受 compiler cap 与 Effective evidence/returned document 上限双重限制；
- 当前不缓存 ALLOW scope/candidate，避免撤权窗口和高基数缓存污染；
- metrics 标签不使用 subject/document/aclRef/physicalIndex/filter digest 全值；
- authority/es-query wire body、集合、字符串和嵌套深度均有 hard cap，超限拒绝而非分页拼接权限。

## 17. 兼容性与 Multi-Agent 扩展设计

系统未投产，不保留旧 `DocumentAclScope` principal DTO、`Map<String,Object>` filter、`DocumentAclFilterFactory.merge`、ACL request profile/indexAlias 字段、main-source mock controller、AgentProperties local blocklist 或 positive cache 兼容层。P1_V2/06 Release Unit 必须同时切换 authority DTO、Adapter request、es-query DTO/service enforcement、candidate pipeline 与 Result Security。

Future Multi-Agent：

- Owner/subject/delegation/run/task evidence 只由 P1 形成新的 current execution/delegation binding，再输入同一 `DocumentAclScopeRequest`；
- protected AST、Corpus/target/filter binding、Safe candidate 和 final currentness 算法不增加 parent/child agent 特例；
- child Agent 不能转发 parent raw scope/filter；Coordinator 只能传 P1 sealed delegation/current evidence，执行 Agent 重新解析自己的 Document ACL scope；
- index ACL schema 不增加 Run/Task/Agent owner 字段；文档访问仍由 tenant/principal/object authority 判断。

未来大规模 ACL 若采用 terms-set reference，必须新增封闭 ContractRef、生命周期/currentness/tenant 隔离/cleanup/审计设计；不得把 AST values 换成自由 lookup URL/index/doc ID。
