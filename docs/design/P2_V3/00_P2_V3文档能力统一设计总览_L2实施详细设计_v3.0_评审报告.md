## 4. S0 阻断问题

复审后未发现遗留 S0。关闭 5 项：

| 序号 | 位置 | 问题 | 风险 | 修复结果 |
|---:|---|---|---|---|
| 1 | 原总体时序 | Effective Document limits 在 Validator/Handler 后才形成 | Runtime Raw Plan、Validator 与 Handler 可能消费不同限额，破坏 P1 Authorization Snapshot 冻结语义 | 改为 Route 后、Runtime Plan 前由 P1 唯一 resolver 冻结，Execution 只允许同值或收紧 |
| 2 | 原 Handler 边界 | Handler 读取当前 Permission/Profile/config | 在 Core recheck 外形成第二授权事实源，撤权与资源收紧不可证明 | Handler 只消费 ValidatedDocumentPlan、ExecutionContext 和 Document ACL 边界结果 |
| 3 | 第二轮 Execution Context | ResolvedDocumentExecutionConfig 被放入 ExecutionValidationContext/ExecutionContext | 反向扩张 P1 Core seam，并与 P1_V2/04 的 Validator 最小输入冲突 | 改为 package-private DocumentRawPlanAssembler 组装 server-origin Raw Plan，Validator 输出最小 Validated Plan；不新增 Context 字段 |
| 4 | 原 Provider→candidate | Provider/06 可直接返回可信 DocumentGeneratedTextCandidate | Provider 可伪造 owner、Invocation、evidence、output ContractRef 或 limit binding | 06 只返回 typed untrusted payload；05 使用本地可信事实构造 candidate security binding |
| 5 | 原 DocumentResourceLimit | maxProviderAttempts 和 stage timeout 混入授权 resource limit | 部署超时/重试配置可改变授权摘要，或被误当成可放宽的业务额度 | Document limit 只保留业务资源维度；deadline、operational cap、attempt policy 独立且 attempts 固定可证明为 0/1 |

## 5. S1 严重问题

复审后未发现遗留 S1。关闭 9 项：

| 序号 | 位置 | 问题 | 风险 | 修复结果 |
|---:|---|---|---|---|
| 1 | 原 04/05/06 关系 | orchestration、generation、candidate/result security 互相调用且所有权循环 | 实施时会复制编排或让 Provider 层决定 fallback/security | 04 成为唯一 Handler sequence；05 冻结 evidence/generation boundary/security；06 只实现 typed port/client |
| 2 | 原 01/07 alias | 两个专题都拥有 alias switch/rollback 状态 | ES 实际状态和本地状态可能形成双权威 | 01 只提供 CAS/read-current 技术原语；07 决策、审计和 reconciliation |
| 3 | 原 03/07 撤权 | 两个专题都定义运行时撤权规则 | Handler/Result Security 可能读取不同 blocklist/currentness | 03 唯一实现 Invocation guard；07 只管理外部 emergency control 与发布治理 |
| 4 | 原 alias freeze | 只冻结 alias 字符串，未绑定同一次 hybrid request 的 physical target | alias 并发切换时各 channel 可查询不同索引 | es-query-service 在请求边界解析一次 ResolvedIndexTargetRef，所有 channel 共用同一 physical target |
| 5 | 第二轮 01/02 边界 | Document Profile 同时保存 readAlias/schemaVersion | Profile 与 corpus/index 生命周期形成双配置和双 currentness | Profile 只携带 DocumentCorpusKey；01 的 immutable corpus catalog 唯一映射 alias/schema |
| 6 | 第二轮 05/06 合约 | 05 的 EvidenceContextPackage 与 06 的 generation payload 互相依赖 | 产生概念循环并诱导跨包重复 DTO | generation input/untrusted payload 的 provider-independent contract 归 05，06 实现 port/client/transport mapping |
| 7 | 原执行阶段 | Document stage 被设计为持久化状态或事件驱动状态机 | 与 P1 Invocation Lifecycle 竞争终态和恢复语义 | stage 仅作为 trace/span；不落库、不发事件、不决定业务成功 |
| 8 | 原实现/验收 | 路径、删除扫描和总体退出门禁不完整 | 总览无法约束 01～07 闭合，旧 Runtime/预算/编排可能残留 | 补齐模块落点、最小命令、静态扫描和 D0～D9 门禁 |
| 9 | 第三轮 server-origin/currentness | 仅靠 server-origin 标记，且 Document Profile 可独立切 latest | 内部对象可伪造，执行期需要新增 Profile currentness 查询 | 私有构造 + Invocation/correlation/registration/AgentProfileRef/limit/digest binding；Document Profile 作为 exact Agent Profile 的原子子版本 |
