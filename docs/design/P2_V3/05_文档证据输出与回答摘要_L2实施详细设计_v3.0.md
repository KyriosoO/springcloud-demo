## 3. 文档状态说明

本文处于 In Review，不授权直接修改 `agent-api` 公共 response/Context contract、`agent-adapter-api` generation contract、Provider HTTP、配置中心、生产数据或发布状态。本文只冻结 Document capability 在 04 ordered safe candidate 与 P1 Result Security 之间的目标实现。

本文是 P2_V3 中 Document evidence selection、generation provider-independent boundary、citation binding、extractive fallback/refuse、public result draft 和 Result Security 的唯一专题规范。旧 P2/P2_V2 仅保留 provenance；其中的 Adapter evidence 直接进 Provider、public DTO 内 `@JsonIgnore` candidate、Projector 外部 revocation/fallback、散落 `AgentProperties` 预算和可公开 invalid citation IDs 不再用于补充实现。

## 4. 背景与目标

当前实现已有 packer、pre-security filter、generation client、citation verifier、fallback composer 和 Result projector，但边界仍不可证明：

- `DocumentEvidenceContextPacker` 按 RRF/score 再排序，覆盖 04 已冻结的 rerank/final order；
- packer 接收 `AdapterDocumentEvidence`，可读 content/context/free metadata，并把 raw chunkId/documentId 作为 citationId；
- evidence item 使用 `Map<String,Object>` metadata，package 保存 query text但不绑定 authorization/target/filter/profile/limit/output contract；
- pre-security filter 在 scope 为 null 时默认放行，且与 final Result Security 分别实现字段过滤；
- citation verifier只检查 Provider 声明列表是 package 子集，不检查最终可见文本中的 marker、单位覆盖、重复或 operation字段互斥；
- `AgentDocumentResult` 同时保存 public text和 `@JsonIgnore` candidate text，内部对象可能被 mapper/log/debug 意外暴露；
- `DocumentResultSecurityProjector` 读取 `AgentProperties`、执行外部 revocation、决定 fallback并截断 generated text，侵入 P1 通用 seam且可能截断引用；
- public parameters 暴露 retrievalProfile/profileVersion/indexAlias，citation verification 暴露 invalid Provider IDs/reason；
- Context 保存 query/filter/citation IDs，候选/文档引用可跨 Invocation 扩散；
- generation public status 混入 PACKED/GENERATING/EMBEDDING_FAILED/RETRIEVAL_PARTIAL 等内部阶段或其他专题状态。

目标是形成一条不可绕过、不可放大、可实现和可测试的单链：04 提供 ordered `SafeDocumentCandidate`；05 在同一 ExecutionScope/limit/output contract 下形成最小 evidence；06 只接收 provider-safe projection并返回 untrusted payload；05 本地构造 trusted generated candidate、验证 citation、选择 deterministic fallback/refuse并形成 final result draft；03 对 exact evidence/citation set做 final currentness；P1 Result Security只做本地 decision/contract/field/mask/limit/bytes投影，最终公共 DTO 中不存在内部 candidate字段。

## 5. 设计范围

### 5.1 范围内

- SEARCH/ANSWER/SUMMARIZE 的 evidence/output policy；
- ordered safe candidate 到 selected evidence/citation 的确定性投影；

- `EvidenceContextPackage`、ECP-1 canonical digest和provider-safe input projection；
- generation request/untrusted payload 的 provider-independent contract所有权；
- trusted `DocumentGeneratedTextCandidateFactory` 与 operation/limit/evidence binding；
- inline citation语法/归属/单位覆盖校验和Grounding状态语义；
- coverage、extractive fallback、refuse和最终 result draft；
- 03 final currentness handoff与P1 local Result Security接入；
- public/internal DTO隔离、query parameters、Context candidate、audit/metrics；
- evidence/context/citation/generated/summary/result bytes预算和测试门禁。

### 5.2 范围外

- retrieval/channel/RRF/dedup/context/rerank算法，归04；
- ACL/filter/Safe candidate/final currentness算法，归03；
- Profile/feature/DocumentResourceLimit定义与求交，归02/P1；
- Provider endpoint/model/credential/HTTP/timeout/attempt/response parser，归06；
- claim事实真值、Gold factuality/quality/capacity、production enable/rollback，归07；
- Multi Agent聚合、跨child evidence共享、全局memory或跨Invocation candidate cache。

## 6. 上级文档约束

1. Provider输出只能是 untrusted payload，不能设置可信 owner、authorization、limit、ContractRef或evidence binding。
2. `GeneratedTextCandidate` 必须由Java使用当前 Invocation、output ContractRef、Evidence package、operation metadata和同一 ResourceLimitReference本地构造。
3. Handler只编排；最终公共结果必须经过P1 `ResultSecurityPort.secure(candidate,outputContract,scope,limits)`。
4. Result Security不得执行外部I/O；03外部 final currentness已在Handler候选集合固定后完成，Projector只本地复核短效decision。
5. Context candidate必须经过P1 approval/CAS/encryption；不保存evidence/candidate/final长文本、Provider payload或ACL正文。
6. 所有字符、数量、字节上限来自同一`DocumentResourceLimit`；不得回读`AgentProperties`或Provider配置作为业务额度。
7. 当前单智能体实现；未来Multi Agent只复用各child独立result/evidence contract，不在05预建共享包或跨授权聚合。

## 9. 总体设计

### 9.1 唯一执行序列

~~~text
04 ordered SafeDocumentCandidate + diagnostics + ValidatedDocumentPlan/OutputIntent
  -> DocumentEvidenceVisibilityProjector(current ExecutionScope/public output Contract/limits)
  -> DocumentEvidenceSelector (stable public-visible prefix/subset, no score)
       -> SEARCH: DocumentSearchResultDraft
       -> ANSWER/SUMMARIZE:
             06 DocumentProviderOutboundPolicyDecisionFactory(current scope, DOCUMENT_GENERATION)
             DocumentGenerationEvidenceProjector(decision, all-or-none)
             EvidenceContextPackageFactory -> ECP-1
             DocumentGenerationInputProjector(ECP actual outbound text)
             06 DocumentProviderOperationRequestBinder(policy/input digest)
             06 DocumentGenerationPort.generate(typed request with policy ref + operation context)
            -> CapabilityOperationOutcome<untrusted payload>
            -> DocumentGeneratedTextCandidateFactory (trusted local binding)
            -> DocumentCitationVerifier
            -> generated draft | extractive fallback draft | refusal draft
  -> DocumentCoverageFactory + DocumentResultDraftFactory/SizeGuard
  -> exact evidence/citation/output identity set fixed
  -> 03 DocumentRevocationGuard external final currentness
  -> DocumentResultCandidate(draft + short-lived decision)
  -> P1 DocumentResultSecurityProjector
       local decision verifier
       ContractRef/scope/field/mask/limit/citation/bytes verification
       public DocumentAgentResultPayload
  -> P1 Context approval + lifecycle commit
~~~

### 9.2 所有权分层

| 层 | 权威对象 | 责任 |
|---|---|---|
| 04 | ordered Safe candidates | retrieval排序和安全候选输入 |
| 05 | public-visible selected evidence/generation evidence/ECP/input-payload contract/candidate/citation/fallback/result draft | evidence到final draft的业务与安全算法 |
| 06 | generation port/client/transport metadata | 一次Provider operation，不决定fallback |
| 03 | final candidate-set currentness decision | ACL对象和emergency view当前性 |
| P1 Result Security | secured public result | 最终field/mask/limit/bytes/decision本地投影 |

### 9.3 Multi Agent演进 seam

`EvidenceContextPackage`、generated candidate和result draft都绑定单一child Invocation、Authorization、Corpus、target/filter/evidence和ResourceLimitReference。未来上层若合并多个child输出，必须建立新的aggregate evidence contract和总预算，并重新执行aggregate Result Security；不得把不同child的ECP item直接拼接、复用citationId或在05内共享Provider package。当前不增加parentAgentId、workerId、sharedEvidenceStore或cross-agent cache字段。

## 10. 详细功能设计

### 10.1 Operation policy 与 output intent

| operation | selected evidence | Provider generation | public内容 | 无evidence |
|---|---|---|---|---|
| SEARCH | 可为空 | 永不调用 | ordered hits/citations/coverage/query parameters | 安全空结果 |
| ANSWER | generated/fallback前至少1条 | 按generation policy/output intent | answer + citations，或仅citations/refuse状态 | SKIPPED + NO_EVIDENCE，无answer |
| SUMMARIZE | `ValidatedSummaryScope`必填且至少1条 | 按generation policy/output intent | summaryText/bullets + citations，或仅citations/refuse状态 | SKIPPED + NO_EVIDENCE，无summary |

`DocumentOutputIntent` 来自ValidatedPlan，只含operation、validated summary scope、generation failure policy、public response shape和output ContractRef。它不能含Provider/model/prompt/timeout/alias或散预算。SUMMARIZE scope中的document IDs只能来自caller已提交并经Validator canonicalized的集合；04已将其作为caller filter与protected filter顶层AND。05再次证明所有selected evidence都在scope内，但不重查索引或把scope当授权。

feature/failure优先级：

1. generation policy REQUIRED：有evidence时Provider disabled/failure/invalid/late/citation invalid均整体执行失败，不走extractive fallback；
2. OPTIONAL：按validated failure policy选择`FALLBACK_EXTRACTIVE`或`REFUSE`，不调用备用Provider；
3. DISABLED：不调用Provider；只有failure policy显式允许时构造extractive result，否则refuse；
4. 无evidence：任何policy都不调用Provider，返回NO_EVIDENCE安全结果，不把基础设施状态伪装成成功generated answer。

### 10.2 Trusted input 与同源 binding

`DocumentEvidencePipelineRequest` 由Handler package-private factory构造：

~~~java
record DocumentEvidencePipelineRequest(
    ValidatedDocumentPlan plan,
    List<SafeDocumentCandidate> orderedCandidates,
    DocumentAclExecutionEvidence aclEvidence,
    DocumentTargetBindingReference targetBinding,
    ContractRef outputContract,
    ExecutionScope executionScope,
    DocumentResourceLimit limits,
    ResourceLimitReference limitReference,
    DocumentRetrievalDiagnostics diagnostics) {}
~~~

factory验证capability/operation/domain/Corpus/profile projection、authorization、ACL/filter/target、output ContractRef、limit reference和Invocation/correlation/registration全部一致；candidate list非null、无重复candidateId、保持04最终顺序且数量在retrieval limit内。scope/null、binding缺失、candidate security mismatch或unknown output contract在任何Provider调用前拒绝。

request仅在agent-service内存存在，不进入adapter-api、Runtime、HTTP、Context或日志。`DocumentResourceLimit` typed value不写入ECP/public DTO；只保存安全reference/digest binding。

### 10.3 Public visibility 与 Provider outbound 分层投影

`SafeDocumentCandidate` 表示ACL/target/filter安全，但不自动表示可公共返回，也不自动表示可发送给Provider。两个目的的规则必须分层，不得共用一个“Provider eligible”结果。

`DocumentEvidenceVisibilityProjector` 先使用exact ExecutionScope、public output ContractRef、02 returnable fields和P1 `ResultValueMaskingSupport`的同一Java权威Mask规则形成ordered `VisibleDocumentEvidence`：

- domain/field不允许、required public text field不可见、unknown Mask/URI或scope缺失整体拒绝，不能null scope默认放行；
- title/section/page/sourceUri/business fields按public contract投影并执行值级Mask；sourceUri只允许受控scheme/host/path，移除userinfo/query/fragment/token；
- anchor snippet和context segments只来自03 Safe text window，不重新读取content/raw `_source`；
- 保持candidate顺序和identity sidecar；public文本经规则后为空时排除，只记录closed internal reason，不对外暴露identity/过滤count。

ANSWER/SUMMARIZE在selection之后，Handler先调用06共享且无I/O的`DocumentProviderOutboundPolicyDecisionFactory.create(DOCUMENT_GENERATION,current ExecutionScope,selected Corpus,generation feature policy,selected field view)`。该factory是四类Document Provider的唯一policy/permission/purpose解释器；只消费ExecutionScope中经Planning/Authorization与Execution recheck冻结的field permission、Mask和security-classification refs，不读`AgentProperties`、Provider配置或07状态正文。05不得复制一套generation-only policy evaluator。

`DocumentGenerationEvidenceProjector`只负责把上述decision应用到整个ordered selection，形成唯一内部`GenerationEvidencePackageItem`列表：

- Provider-facing value只含同citationId、允许title/section/page和实际出站text；内部`GenerationEvidencePackageItem`另保留candidate identity/security sidecar供ECP/03绑定，但`DocumentGenerationInputProjector`不得把sidecar映射到adapter-api input。Provider输入不含URI、query、document/chunk identity、ACL refs/principals、security binding、Corpus target、profile/limit、scores/ranks/vector或free metadata；
- 每个item的citationId、顺序和identity sidecar与selected evidence一一绑定；Provider投影可进一步mask文本，但不得重排、替换、静默丢项或重新分配citation ID；
- 按实际outbound title/section/page/text重新计算字符使用量并证明不超过同一`maxContextChars/maxEvidenceChars/maxSnippetChars`交集；Mask替换造成文本增长时不得沿用投影前计数；
- 任一selected item不允许发往Provider、投影后空或policy/binding不可证明时，整个generation projection返回typed `NOT_PROVIDER_ELIGIBLE`，由10.11按REQUIRED/OPTIONAL路由；不用Provider子集生成与public citations不一致的答案；
- 06 decision factory/canonicalizer将固定用途、current policy/permission evidence和允许field/mask/classification refs形成decision digest；05再把实际应用的selected identity/input digest绑定为`providerOutboundPolicyDigest`。它进入ECP但不替代ExecutionScope授权。unknown classification、purpose规则缺失、scope evidence过期或无法证明只收紧均在任何port调用前fail closed；
- SEARCH永不执行Provider projection；OPTIONAL/DISABLED的extractive fallback使用public-visible selected evidence，不因Provider不可用而丢失本可安全返回的证据。

两个projector复用P1 Mask权威实现，但都不是最终Result Security。public visibility负责返回面可见性，generation projection负责Provider outbound data minimization，P1 Projector在返回前独立复核public result；三者不得各自定义Mask enum或读取散配置。

### 10.4 Evidence selection 算法

输入为ordered public `VisibleDocumentEvidence`。算法按输入顺序单次遍历，不读取RRF/rerank score：

1. 上限`itemCap=min(maxEvidenceCount,maxCitationCount)`；任一为0时ANSWER/SUMMARIZE无法形成package，SEARCH返回空evidence；
2. candidateId/security binding重复或同document/version但ACL/target/filter binding不一致整体拒绝；
3. 每个item的anchor snippet在Unicode code point边界截至`maxSnippetChars`；优先在不超过上限的最后一个完整句末截断，没有安全边界则按code point截断并标记；
4. 所有operation的selected evidence text累计不超过`maxEvidenceChars`；`maxContextChars`只在Validated Plan的generation policy为REQUIRED/OPTIONAL时约束将进入Provider package的title/section/page/text总字符，且与`maxEvidenceChars`同时满足，不是两份可相加预算；
5. SEARCH和generation policy DISABLED不构建Provider package，因而不消费`maxContextChars`；该dimension为0表示禁止generation context，不得据此清空本可公开的SEARCH evidence或本地extractive fallback。04的context expansion仍按0语义禁用；05不得重新扩展或重置额度；
6. distinct documents不超过`maxReturnedDocuments`，同document chunks不超过`maxChunksPerDocument`；正常情况下04已满足，05仍作防御复核；
7. item加入后分配selection-local opaque `citationId="C" + positiveDecimalOrdinal`，按selected顺序从`C1`开始，不允许前导零；序号用checked positive int并受已有count/char预算限制，不引入固定4位或9999隐含上限；不使用documentId/chunkId/hash前缀，避免Provider/public引用泄露内部identity；
8. 达到任一count/char/byte预估上限后停止选择后续item并标记`truncated=true`；不跳过中间高耗item去选择更后项，避免预算变化导致非前缀顺序漂移。

SEARCH public citations和ANSWER/SUMMARIZE的public/fallback citations使用同一public-visible selection结果。generation projection只可以all-or-none方式为该selection生成同序、同citationId的Provider文本；不得另选Provider子集或为public输出重新selection。

### 10.8 Citation语法、归属和单位覆盖

Provider可见citation语法固定为`[C1]`、`[C2]`……；lexical parser只接受`\[C[1-9][0-9]{0,9}\]`形式并用checked positive-int解析，溢出拒绝；semantic verifier再要求ID属于package实际分配集。不接受前导零、`citation:`别名、自由label、URL、documentId、嵌套Markdown链接或宽松trim猜测。

`DocumentCitationVerifier`执行：

1. payload citedIds与可见文本marker集合必须完全相等；不能有未使用binding或未声明marker；
2. 所有ID属于ECP、无重复、顺序按文本首次出现；
3. ANSWER每个非空paragraph至少一个合法marker；
4. SUMMARIZE的summaryText每个非空paragraph和每个bullet分别至少一个marker；
5. marker必须完整落在最终单位末尾或句末允许位置，不能在word/URI/code/HTML中；
6. public citations只由实际marker引用的selected evidence构造；当前policy要求完全相等，因此不静默删除unused evidence；
7. 任一非法/缺失marker使generated candidate UNVERIFIED并按10.11路由，不删除“未引用句”后继续输出。

`GroundingStatus.VERIFIED` 仅表示上述引用语法、归属和可见单位覆盖闭合，不证明claim事实正确、证据蕴含或回答完整；07的Gold/factuality gate单独评价。`PARTIAL` 只表示caller-known SUMMARIZE scope因安全可见证据/预算截断而覆盖不全，但所有可见文本单位仍必须citation-bound；`UNVERIFIED` candidate正文永不公开；`NO_EVIDENCE`表示没有可见evidence。

### 10.11 Generated、fallback与refuse路由

| 条件 | REQUIRED | OPTIONAL | DISABLED |
|---|---|---|---|
| 无evidence | NO_EVIDENCE安全结果 | 同左 | 同左 |
| generation SUCCEEDED + citation VERIFIED | generated draft | generated draft | 不调用 |
| Provider projection不适用/port disabled/failed/late/invalid payload | 整体执行失败 | 按intent fallback/refuse | 不执行projection/port，按intent fallback/refuse |
| citation invalid/UNVERIFIED | 整体执行失败 | 按intent fallback/refuse | 不适用 |

### 10.12 Deterministic extractive fallback

`DocumentExtractiveFallbackComposer` 只使用selected evidence，不调用Provider、不读取query/全文/config：

- ANSWER：按evidence顺序输出若干完整anchor snippet，每段末尾固定`[citationId]`；
- SUMMARIZE：按document首次出现顺序生成bullets，每bullet来自该document首个selected snippet并带citation；可选summaryText只是bullets按顺序连接，不做语义改写；
- 每个可见paragraph/bullet都有citation，使用与10.8相同verifier；
- `maxGeneratedChars/maxSummaryChars/maxSummaryBullets/maxCitationCount/maxResultBytes`共同限制；composer在加入下一完整单位前检查，不能截断单位/citation；
- 无法加入至少一个完整单位时返回REFUSE；
- 相同selected evidence/limits/operation得到字节级相同fallback。

fallback generationStatus=FALLBACK；citation-bound成功时groundingStatus=VERIFIED或按caller-known summary coverage为PARTIAL。fallback不是“生成事实”，public/API说明必须标识为extractive，不与Provider SUCCEEDED混淆。

### 10.14 Document Result Security

`DocumentResultSecurityProjector` 实现P1 registry选择的Document output ContractRef projector，输入`DocumentResultCandidate`：

1. `DocumentFinalCurrentnessDecisionVerifier` 本地验证ALLOW、freshness、Invocation/permission/authorization/limit/candidate set binding；不访问网络/07/ACL authority；

### 10.16 Truncation、字符与最终字节预算

预算按顺序单调消费：

1. 04限制retrieval candidates/context window；
2. 05 provider projection执行单snippet `maxSnippetChars`；
3. evidence selection对全部operation执行`maxEvidenceCount/maxEvidenceChars/maxCitationCount`；仅REQUIRED/OPTIONAL generation再同时执行`maxContextChars`，SEARCH/DISABLED不消费该generation-only dimension；
4. Provider payload严格验证`maxGeneratedChars`或`maxSummaryChars/maxSummaryBullets`，超限invalid，不截断；
5. fallback逐完整单位加入并在加入前检查相同output limits；
6. `DocumentResultSizeGuard`使用与public projector相同JSON schema/ObjectMapper对draft public projection做UTF-8精确size precheck；
7. SEARCH可从尾部成对移除hit/citation并重算coverage直到满足`maxResultBytes`；ANSWER/SUMMARIZE若generated文本引用将被移除evidence，generated draft失效，OPTIONAL改走重新构造的fallback/refuse，REQUIRED失败；
8. 03 final currentness只对最终size-stable identity set执行；P1 Projector再次exact验证，不能在Guard后删identity。

所有字符计数按Unicode code point；字节按最终UTF-8 JSON。checked arithmetic用于count×chars/序列化预估；0语义遵守02，不能解释为unlimited。

### 10.17 Context write

05只形成P1 `ContextWriteCandidate`，由Context approval验证owner/type/scope/limits/TTL并加密持久化。目标`DocumentCapabilityContextPayload`最多保存：operation、domain、materialType、经当前field/mask规则批准的用户query/typed filters、actual topK和summaryScope safe view，用于后续重新Planning/Authorization；不保存profile/alias、citation/document/candidate IDs、coverage digest、evidence/package/provider/final text、ACL/target/limit binding或异常reason。

后续Invocation读取Context后仍必须重新Route/Plan/authorize/profile select/ACL/retrieval，不得把Context当可复用evidence或授权。Document continuation candidate是可选输出：05在提交approval前可因query/filter不满足明确的field/mask/size规则而确定性选择“不产生candidate”，此时不进入Context事务且不影响secured result；一旦已向P1提交candidate，approval/CAS/encryption/persist任一步失败必须遵守P1 finalization原子语义，05不得把失败降级成静默成功。

## 14. 幂等、事务与一致性设计

- visibility/selection、citation ID、generation projection、ECP-1、fallback和public draft在相同ordered candidates/bindings/limits/policy下确定；
- generation Provider本身不要求确定，但outcome必须绑定唯一operationId/packageDigest；迟到结果作废；
- Provider/client不自动retry，Handler不调用备用Provider；当前每generation operation 0或1 outbound attempt；
- ECP/candidate不跨Invocation缓存或复用，package/citation ID只在本次Invocation有效；
- final currentness发生在最终identity/size稳定后，Result Security同步本地执行，不存在异步gap；
- Result与Context writes由P1 finalization协调；05不先写Context、audit或candidate表；
- optional fallback不是Provider事务补偿，只是同Invocation内纯函数路由。

## 15. 权限、风控与审计设计

1. 只消费03 Safe candidate；先应用public visibility field/mask，再仅对generation应用all-or-none Provider outbound最小投影；scope/policy缺失不默认放行。
2. Provider input不含subject/JWT/ACL/target/profile/limit/query/document identity/URI；citation ID为本Invocation selection-local opaque值，generation package只复用该ID而不重新分配。
3. Provider payload所有文本/ID/enum/字段都不可信；strict parser/candidate factory/citation verifier逐层验证。
4. generated/fallback/refuse最终visible identity set全部进入03 final currentness，DENY/FAILURE不返回partial evidence/text。
5. Result Security不外部I/O、不读AgentProperties、不做fallback；unknown ContractRef/type/Mask/field/identity整体拒绝。
6. public DTO无internal candidate字段、Provider invalid IDs/reason、alias/profile/target/ACL/limit metadata。
7. coverage/count不使用未授权或ES total，拒绝通过差值暴露denied/missing document。
8. query/filter Context只在P1 approval/mask/encryption后保存；evidence/citation/document ID不持久化。
9. security audit使用closed reason和safe digest；普通日志不记录文本/ID/payload/exception body。

## 16. 性能与容量设计

| 阶段 | 复杂度/上限 | 防护 |
|---|---|---|
| Public visibility projection | O(N×visible fields) | N<=04 bounded candidates，field set typed/bounded |
| Evidence selection | O(N) | stable prefix，count/chars checked arithmetic |
| Generation evidence projection | O(selected×provider fields) | all-or-none，no subset/reorder，typed policy |
| ECP canonical | O(selected chars) | length-prefixed streaming digest，不复制多份全文 |
| Provider request | <=maxContextChars/evidence caps | 06 response/request byte cap、bulkhead/deadline |
| Citation parse | O(generated chars + IDs) | closed marker regex/parser、count/chars bounded |
| Fallback | O(selected evidence) | complete-unit append、output limits |
| Result size | O(public draft bytes) | shared serializer、maxResultBytes、no unbounded retry loop |
| Result Security | O(public nodes/fields) | no I/O、bounded mask/citation recheck |

实现避免同时保留Safe candidate全文、Provider text副本、ECP JSON、candidate JSON和public JSON多份：使用immutable slices/value引用和streaming digest/serialization；但不得用lazy对象跨Invocation或在日志中materialize全文。byte-fit reduction最多按evidence数线性移除尾部，不循环调用Provider。
