## 3. 文档状态说明

本文处于 In Review，不授权直接修改公共 Agent API、es-query-api 既有调用者、配置中心、生产 Provider 或 Elasticsearch 数据。本文只冻结 `DocumentCapabilityHandler` 及其 Document Adapter/ES 检索路径的目标实现。

本文是 P2_V3 中 Document 查询准备、检索调用、多通道执行、RRF、去重、上下文扩展、rerank 调用位置和失败路由的唯一专题规范。旧 P2/P2_V2 仅保留 provenance；其中的 `indexAlias/profileVersion/aclScope/Map DSL` 请求、Handler 直读 `AgentProperties`、两套 merger 或 Runtime rewrite 路径不再用于补充实现。

## 4. 背景与目标

现有实现已经包含 rewrite、embedding、ACL、hybrid search、RRF、context、rerank 和 generation，但它们通过一个可变 `DocumentRetrievalRequest` 反复复制并由 Handler 读取散配置，导致以下问题：

- `ValidatedDocumentPlan` 直接携带 Adapter DTO，Planning、Validation 与执行边界混合；
- Handler 根据 `AgentProperties` 再决定 profile、feature、数量和 fallback，绕过 P1 冻结结果；
- 请求携带 `retrievalProfile/profileVersion/indexAlias/expected model/dimension/raw aclScope`，侵入 01/02/03/06 所有权；
- Adapter 与 es-query-service 接受 `Map<String,Object>`/自由 query DSL，无法证明 caller filter 与 protected filter 始终同时存在；
- 当前 ES 侧在 raw hit 未形成完整安全 binding 前执行 RRF/dedup/context，Agent 侧又把 response validator 描述成 RRF 前置，顺序不闭合；
- context 逐 document 发起查询，存在 N+1、无界字符和授权 binding 漂移风险；
- `partial`、`degraded` 布尔值不足以表达 required/optional channel 的确定性语义；
- Adapter result、evidence result 和最终 Agent result 使用相近 DTO，责任边界不清。

目标是形成一条可直接实现、可测试且为未来 Multi Agent 保留叶子边界的单智能体执行链：每个 `ValidatedDocumentPlan` 只选择一个 Corpus；Handler 只消费冻结计划和 Execution Context；03 形成 ACL binding；06 只执行 typed Provider operation；es-query-service 对一个 resolved target 执行全部 channel/RRF/dedup/context；Agent 边界再次校验并投影 safe candidates；05 完成 evidence/output；03 完成 final currentness；P1 Result Security 最终投影。

## 5. 设计范围

### 5.1 范围内

- `DocumentCapabilityHandler` 的唯一业务执行顺序和阶段依赖；
- 从 `ValidatedDocumentPlan` 形成 query variants、typed channels 与 retrieval command；
- rewrite、embedding、rerank 的调用时点、输入子集校验和 required/optional fallback；
- Agent Adapter 与 es-query-service 的 strict typed request/response contract；
- 单 Corpus/单 resolved target/单 protected filter 的 hybrid retrieval；
- channel 执行、raw-hit binding、RRF、chunk merge、document limit、context batch expansion；
- Adapter 边界 response binding、`AclBoundDocumentHit` 到 `SafeDocumentCandidate` 的交接；
- 检索 diagnostics、deadline/cancellation、一致性、容量和测试门禁；
- 单智能体实现下为 Multi Agent 演进保留的 leaf invocation seam。

### 5.2 范围外

- Corpus source、schema、rebuild、manifest、alias switch 与 target resolver 内部算法，归 01；
- Profile 选择、projection、Document resource contribution/resolver，归 02/P1；
- ACL authority、protected filter AST、candidate security、final currentness 算法，归 03；
- evidence packing、citation、fallback/refuse、最终 Document candidate，归 05；
- Provider HTTP、credential、model、timeout、response cap、attempt metadata，归 06；
- Gold/security/capacity gate、rollout/emergency state、回滚和迁移 change，归 07；
- Multi Agent coordinator、子任务分解、跨 Agent 聚合、共享记忆或跨 Invocation 事务。

## 6. 上级文档约束

本文必须同时满足：

1. Planning Runtime 只做 Route/Plan，不执行检索或 rewrite/embedding/rerank/generation。
2. Core 保持 capability-neutral；Document 分支只存在于 capability handler/validator/adapter。
3. Handler 只接收 `ValidatedDocumentPlan` 与 `ExecutionContext`，不重读 Agent Profile、Policy、Permission、Document Profile 或业务上限配置。
4. 所有外部操作使用 P1 `CapabilityOperationContext`、absolute deadline、cancellation 和同一 `ResourceLimitReference`；不得自造 deadline 或重算 Effective limits。
5. Adapter 是 Agent 与外部数据能力的边界；Adapter 不获得 Raw Plan、JWT、ExecutionScope、权限正文或 Provider credential。
6. Result Security 仍由 P1 单一端口执行；04 不新增第二最终输出投影器。
7. 当前是单智能体执行；Multi Agent 只预留 invocation/operation/owner-neutral contract，不实现调度与聚合。

## 8. 设计边界与约束

| 约束 | 冻结规则 |
|---|---|
| 单计划单 Corpus | 一个 `ValidatedDocumentPlan`、一条 retrieval command、一个 hybrid request 只允许一个 `DocumentCorpusKey` |
| 单次 target resolve | es-query-service 在 request boundary 调用 01 resolver 一次，全部 channel/context 使用返回的同一 physical target |
| 单一 protected binding | 每个 channel、context 和 response 都绑定同一 protected filter digest/ACL evidence digest |
| Profile 不重入 | command/wire 不携带 Profile 正文、allowed set、alias/schema/provider/model；只携带最小 execution binding safe refs |
| 无自由 DSL | Agent/Adapter wire 使用 sealed typed query/filter/channel DTO；caller 不能提交 JSON DSL、script、field name 或 operator |
| 先绑定后算法 | es-query-service raw hit 必须先通过本地 target/filter/schema/ACL binding 校验，再参与 RRF/dedup/context |
| 边界再校验 | Adapter 收到 fused response 后再次校验 envelope/hit/context binding，才向 Agent 输出 `AclBoundDocumentHit` |
| Adapter SPI 不改写 | Domain Adapter 固定 `(validated command, operation context)`；只有 03/06 capability-local Provider request 内嵌 context |
| Limit 同源 | 所有数量取 `ValidatedPlan` concrete value 与同一 Effective `DocumentResourceLimit` 的较小/已验证值；不得读取 properties 默认补大 |
| Optional 只缩小 | optional failure 只能删除增强/可选 channel或回到原稳定顺序，不能换 Provider、扩大 query/topK 或放宽 filter |
| 无跨 Invocation cache | query/vector/result/currentness ALLOW 不跨 Invocation 缓存，不以 profile/corpus 作为共享授权 key |
| 一次外部 attempt | 每个 capability-local Provider/Adapter operation 当前最多一次 outbound attempt；SDK retry 关闭 |
| 外发先决策 | rewrite/embedding/rerank 在port前必须绑定06基于current ExecutionScope生成的purpose-specific outbound decision；Safe/public-visible不等于Provider-visible |

当前不支持一个 Validated Plan 同时查询多个 materialType/Corpus。若公共请求要求多个 materialType，Planning 必须在进入本 Handler 前拒绝或由未来上层 Multi Agent/coordinator 形成多个独立、各自授权和限额的 child Invocation；04 不预建本地 fan-out/fan-in 或跨 Corpus RRF。

## 9. 总体设计

### 9.1 唯一执行序列

~~~text
P1 Core recheck
  -> DocumentPlanValidator -> ValidatedDocumentPlan
  -> DocumentCapabilityHandler.require same DocumentResourceLimit
  -> 03 ACL resolve/evidence/protected filter + scope currentness
  -> DocumentQueryPreparer
       -> local rule extraction
       -> optional 06 rewrite -> strict normalization
       -> optional 06 embedding -> vector/provider binding validation
  -> DocumentRetrievalCommandFactory
  -> DocumentRetrievableAdapter.retrieve(command, operationContext)
       -> typed Agent DTO -> typed es-query-api DTO
       -> es-query-service authentication/strict parse
       -> 01 CorpusKey target resolve exactly once
       -> caller/protected filters compile separately, top-level AND
       -> bounded channel execution on the same physical target
       -> local raw-hit binding validation
       -> deterministic RRF -> document selection -> batch context
       -> typed response bound to target/filter/profile/limit/operation
       -> Adapter response binding validation -> AclBoundDocumentHit
  -> 03 DocumentCandidateSecurityProjector -> SafeDocumentCandidate
  -> optional 06 rerank -> subset validator -> stable reordered candidates
  -> 05 evidence/search or evidence/generation/fallback candidate
  -> 03 final currentness guard on exact candidate/evidence/citation set
  -> P1 Document Result Security local verification/projection
  -> P1 lifecycle commit
~~~

### 9.2 责任分层

| 层 | 决定什么 | 不决定什么 |
|---|---|---|
| Handler | 阶段顺序、required/optional 路由、operation context、调用 03/05/06 的位置 | alias、ACL 语义、Provider transport、output security |
| Query Preparer | deterministic query variants、typed channel inputs | profile/field/feature 授权、自由 DSL |
| Adapter | typed-to-typed 映射、一次 HTTP operation、response boundary validation | 业务 fallback、RRF 算法、ACL authority |
| es-query-service | target resolve、channel query compile/execute、local hit binding、RRF/dedup/context | Profile 选择、caller authorization、rerank/generation |
| 03 | protected filter、bound/safe candidate、final currentness | channel scoring、document ordering |
| 05 | evidence/citation/generation boundary/final candidate | retrieval 排序、ACL filter |
| 06 | 单次 Provider operation 与 typed outcome | 是否调用、fallback 或下一阶段 |

### 9.3 Multi Agent 演进 seam

`DocumentCapabilityHandler` 是 leaf capability executor，而不是 Agent coordinator。所有 request/result binding 使用 invocationId、requestCorrelationId、registrationIdentity、operationId 和 authorization/limit safe refs，不使用 JVM singleton 状态或“当前 Agent”全局变量。未来 Multi Agent 只需在上层为每个 child 建立独立 P1 Invocation/Execution Scope，再调用同一 leaf handler；当前 DTO 不加入 `parentAgentId/workerList/sharedContext` 等尚无语义的字段。

跨 child 的候选融合必须另立上层契约，重新证明权限、resource allocation、provenance 和 Result Security；不得复用本文单 Corpus RRF 直接合并不同 authorization binding。

## 10. 详细功能设计

### 10.1 ValidatedDocumentPlan 消费边界

目标 `ValidatedDocumentPlan` 不再保存 `DocumentRetrievalRequest` Adapter DTO，而保存 Validator 输出的不可变领域值：

~~~java
public record ValidatedDocumentPlan(
    String capabilityId,
    String domainId,
    DocumentOperation operation,
    String normalizedQuery,
    List<ValidatedDocumentCallerFilter> callerFilters,
    DocumentExecutionProfileProjection profileProjection,
    ValidatedDocumentExecutionParameters parameters,
    DocumentOutputIntent outputIntent)
    implements ValidatedPlan {

    @Override
    public AgentPlanKind planKind() {
        return AgentPlanKind.DOCUMENT;
    }

    @Override
    public Optional<String> domain() {
        return Optional.of(domainId);
    }
}
~~~

`parameters` 只包含 Runtime plan 在 server projection/Effective limits 内选择并经 Validator 核准的具体数量、query option 和 return fields；不得包含 alias、physical index、schema、raw ACL、Provider/model、timeout/attempt、Profile/Policy/Permission 正文或散装 Effective limit 副本。`profileProjection.selectedCorpus()` 是唯一 Corpus。

Handler 首先从 `context.executionScope().resourceLimits()` 以 P2_V3/02 的固定 `ContractRef` 和类型取得同一 `DocumentResourceLimit`，核对 plan profile projection digest、operation、capability、registration、`ResourceLimitReference` 与 Execution Context binding。任何缺失、类型/version mismatch、concrete value 超限、deadline 已过或 cancellation 已触发，在调用 03/Adapter/Provider 前拒绝。

### 10.2 Query 规范化与规则抽取

`DocumentQueryPreparer` 按以下顺序执行：

1. 使用 Validator 已接受的 `normalizedQuery`；Handler 不重新 trim 后改变 canonical query。
2. 校验字符数不超过 `maxQueryChars`，Unicode 非法序列、控制字符、空白 query 拒绝。
3. `DocumentRuleExtractor` 只从 query 与 typed caller filters 派生受控字段值，如 documentNo、issuer、taxType、validityStatus、effectiveDate；输出仍为 `ValidatedDocumentCallerFilter`，不能直接生成 ES field/operator。
4. 派生 filter 与 caller filter 合并时按 canonical field+operator+value 去重；总数不得超过 `maxCallerFilterCount`，冲突值拒绝，不以“最后一个覆盖”。
5. original query 永远是 variant 0；rule keywords 和 rewrite candidates 只用于各 channel query builder，不覆盖 caller/protected filters。

规则抽取必须是纯函数、确定性且不读取 Profile/config。无法识别的文本保留在 original query，不变成自由 metadata/DSL；敏感 query/keyword/value 不写日志、metric tag、checkpoint 或 Context。

### 10.3 Rewrite 调用与候选规范化

只有 `profileProjection.rewritePolicy()!=DISABLED` 且 `maxRewriteCandidates > 0` 才可能调用06 `DocumentQueryRewritePort`。Handler先调用06本地纯函数`DocumentProviderOutboundPolicyDecisionFactory.create(REWRITE,current ExecutionScope,selected Corpus,rewrite policy,query-only field view)`；factory只消费ExecutionScope中当前policy/permission/field/mask/security-classification refs，不读Provider配置或07状态。`DocumentRewriteInputProjector`再形成只含original query、语言/operation safe enum和允许候选数的最小input，并把其canonical digest绑定进`DocumentProviderOutboundPolicyReference`。

Handler从当前Execution Context创建`CapabilityOperationContext(REWRITE)`；`DocumentRewriteOperationRequest(input,policyReference,operationContext)`内嵌唯一context并实现P1 `CapabilityOperationRequest`。policy/reference不序列化给Vendor。decision不允许、过期、input digest mismatch或query outbound purpose不可证明时不得调用port：REQUIRED整体拒绝，OPTIONAL使用original+local rules，DISABLED本来即不可到达。request不包含ACL、Corpus alias、Profile正文、domain/materialType、Provider/model或document content。

`RewriteCandidateNormalizer` 固定执行：

- response operation/limit/deadline/cancellation metadata 必须与 request 相同；
- 只接受 plain text，拒绝 JSON/SQL/ES DSL、字段冒号表达式、script/template、控制字符和超长文本；
- Unicode NFKC、空白折叠后按 exact string 去重；与 original query 相同的不计入 rewrite 数；
- 先保持 Provider 返回顺序，再截取不超过 `maxRewriteCandidates`；Provider 响应本身超出 06 response cap 或 contract count 时整次 operation invalid，不把超量响应静默截成合法；
- 形成 Invocation 内短生命周期 `DocumentQueryVariants(original, ruleKeywords, rewrites, digest)`；digest 不持久化或作为高基数 metric。

feature policy 为 REQUIRED 时，disabled/timeout/invalid/late/failure 均拒绝本次执行；OPTIONAL 时使用 original+local rules 并记录 typed `REWRITE_DEGRADED`；DISABLED 时不得调用端口。fallback 不调用第二 Provider，不增加候选上限。

### 10.4 Channel 计划

通道使用 02 profile 中的 closed `DocumentRetrievalChannel`，当前仅允许：

| channel | 输入 | ES query builder | 必要校验 |
|---|---|---|---|
| `BM25` | original/rule/rewrite typed text variants | 01 schema 中受控 searchable text fields 的 multi-match/bool | field set 来自 projection，不能由 caller 指定 |
| `EXACT_PHRASE` | exact documentNo/phrase/original | term/match_phrase 的封闭组合 | exact field/type/analyzer contract 必须存在 |
| `DENSE_VECTOR` | 一条 normalized original query 的 embedding | 01 manifest 指定 vector field 的 kNN | embedding binding、finite vector、dimension/manifest 一致 |

不再并存 `EXACT` 与 `PHRASE` 两个语义重叠 enum；历史值在 M0 兼容清单中一次迁移到 `EXACT_PHRASE`，内部不保留第二 executor。未知 channel、空 enabled channels、required 非 enabled 子集、非正 weight/rrfK/candidate count 均在 Validator/command factory 双重拒绝。enabled channels 含 `DENSE_VECTOR` 时 `embeddingPolicy` 不能为 DISABLED；若 `requiredChannels` 含 `DENSE_VECTOR`，`embeddingPolicy` 必须为 REQUIRED。否则 Profile candidate/Planning 直接拒绝，不能把 required channel 建在 optional Provider 上。

`DocumentChannelPlanFactory` 以 profile projection 的 enabled/required/weights/fusion policy 和 concrete parameters 构造 immutable channel list。实际 channel 数不超过 `maxChannelCount`；每通道候选数不超过 `maxCandidatesPerChannel`；RRF 输入总数用 checked multiplication 验证，不能溢出或依赖 ES 默认 size。

### 10.5 Embedding 调用与索引兼容

仅当 channel list 含 `DENSE_VECTOR`、`profileProjection.embeddingPolicy()!=DISABLED` 且 `maxEmbeddingTexts/maxEmbeddingDimensions > 0` 时才可能调用06 `DocumentEmbeddingPort`。当前一次retrieval只embedding original normalized query，因此text count为1；rewrite candidates不自动产生额外vector。调用前同样取得`EMBEDDING` outbound decision并由`DocumentEmbeddingInputProjector`形成单文本input/policy reference；decision不适用时按required vector拒绝或optional删除vector channel，且outbound attempt=0。

06 在 Provider boundary 校验其 operational provider/model configuration 并返回：

~~~java
public record DocumentEmbeddingValue(
    List<Float> vector,
    int dimension,
    DocumentEmbeddingBindingReference bindingReference) {}
~~~

04 校验 vector 非空、元素 finite、dimension 与实际长度一致、`dimension <= maxEmbeddingDimensions`、operation metadata/limit reference/deadline binding 一致。`DocumentEmbeddingValue` 是 06 Provider operation outcome；command factory 将其映射为 adapter-api `DocumentQueryEmbedding(vector,dimension,bindingReference)`，不能让 adapter-api 依赖 agent-service provider 包。Profile/Validated Plan/retrieval command 不保存 expected provider/model/dimension；`bindingReference` 只携带 06 允许的 safe provider/model/version/dimension digest。es-query-service 在解析 01 sealed manifest 后再精确校验该 binding/dimension 与 active vector policy；不一致是 typed `VECTOR_INDEX_BINDING_MISMATCH`，不得截断、补零、换模型或回退到另一 physical index。

若 DENSE_VECTOR required，任何 disabled/failure/mismatch 均拒绝；若 optional，则在发出 retrieval command 前删除该 channel 并按剩余通道重建 canonical channel plan。删除后无通道则拒绝，不发送空检索。embedding optional fallback 不能改变其他 channel weight；RRF 不做权重归一化。

### 10.6 ACL 前置与 retrieval command

Handler 在任何检索 Adapter 调用前完成 P2_V3/03：

1. 以 selected Corpus、current permission evidence 和 `CapabilityOperationContext(ACL_SCOPE_RESOLVE)` 调用 ACL authority；
2. 形成 `DocumentAclExecutionEvidence` 与唯一 `DocumentProtectedFilterBinding`；
3. 调用 scope currentness；
4. 核对 Corpus/profile projection/authorization/limit reference 与 plan/context 一致；
5. Allow 后才构造 retrieval command，Deny/Failure 均 fail closed。

### 10.7 Adapter 与跨服务请求契约

`DocumentRetrievableAdapter` 只提供一个目标方法：

~~~java

    CapabilityOperationOutcome<AdapterDocumentRetrievalResult> retrieve(
        DocumentRetrievalCommand command,
        CapabilityOperationContext operationContext);

~~~

`agent-adapter-document` 的 mapper 把 Agent typed value 一对一映射到 es-query-api strict DTO。目标 `HybridSearchRequest` 至少分为：

~~~java
public record HybridSearchRequest(
    DocumentCorpusKeyDto corpusKey,
    DocumentSearchExecutionBinding executionBinding,
    List<DocumentCallerFilterNode> callerFilters,
    DocumentProtectedFilterNode protectedFilter,
    String protectedFilterDigest,
~~~

Agent command 使用 agent-adapter-api `DocumentCorpusKey`，ES wire 使用 es-query-api `DocumentCorpusKeyDto`；二者遵守 01 DCK-1 canonical contract，由 agent-adapter-document 唯一 mapper转换，禁止 agent-adapter-api 依赖 es-query-api。相同规则适用于 `ResourceLimitReference`、operation metadata、embedding/security binding：es-query-api 定义字段等价的 strict wire DTO，不直接依赖 agent-adapter-api Java type；只有同时依赖两侧的 agent-adapter-document执行映射和 canonical contract test。DTO 禁止出现 `Map<String,Object>`、rawJson、queryDsl、filterDsl、script、query_string、caller field string、index/alias、Profile/ACL 正文、queryVector 日志字段或 extensions。Query text/vector 是执行 payload，只存在传输体和 Invocation 内存；不得进入日志/trace attribute。HTTP 使用专用服务身份、scope 和 TLS，filter/profile/limit digest 只做完整性 binding，不替代服务认证。

`DocumentSearchOperationMetadata` 只映射 requestCorrelationId、operationId/type、absolute deadline epoch、registration safe identity和 `ResourceLimitReference`；不复制 ExecutionScope/JWT/permission/CancellationSignal。Agent cancellation 由 Adapter 订阅只读 signal并取消/关闭当前 HTTP exchange，es-query-service 通过 transport cancellation/request scope停止子任务；deadline仍在 wire metadata独立验证。es-query-service 必须在开始、每个 channel/context 子任务完成和 response 写出前检查 deadline/transport cancel；late response不能形成成功 outcome。

Adapter 不在 HTTP 异常后改走 generic search endpoint；不自动 retry；null/unknown content-type、oversize、schema mismatch、late response、cancellation、timeout、5xx 形成 typed failure。它不决定 required/optional fallback，Handler 按本文矩阵处理。

### 10.8 es-query-service request boundary

es-query-service 按固定顺序处理：

1. 验证专用服务身份/scope、request size、content-type 和 strict schema；
2. 校验 operation safe metadata、Corpus/execution/profile/limit/filter binding 字段非空且 canonical；
3. 使用 01 `DocumentIndexTargetResolver.resolve(corpusKey)` 精确一次，得到 `ResolvedIndexTargetRef`；
4. 验证 target sealed、release-attested、schema/vector policy 与 request 相容；
5. strict parse caller filters，拒绝 ACL field/unknown field/operator；
6. strict parse protected AST、重算 DAF-1，与 digest/evidence/cap/schema 校验；
7. 分别编译 caller fragment 和 protected fragment；每个 channel/context query 顶层 AND 同时引用这两个 immutable fragment；
8. 构造 bounded channel tasks 并使用步骤 3 的 physical target；后续不得再次读取 alias；
9. 先校验 channel raw response/hit binding，再进入 RRF/dedup/context；
10. 返回只含安全字段与 safe target binding 的 typed response。

任一 channel 尝试移除/变更 protected fragment、使用另一 target、请求 `_source` embedding/ACL principal/internal field 或走 generic endpoint，整个 request 失败。caller filter 为空合法，protected filter 永远必填。

### 10.9 Channel 执行与本地 raw-hit binding

每个 channel task 共享 request cancellation/deadline、target、filter fragments 和 source allowlist；可在 es-query-service 内有限并行，但 task 数不超过实际 channel 数，禁止 unbounded executor/common pool。任一 task 在 deadline/cancel 后不得把结果加入融合。

`DocumentChannelHitBindingValidator` 位于 es-query-service，在 RRF 前把 ES raw hit 转为内部 `BoundDocumentChannelHit`。它验证：

- channel/Corpus/physical target/schema/content/attestation binding；
- protected/caller filter digest 与当前 compiled fragment identity；
- documentId/documentVersion/chunkId/chunkIndex/offset/ACTIVE status；
- aclRef/aclVersion 非空并与 indexed projection 合法；
- title/section/page/content/safeSourceUri/business fields 类型、数量和 source allowlist；
- ES score finite，channel 内 rank 输入可稳定排序；
- `_source` 不含 embedding、principal sets、raw ACL、internal index、free metadata 或未知字段。

任一 raw hit invalid 时整个 retrieval 失败，不能丢弃异常 hit 后继续，因为丢弃会改变 count/rank 并可能泄露对象存在性。零 hit 是合法成功，不产生“被 ACL 过滤数量”。

### 10.10 Required/Optional channel outcome

channel outcome 使用 closed union，不使用 `partial=true` 代表任意含义：

~~~java
public sealed interface DocumentChannelOutcome
    permits DocumentChannelSucceeded, DocumentChannelFailed {}

public record DocumentChannelSucceeded(
    DocumentRetrievalChannel channel,
    List<BoundDocumentChannelHit> hits,
    DocumentChannelDiagnostics diagnostics)
    implements DocumentChannelOutcome {}

public record DocumentChannelFailed(
    DocumentRetrievalChannel channel,
    DocumentChannelFailureCode code,
    String diagnosticId)
    implements DocumentChannelOutcome {}
~~~

required channel 失败、迟到、取消、binding invalid 时 es-query-service 返回整体 typed failure，不执行 RRF。optional channel 的 operational no-result 是成功空列表；只有明确的 optional operational failure 才可删除该 channel，并在 response 记录低基数 reason。ACL/contract/target/schema/binding/security failure 永远不是 optional degradation。

删除 optional channel 后至少有一个 succeeded channel才能融合。RRF 使用原 channel weight，不按剩余权重归一化；这样同一成功集合得到同一排序。Handler 收到 response 后再次核对 required outcome 完整和 degraded 集合只来自 optional channels。

### 10.11 RRF 与 chunk identity merge

每个 succeeded channel 先稳定排序：`esScore desc, documentId asc, documentVersion asc, chunkIndex asc, chunkId asc`，rank 从 1 开始。同一 channel 出现重复 `chunkIdentity=(documentId,documentVersion,chunkId)` 时：binding 全同取排序第一项；任一 content/ACL/target/filter binding 不一致整体失败。

跨 channel 按相同 chunk identity 聚合。RRF 固定公式：

`score = Σ(weight[channel] / (rrfK + rank[channel]))`

实现对每个 term 使用 `BigDecimal.valueOf(weight).divide(BigDecimal.valueOf(rrfK+rank),18,HALF_EVEN)`，再按 stable channel enum 顺序相加并保持 scale 18；禁止依赖平台默认浮点格式或 completion order。`rrfK` 与正整数 weight 来自 profile projection 并已校验；缺失 channel 不贡献，raw ES score 不跨 channel 直接相加。

融合稳定排序为：

1. RRF score 降序；
2. best channel rank 升序；
3. matched channel count 降序；
4. documentId 升序；
5. documentVersion 升序；
6. chunkIndex 升序；
7. chunkId 升序。

融合完成后最多保留 `maxFusedCandidates`。`candidateId` 由 Corpus、target binding、documentVersion、chunkId、filter/evidence binding 的 canonical digest 形成，不使用 list position 或随机 UUID；不得在重试/重排时改变 identity。

### 10.12 Document selection 与去重

RRF 已完成 chunk 跨 channel merge；随后执行 document selection，而不是第二套相似度 dedup。dedup key 固定包含：

`CorpusKey + targetBindingDigest + documentId + documentVersion + aclRef + aclVersion + protectedFilterDigest + aclEvidenceDigest`

相同 documentId 但任一 security/version binding 不同不是两个可并存 group，而是 contract/security failure。禁止按标题、URI、内容 hash 等模糊键跨文档合并。

按 RRF 稳定顺序单次遍历：

1. 第一次遇到新 document group 时，若 distinct document 数已达 `maxReturnedDocuments`，跳过该 group 的全部后续 chunk；
2. 已接受 group 最多保留 `maxChunksPerDocument` 个 chunk；
3. 总接受 chunk 数仍不得超过 `maxFusedCandidates`；
4. 被跳过的 item 只增加安全 truncation flag/总计数，不输出 identity、score、title 或原因细节；
5. 不重新排序，不用 HashMap iteration order 决定输出。

Profile 的 `DocumentDedupPolicy` 在当前版本只能选择上述确定性 strategy 及其 server-frozen参数，不能选择任意字段或脚本。`maxReturnedDocuments` 限制 distinct documents，不等价于 hit count。

### 10.13 Context window 批量扩展

context 只对 10.12 已接受的 chunk 执行，用于构造 candidate text window，不新增 candidate/evidence/citation identity。before/after chunk 数来自 profile projection 的 closed `DocumentContextPolicy`，并受已验证 concrete parameter 约束；单 anchor snippet 受 `maxSnippetChars`，所有返回 context window 文本合计受 `maxContextChars` 的同源预算约束。

es-query-service 只发起一个 bounded batch context query：按已接受 documentId+documentVersion 计算去重后的相邻 chunkIndex 集，checked count 后以同一 physical target、同一 caller/protected fragments、同一 source allowlist 查询。禁止逐文档 N+1、alias 再解析、无 filter mget、raw cache 拼接或扩大到整个 document。

每个 neighbor 必须通过与 10.9 相同的 binding validator，并且与 anchor 的 Corpus/target/documentVersion/aclRef/aclVersion/filter/evidence binding 全同。缺失/越界 neighbor 视为空，不暴露原因；返回额外/错误 binding/重复冲突 neighbor 整体失败。文本按 `before chunkIndex asc -> anchor -> after chunkIndex asc` 拼接；在 Unicode code point 边界按全局剩余字符预算裁剪，记录 `CONTEXT_TRUNCATED`，不得把裁剪后的文本当新 chunk identity。

`maxContextChars` 是 retrieval window→05 `EvidenceContextPackage` 的 end-to-end ceiling，不是 04 和 05 各可消费一次的两份额度。04 返回的全部 context 文本已不得超过该值；05 只能选择其子集并连同其他允许 evidence text 再证明 package 总字符不超过同一值，不能通过重新读取全文、再次扩展 neighbor 或把 snippet/context 分桶相加来放大。`maxEvidenceChars/maxSnippetChars` 仍分别约束 evidence 总量和单 snippet，所有适用上限同时取交集。

es-query-service 返回：

~~~java
    ResourceLimitBindingDto resourceLimit,

public record ResourceLimitBindingDto(
    String contractName,
    String contractVersion,
~~~

`HybridSearchHit` 只含 candidate/document/chunk identity、safe source fields、context window、channel ranks、RRF score 和 03 要求的 security binding refs；不含 raw `_source`、internal index/alias、ACL principals、embedding/vector、score explanation、query、DSL 或 arbitrary metadata。

Adapter 的 `DocumentRetrievalResponseBindingValidator` 在 HTTP 反序列化后执行第二次校验：request/response operation、Corpus、profile/limit/authorization/filter/evidence/target refs 完整一致；channel result 符合 required/optional policy；hit identity/order/count/field/type/score/context 合法；diagnostics count 与 hits 可验证地一致；prohibited/unknown 字段拒绝。它依据每个返回 hit 的 channel ranks/weight/rrfK 重算可见 RRF score和相对顺序，并校验 truncation/count 声明，但不在 Agent 重跑 ES channel或重建被截断的完整候选集合。输出 `AdapterDocumentRetrievalResult(List<AclBoundDocumentHit>, diagnostics, binding)`。

es-query-service 本地 validator 是“算法前安全校验”，Adapter validator 是“跨服务边界完整性复核”，二者责任不同，不是两套 RRF 或两份 ACL authority。Adapter 任一 mismatch 整体拒绝，不丢单 hit继续。

### 10.15 Safe candidate 投影

Handler 只把 `AclBoundDocumentHit` 交给 P2_V3/03 `DocumentCandidateSecurityProjector`，并提供同一 ACL evidence、target/filter/profile/limit binding。Projector 输出 ordered `SafeDocumentCandidate`；04 不复制其字段/mask/URI/文本安全算法。

投影前后 candidate 数和顺序必须相同；若某 hit 因 prohibited field、URI 或 binding 无法形成 safe candidate，整体 retrieval security failure，不静默减少列表。query/vector/raw rank details 不进入 candidate。空 bound hits 输出空 safe list并进入 05 的 NO_EVIDENCE 路径。

### 10.16 Rerank 调用与稳定回退

只有 `profileProjection.rerankPolicy()!=DISABLED` 且 `maxRerankCandidates > 0` 且 safe list 非空时才可能调用06。`SafeDocumentCandidate`只证明ACL/target/filter安全，不自动证明可外发。Handler先取得`RERANK` outbound decision；`DocumentRerankInputProjector`对safe list前`min(size,maxRerankCandidates)`项应用该decision的field/mask/security-classification规则，形成candidateId、bounded query/title/snippet和允许低敏字段的最小projection及input digest。任一item/field不允许时不得静默换成不同candidate子集：REQUIRED拒绝，OPTIONAL不调用port并保持完整原RRF顺序。

Rerank input不含ACL、URI、context全文、embedding、document/chunk identity、internal metadata、citation owner、Profile/provider/model或物理target。`DocumentRerankOperationRequest(input,policyReference,operationContext)`内嵌唯一context；06只验证/传输该projection，不读取ExecutionScope或自行放宽decision。

06 payload validator 必须证明：

- operation/limit/deadline/cancellation binding 一致且 response 未迟到；
- candidateId 是 input 子集、无重复；
- score finite，reasonCode 是 closed safe enum；
- Provider 未返回文本、field/metadata、citation、topK 或新增 candidate；
- response count 不超过 input count。

稳定重排规则：已返回 IDs 按 `rerankScore desc, originalPosition asc, candidateId asc`；未返回的 input IDs 按原顺序追加；未送 rerank 的 tail 再按原顺序追加。Provider 空结果视 invalid outcome。REQUIRED 失败拒绝；OPTIONAL 失败/disabled/late 使用完整原 RRF 顺序并记录 typed degradation；禁止备用 Provider或第二次调用。

rerank 只生成 order/score sidecar，不修改 `SafeDocumentCandidate` identity/security/text/URI。05 可消费最终 order，但不得把 provider score 当授权或 citation 可信度。

### 10.17 05/06/03 后续调用位置

最终 ordered safe candidates 交给 05：

- `document.search`：05 选择/打包 evidence、citation 和 coverage，形成 search result candidate，不调用 generation；
- `document.answer`/`document.summarize`：05 先形成 `EvidenceContextPackage`，仅在非空且 operation policy/limit 允许时由 Handler 调用 06 generation；05 再校验 untrusted payload、citation，决定 generated candidate、extractive fallback 或 refuse；
- 04 不自行拼 answer/summary/citation，不把 `AdapterDocumentRetrievalResult` 直接作为最终 payload。

当 05 已冻结最终 candidate/evidence/citation identity set 后，Handler 紧邻返回 Core 前调用 03 `DocumentRevocationGuard`，取得 bound `DocumentFinalCurrentnessDecision` 并附到 05 candidate。其后 P1 `DocumentResultSecurityProjector` 只做本地 decision verifier 和 output contract/field/mask/count/chars/bytes 投影。任一后续 identity 增删/重排导致 candidateSetDigest 改变都拒绝。

### 10.18 失败与降级矩阵

| 阶段/故障 | REQUIRED/安全关键 | OPTIONAL | 对外安全语义 |
|---|---|---|---|
| Plan/Profile/limit binding mismatch | 拒绝，不调用外部能力 | 不适用 | INVALID_EXECUTION_SCOPE |
| ACL resolve/currentness deny/failure | 拒绝 | 不可降级 | PERMISSION_CHANGED/ACCESS_DENIED 模板 |
| rewrite disabled/timeout/invalid/late | required 拒绝 | original+local rules | 不暴露 Provider 原因 |
| embedding/vector binding failure | required vector 拒绝 | 删除 vector channel | 不暴露 model/index细节 |
| target/schema/attestation/filter binding failure | 整体拒绝 | 不可降级 | RETRIEVAL_UNAVAILABLE 模板 |
| channel zero hit | 成功空 channel | 成功空 channel | 只报告安全空结果 |
| required channel operational failure | 整体拒绝 | 不适用 | RETRIEVAL_UNAVAILABLE |
| optional channel operational failure | 不适用 | 删除 channel、原权重 RRF | typed degradation |
| raw hit/response contract mismatch | 整体拒绝 | 不可丢 hit继续 | RETRIEVAL_UNAVAILABLE |
| context missing neighbor | 继续 | 继续 | 不暴露缺失原因 |
| context binding/contract failure | 整体拒绝 | 不可降级为无 context | RETRIEVAL_UNAVAILABLE |
| rerank invalid/late/failure | required 拒绝 | 原 RRF 顺序 | 不暴露 Provider 原因 |
| 所有 safe candidates 为空 | 05 NO_EVIDENCE/refuse | 同左 | 不调用 generation |
| generation/citation/final currentness/Result Security | 依 05/03/P1 拒绝 | 只允许 05 冻结 fallback | 不返回 partial answer/evidence |
| deadline/cancellation | 立即终止，迟到结果作废 | 不再继续 fallback 链 | CANCELLED/DEADLINE_EXCEEDED |

所有 degradation 都是当前 Invocation 的不可变 diagnostics item；不能修改 P1 state machine success/failure 语义，不能写回 Profile/config，也不能作为下一次调用的默认策略。

## 12. 数据设计

本文不新增数据库表、索引或长期缓存。所有对象均为 Invocation 内不可变值：

| 数据 | 生命周期 | 可持久化内容 |
|---|---|---|
| query variants/vector | query preparation～retrieval 完成 | 不持久化、不写 Context/log |
| ACL evidence/protected AST | Invocation retrieval～final currentness | 仅 safe digest/version/diagnostic ref 可审计 |
| resolved physical target | es-query-service 单 request | 仅 safe target binding 可返回；physical name 不跨边界 |
| channel raw/bound hits | es-query-service request | 不持久化 |
| fused/context hits | es-query-service→Adapter operation | 不持久化；只传安全字段 |
| safe/rerank candidates | agent-service Invocation | 不写 checkpoint/共享 Context |
| retrieval diagnostics | Invocation + safe audit/metrics | 低基数 outcome/count/duration/version safe ref |

canonical digest 责任：query variant digest 仅做本地完整性；DAF-1/DAE-1/DCS-1 归 03；target binding 归 01；profile projection digest 归 02；limit reference 归 P1/02。04 不发明同一事实的第二 digest，也不把这些 digest 当签名或授权证据替代品。

## 13. 状态流转设计

04 不创建第二持久化状态机。Invocation 内阶段视图仅用于 diagnostics：

~~~text
PLAN_VALIDATED
  -> EXECUTION_BOUND
  -> ACL_BOUND
  -> QUERY_PREPARED
  -> CHANNELS_PREPARED
  -> RETRIEVAL_STARTED
  -> TARGET_BOUND
  -> CHANNELS_EXECUTED
  -> HITS_BOUND
  -> FUSED
  -> SELECTED
  -> CONTEXT_BOUND
  -> RESPONSE_VALIDATED
  -> SAFE_PROJECTED
  -> RERANKED | RERANK_SKIPPED | RERANK_DEGRADED
  -> EVIDENCE_OUTPUT_BOUND
  -> FINAL_CURRENTNESS_ALLOWED
  -> HANDLER_CANDIDATE_READY
~~~

任何拒绝/timeout/cancel 直接返回 P1 typed failure，不把局部阶段写为可恢复 checkpoint。降级是成功候选的 typed annotation，不是独立 SUCCESS 终态。P1 Lifecycle/Attempt owner 仍是 Invocation 状态唯一权威。

## 14. 幂等、事务与一致性设计

- 检索是只读操作，不建立跨 Agent、ACL authority、Provider、es-query-service 的分布式事务。
- 相同 frozen plan、authorization/limit/profile binding、target、query variants、Provider value 和 channel outcomes 产生相同 candidate identity/order；Provider/ES 版本变化通过 binding 显式体现。
- requestCorrelationId+operationId 只用于关联和 late-response rejection，不作为允许重放副作用的幂等写 key。
- alias 在 target resolve 后切换不影响当前 request；所有 channel/context 使用 resolved physical target。下一 Invocation 重新 resolve。
- ACL 在 retrieval 前 scope currentness、最终输出前 candidate currentness 双检；无法消除的时序窗口由 03 short-lived decision 与 07 SLA 控制。
- optional channel 并发完成顺序不影响 RRF；merger 按 channel enum/profile order 读取 outcomes，不按 future completion order。
- 不缓存跨 Invocation positive ACL、query result、vector、rerank order；未来缓存必须先有 authorization/currentness/eviction ADR。

## 15. 权限、风控与审计设计

1. protected filter 必填且与 caller filter 分字段传输、分对象编译、顶层 AND。
2. generic ES search/index/count/debug/preview 端点由 01 target guard 禁止访问 Document physical target。
3. Provider只见经current ExecutionScope purpose-specific decision投影的本阶段最小输入：rewrite/embedding不见文档和ACL；rerank只见all-or-none provider-safe candidate projection；generation归05/06。Safe/public-visible不作为外发许可。
4. target/filter/ACL evidence/profile/limit/authorization binding 在 request、raw hit、fused response、safe candidate 和 final candidate 全链闭合。
5. security/contract failure 不能降级、partial 或丢单 hit；用户错误不区分“无文档”和“无权限文档”。
6. query、vector、document text、ACL principal、URI query、raw score/DSL、physical index、credential 不进日志/audit/checkpoint/metrics tag。
7. audit 只记录 capability/operation、Corpus safe key、profile/permission/target safe version、limit/filter/evidence digest、channel outcome、count、termination 和 diagnosticId。
8. response DTO unknown/prohibited fields按 strict contract 拒绝；不把 arbitrary metadata 透传到 Agent result。

## 16. 性能与容量设计

| 阶段 | 上限/复杂度 | 防护 |
|---|---|---|
| Query preparation | query chars + rewrite candidates | O(chars+candidates)，无全库查找 |
| Embedding | 当前 1 text，dimension <= Effective limit | response bytes/finite/dimension 双检 |
| Channel execute | channelCount × candidatesPerChannel | checked multiplication、bounded executor、同 deadline |
| Raw binding | 所有 channel hits | O(total hits)，invalid whole-request |
| RRF | total hits | O(N log N)，N <= channel×candidate cap |
| Document selection | fused candidates | O(N)，stable linked structures |
| Context | 一个 batch，bounded doc/chunk indexes/chars | 禁止 N+1/mget 绕 filter |
| Response mapping | selected chunks/context chars | response byte cap、stream/typed parse |
| Rerank | <= maxRerankCandidates | 最小 safe projection、一次 Provider call |

es-query-service channel 并发使用 Document 专用 bulkhead，不使用 common pool；bulkhead/queue/connect/read cap 是 operational safety cap，只能早于 absolute deadline失败，不能扩大 DocumentResourceLimit。Context batch 的 terms/count/bytes 还受 03 compiler/transport security cap；超限整体拒绝，不截断 ACL terms 或换无 filter path。

禁止同时在 ES 和 Agent 各保留一份 RRF/dedup实现；目标唯一算法位于 es-query-service。Agent 只验证 response order/binding 与执行 rerank sidecar，避免大列表/正文跨服务多次复制。
