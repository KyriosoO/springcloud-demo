## 3. 文档状态说明

本文处于 In Review，不可作为开发授权。Approved 需要 P2_V3/00～07 全部无 S0/S1 且经用户确认；Implemented 需要 P1_V2/06 Release Unit 的代码、SQL、配置、外部契约和验证全部闭合。文档评审通过不授权公共/跨服务 contract、DDL、数据清理、生产依赖、Provider 采购或发布。

## 4. 背景与目标

旧 P2 保留基础文档能力，P2_V2 又叠加 ES v2、Profile、多通道、RRF/rerank 和 Gold Query。两套文档同时声称权威，并出现以下冲突：

- P2_V2/04 与 09 重复定义检索执行顺序；
- P2 05/06 与 P2_V2 07 重复定义 generation/evidence/candidate/security；
- 索引文档与运行治理文档都拥有 alias switch/rollback；
- ACL 文档与发布文档都拥有运行时撤权判定；
- Provider retry/timeout、Document resource limit 与部署 hard cap 混层；
- document rewrite 进入 Planning Runtime，突破 P1 capability-local port；
- Validator/Handler/Projector 各自读取 Profile/配置并重算预算。

目标是形成一个单 Agent、单执行主链、单事实所有权的 Document capability 基线，使 document.search、document.answer、document.summarize 复用 P1 Registration/Core/Lifecycle/Authorization/Result Security seam；future Multi-Agent 仅扩展 P1 owner/scope/binding/budget 输入，不重写 Document 检索、证据和 Provider 业务合同。

### 5.2 范围外

- 修改 L0/L1/P1_V2 或旧 P2/P2_V2。

## 6. 上级文档约束

1. Java 是 Document wire structure、Profile/limit contract、权限、执行、candidate 和 Result Security 的权威源。
2. Planning Runtime 只负责 Route/Plan，不承载 rewrite/generation/embedding/rerank 或检索。
3. capabilityId 固定为 document.search、document.answer、document.summarize；domain/materialType/profile/operation option 不是新 capabilityId。
4. Document Profile 在 Runtime Plan 前由 Java 根据 selected capability/domain 与受控 request input 解析；Runtime 只能返回 wire plan，不能提供可信 Profile 投影或选择 index alias/provider/model。
5. P1 Authorization/metadata 边界在 Runtime Plan 前冻结 Effective Document limits；Core recheck 后只产生同值或更严格 view。
6. Validator 只消费 server-origin DocumentRawPlan、ExecutionValidationContext.domainProjection() 和 typed limits；不解析 Profile、不调用 resolver、不读取配置。
7. Handler 不重读原始 Agent Profile/Policy/Permission/config；只消费 ValidatedDocumentPlan、ExecutionContext 和当前 Document ACL 边界结果。
8. Validator、Handler、DocumentRetrievableAdapter/capability-local Provider 和 Result Security 使用同一 limits view/reference。
9. Provider 输出是不可信 payload；operation metadata 由本地 client boundary 形成，candidate security binding 由 agent-service 使用可信 Invocation/evidence/limit facts 构造。
10. Context 不保存全文、vector、Provider payload、未验证 candidate 或跨 Invocation 业务结果。
11. current CHAT 只使用 ConversationScope；不创建 Run/Task/ResultRef/usage ledger 空壳。
12. 系统未投产，不保留 Runtime rewrite、旧检索编排或预算双路径；P1_V2/06 以一个 Activation Candidate 原子切换。

## 8. 设计边界与约束

| 边界 | 强制规则 |
|---|---|
| P1 seam 不变 | P2 不修改 PAI-1、Invocation/Lifecycle、Authorization formula、Domain Binding、operation SPI 或 Result Security 通用接口 |
| Pre-Plan freeze | Profile/limit 在 Runtime Plan 前解析/冻结；Validator/Handler 不 resolve |

## 9. 总体设计

~~~text
P1 Planning after valid Document Route:
  selected capability/domain
    -> Java-controlled Document profile selection
    -> P1 Authorization/metadata resolver freezes Effective Document limits
    -> Runtime Plan receives existing capability/domain schema only
    -> Java assembles server-origin DocumentRawPlan from wire plan + Profile projection
    -> ExecutablePlanningResult binds raw-plan/Profile digest through PAI and limits through Snapshot

P1 Execution Core:
  current authorization/Context/Domain/limits recheck
    -> DocumentPlanValidator validates DocumentRawPlan with domain projection/limits
    -> DocumentCapabilityHandler
         -> Document ACL scope/currentness + protected filter
         -> query preparation
         -> optional rewrite/embedding via 06
         -> DocumentRetrievableAdapter
         -> es-query-service resolves alias once
         -> BM25/phrase/vector + RRF/dedup/context
         -> 03 SafeDocumentCandidate projection
         -> optional rerank via 06
         -> 05 EvidenceContextPackage
         -> optional generation payload via 06
         -> 05 local candidate binding/citation verification/fallback
    -> P1/05 Document Result Security with same limits
    -> P1 Lifecycle commits secured result/context/audit
~~~

## 10. 详细功能设计

### 10.1 Pre-Plan Profile 与 Effective limits

DocumentRetrievalProfile 不由 Raw Plan、Provider 或 Handler 选择。Route 已解析 capability/domain 后，Java 根据以下受控输入形成 DocumentProfileSelection：

- selected capabilityId/domain；
- Agent Profile/Policy 已允许的 Document profile set；
- 调用者公共契约明确提供且已由 Java 校验的 optional materialType/requestedProfile/request narrowing；
- 当前 metadata/profile/policy/permission evidence。

DocumentRetrievalProfile 是 P1 exact AgentProfileRef 所指 immutable profile bundle 的版本化子配置；不得建立独立的 latest 指针、热更新 currentness port 或撤销事实源。Document Profile 的 candidate 构建、校验和发布与所属 Agent Profile/Policy candidate 原子完成，PROFILE contribution 的 evidenceRef 必须包含 AgentProfileRef + documentProfileVersion。P1 execution recheck 对 exact Agent Profile/version 的 currentness 因而同时覆盖该子配置；失效时整体 fail closed。

若 materialType/requestedProfile 未在 caller contract 中明确提供，必须使用 domain 下唯一 default profile；零个或多个 default 启动失败。Runtime Route/Plan 输出中的 profile 只能作为不可信 echo 并必须与 Java 已选值一致；不得指定/覆盖 indexAlias、schemaVersion、provider/model 或 Effective limit。

02 的 resolver 只解析 immutable Document profile snapshot；02 的 contract-specific adapters 形成 Definition/Profile/Policy/Permission/optional Request typed contributions。随后只由 P1 CapabilityResourceLimitResolver 求交并冻结 EffectiveCapabilityResourceLimits。

Profile snapshot 只在 Java Planning 边界投影为 DocumentPlanningProfileProjection，字段限定为 profile safe ref/version、DocumentCorpusKey、允许的 materialTypes、检索/生成 feature policy、通道与确定性算法参数，不含 readAlias/physicalIndex、provider/model/endpoint/credential、Profile/Policy/Permission 正文。该投影不新增 PlanRequest wire 字段，也不发送给 Runtime；Runtime 仍只返回 P1_V2/01 的 DocumentAgentPlan。

PlanningService 收到严格解析的 DocumentAgentPlan 后，只能通过 package-private DocumentRawPlanAssembler 使用当前 Invocation 已选且已冻结的投影组装 DocumentRawPlan(runtimePlan, profileBinding, serverProfileProjection)。DocumentProfileBinding 固定包含 invocationId、requestCorrelationId、registrationIdentity、AgentProfileRef/documentProfileVersion、ResourceLimitReference 和 projection canonical digest；构造器私有，serverProfileProjection 没有 JSON 反序列化入口，Runtime 响应不能覆盖。Document raw-plan canonical form 同时覆盖 runtimePlan canonical digest 与完整 binding，并由 P1 PlanningArtifactCanonicalizer 进入 PAI-1。不得把这一动作实现为 public builder、自由 Map、Context Snapshot、ExecutionContext 新字段或第二 Planning Artifact。

### 10.2 Execution 唯一序列

1. P1 Core 重检 Authorization Snapshot、Context、Domain Binding 与 Effective limits，只接受同值/收紧。
2. DocumentPlanValidator 校验 DocumentRawPlan 的 profile binding 与当前 invocation/correlation/registration/AgentProfileRef/ResourceLimitReference 全部一致，并只结合 ExecutionValidationContext.domainProjection() 与 typed limits 校验 capability/operation/domain/materialType/filters/options；输出携带最小 DocumentExecutionProfileProjection 与 concrete execution parameters 的 ValidatedDocumentPlan，不读取配置或解析 Profile。
3. Handler 只接收 ValidatedDocumentPlan 与 ExecutionContext 中的 limits/deadline/cancellation；不重读 Agent Profile/Policy/Permission/Document Profile。
4. 03 解析/复检 Document ACL execution evidence，构建唯一 protected filter object/digest。
5. Java 规则按 ValidatedDocumentPlan 准备 query；按其冻结的 feature policy 可调用 06 rewrite/embedding。optional 增强失败只走 04 冻结的确定性 fallback；required 失败整体拒绝。
6. DocumentRetrievableAdapter 只接收 validated request + CapabilityOperationContext，不接收 Raw Plan/ACL authority/JWT/config。
7. es-query-service 在一个 hybrid request 内解析 alias 一次，所有 BM25/phrase/vector channel 使用同一 physical target 和 protected filter。
8. 04 负责 channel result normalization、RRF、dedup、context window 和稳定排序；03 投影 SafeDocumentCandidate。
9. optional rerank 只接收 safe candidate subset；返回 id/score 必须是输入子集且无重复。
10. SEARCH 由 05 形成 evidence final candidate；ANSWER/SUMMARIZE 由 05 打包 EvidenceContextPackage，再由 06 返回 untrusted generation payload。
11. 05 使用可信 Invocation/package/evidence/operation metadata/limits 本地构造 DocumentGeneratedTextCandidate，完成 citation verification 和 extractive fallback/refuse。
12. DocumentResultSecurityProjector 复检 current revocation、output ContractRef、field/mask/citation/URI/text/count 与同一 limits，形成 final payload。
13. P1 Lifecycle 只提交 secured result、获批小型 Context 和安全 audit 摘要。

### 10.3 专题交互不重叠规则

- 01 vs 07：01 提供 switch/rollback/read-current 技术原语；07 的 change state machine 决定何时调用并持久化 report/audit/reconciliation。
- 02 vs P1_V2/05：02 只实现 Document limit type/contract/contribution；P1 resolver 唯一求交/冻结/recheck。
- 03 vs 07：03 的 runtime guard 是执行事实；07 的 emergency state 是外部治理输入，必须通过 03/P1 Policy currentness 生效。
- 04 vs 06：04 选择何时调用 optional port；06 只执行一次 typed operation，不决定业务 fallback 或下一步骤。
- 05 vs 06：06 generation result 是 untrusted payload；05 CandidateFactory 才能绑定 current Invocation/evidence/citation/output ContractRef/limit reference。
- 04 vs 05：04 提供 ordered safe candidates；05 不重新评分/RRF/dedup，只做 evidence selection/packing/security。

### 10.4 Alias 与索引一致性

Profile 不拥有 readAlias/schemaVersion。ValidatedDocumentPlan 只携带受控 DocumentCorpusKey(domain,materialType)；01 的 immutable corpus catalog 是 CorpusKey→readAlias/schemaVersion 的唯一映射。每次 /hybrid-search 在 es-query-service request boundary：

1. 以 DocumentCorpusKey 精确解析一次 corpus catalog，并校验 readAlias/schemaVersion 与 active mapping 兼容；
2. 读取一次 alias target，形成 ResolvedIndexTargetRef(alias,physicalIndex,schemaVersion,indexContentDigest/reportRef)；
3. 所有 channel 在同一 request 使用该 physicalIndex；
4. response/evidence/audit 绑定 target safe ref；不把 physical index 开放给用户输入；
5. alias 在请求后切换不重放当前检索；final currentness 仍复检 permission/emergency control，索引发布安全由 07 report 保证。

Alias switch 使用 01 的 ES CAS/read-current 技术原语；07 采用 PREPARED intent -> ES operation -> read actual -> SUCCEEDED/FAILED/UNKNOWN reconciliation。不得由 01 和 07 各持久化一套不一致状态机。

### 10.5 Provider payload 到可信 candidate

06 的四类 port 均返回 P1 CapabilityOperationOutcome<R>。其中 generation request/payload 复用 05 冻结的 provider-independent boundary contract，06 只实现 port/client 与 transport mapping：

- rewrite R 只含候选短文本/安全诊断；
- embedding R 只含 vector/modelVersion/dimension；
- rerank R 只含输入 candidateId 子集及 score/reason；
- generation R 只含 candidate answer/summary/bullets、provider citation ids、finish reason 等 untrusted payload。

Provider 不得设置 invocationId/owner/authorizationBindingDigest/ResourceLimitReference/output ContractRef/evidence owner。agent-service client boundary 形成 operation metadata；05 CandidateFactory 使用 operation context、EvidenceContextPackage、当前 Scope 和 limits reference 构造 security binding。任何 citation 不属于 package、operation/limit mismatch、late/cancel/deadline 或 payload 超限均不能形成 GeneratedTextCandidate。

### 10.6 Budget、deadline 与 operational cap

| 限制类别 | 所有者 | 示例 | 使用规则 |
|---|---|---|---|
| PlanningBudget | P1 Profile/Policy/Planning | total duration、repair attempts | 只约束 Route/Plan/repair，不进入 Document execution limit |
| DocumentResourceLimit | 02 + P1 resolver | query chars、channel/topK、candidate/evidence/chunk/context/output chars | Definition/Profile/Policy/Permission/Request 单调求交；四消费者同源 |
| absolute deadline | P1 Invocation Handle | caller end time | 全链共享，只消费剩余时间 |
| Provider operational cap | 06 composition/client | connect/read stage cap、response bytes、bulkhead | 只能更早拒绝/缩短，不能成为授权 source |
| attempt policy | P1_V2/05 | current 0/1 outbound attempt | 不进入 DocumentResourceLimit；不可观测/大于 1 生产门禁失败 |

DocumentResourceLimit 不包含 maxProviderAttempts、Provider endpoint timeout、credential、bulkhead 或 hidden retry 配置。

### 10.7 Failure、fallback 与 capability 语义

- document.search 不调用 generation；只输出安全 evidence/citations/coverage/query parameters。
- document.answer/summarize 共用 retrieval/evidence/security chain，以 operation policy 区分 output fields/grounding/fallback。
- Profile 明确 required/optional channel/provider；optional 失败只能使用 04/05 的确定性本地 fallback，不自动调用备用 Provider。
- ACL/required channel/required provider/Result Security/currentness/limit failure均 fail closed。
- 无 evidence 时按 05 返回 NO_EVIDENCE/refuse；不调用 generation 产生无依据文本。
- disabled Provider 是唯一 Bean 的 typed implementation，不是 feature flag 兼容旧 Runtime。

### 10.8 旧路径原子处置

P1_V2/06 的同一 Activation Candidate 必须：

- 新建/迁移 capability-local rewrite/embedding/rerank/generation port/client；
- 删除 RuntimeDocumentQueryRewriteClient；
- 删除 Agent Runtime document rewrite endpoint/core/DTO/Prompt/test/config；
- 保持 Runtime 业务 endpoint 仅 Route/Plan；
- 不新增 /multi-channel-search，扩展现有 /hybrid-search Java contract；
- 删除 P2_V2/04 与 09 的重复 orchestration 实现；
- 删除 Document Validator/Handler/Projector 对 AgentProperties 业务预算的直接读取；
- 删除 Provider 自报 security binding、unknown attempts=0、SDK retry 和 free String final candidate 路径。

不得先删唯一 rewrite 实现，也不得保留长期双调用。新 client/contract test/端到端 fallback/deadline/security 通过后，在同一未激活 candidate 删除旧路径。

## 13. 状态流转设计

Document 执行不新增业务状态机。Invocation 终态完全归 P1 Lifecycle。

PROFILE_RESOLVED、ACL_VERIFIED、INDEX_TARGET_RESOLVED、RETRIEVED、RERANKED、EVIDENCE_PACKED、GENERATED、SECURED 仅是进程内 trace/span 名称：

- 不定义共享持久化 enum；
- 不写数据库 stage 字段；
- 不通过 event bus 驱动下一阶段；
- 缺失 span 不影响业务正确性；
- 业务成功只由 P1 FinalizedInvocationResult 决定。

Rebuild task 与 Rollout change 是 01/07 的独立运维状态，不与一次 Document Invocation 状态合并。

## 14. 幂等、事务与一致性设计

- Agent Profile + Document Profile 子配置的 canonical version 对同一逻辑输入稳定并原子发布；Document Profile 不独立切 latest。Corpus/schema bundle 由 01 独立原子发布并受 07 gate 约束。
- hybrid request 内 alias 只解析一次；所有 channel 共享 target ref/protected filter/effective limits。
- retrieval 只读；operationId 仅诊断，不授权 Provider replay。
- Provider current attempt 为 0/1，无自动 retry；late/cancel response 丢弃。
- candidate 不跨 Invocation 缓存；Embedding cache 本阶段不实现。
- alias rollout 使用意图持久化 + ES CAS + read-current + reconciliation；unknown 不猜测成功/回退。
- finalization 只提交 secured result/approved Context；任何 candidate/Context 失败不返回 SUCCESS。
- P1_V2/06 Activation Candidate 一次切换 Runtime/provider/config/contract，不双写/双读。

## 15. 权限、风控与审计设计

- P1 Authorization currentness 先于 Validator；03 Document ACL currentness 在 retrieval 前和 final output 前执行。
- 每个 channel 使用相同 protected filter；无法表达 filter 的 channel 不执行。
- rewrite/embedding 只接收有界 query/input；rerank 只见 safe candidate projection；generation 只见 EvidenceContextPackage 的有界允许文本。
- Provider 不接收 JWT、完整 ExecutionScope、ACL expression/raw token、Profile/Policy、index credential、未授权全文或 raw document。
- sourceUri 去 credential/query/fragment/token；vector、score explanation、internal index 和 raw Provider payload 不进入 final output。
- audit 记录 safe version/digest/count/decision/reason/diagnosticId；不记录 query/evidence/candidate/final long text 或 secret。
- emergency control 由 07 管理，但必须通过 P1 Policy/03 guard 的 currentness 输入生效，不能在 Handler 写一套 blocklist switch。

## 16. 性能与容量设计

- DocumentResourceLimit 有界 query/channel/topK/candidate/chunk/evidence/context/output/vector count/dimension；所有 04/05/06 消费方不得直读业务上限配置。
- Provider stage cap、response cap、bulkhead 和 queue cap 是 operational guard，只能比 absolute deadline 更严格。
- RRF/dedup/evidence packing 对有界候选线性或 N log N，禁止全量 corpus scan、无界 context expansion 和多份全文复制。
- ES hybrid request 一次解析 alias、一次编译 protected filter，并在各 channel 复用。
- diagnostics 有数量/大小上限；metrics 不使用 query/documentId/physicalIndex/profileVersion/digest 全值等高基数标签。

## 17. 兼容性与扩展性设计

系统未投产，内部接口直接切换，不保留 Runtime rewrite、旧 orchestration、旧 schema reader 或预算兼容 facade。已有 transaction/es-query 等跨服务公共契约在未获授权时保持兼容；如必须改变字段，先清点调用者并按 P1_V2/06 M0 授权。

future Multi-Agent L1 评审后可扩展 P1 Owner/InvocationScope/binding identity、Delegation/current permission 和 Run/Task remaining resource contribution。Document Profile、ACL filter、retrieval/evidence/provider/result contracts 继续复用，但 candidate/evidence binding 必须纳入届时 P1 定义的新 owner/scope/ref；当前不预建字段。
