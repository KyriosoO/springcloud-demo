## 3. 文档状态说明

本文处于 **Implemented**。治理 schema source、管理 API/服务身份校验、validation/report/gate、Provider activation、index rollout、emergency state、reconciliation 与审计所有权已完成本地实施和验证。该状态不允许访问或变更生产环境，不代表真实 alias/Provider 发布获批，也不允许 commit、push、创建分支或 PR。

本文是 P2_V3 中 Document validation report、release gate、index/provider operational change、emergency control、reconciliation、governance audit 与 production readiness 的唯一专题规范。旧 P2/P2_V2 仅保留 provenance；其 caller 提供 `validationDigest/operatorRef/targetIndex/threshold`、direct alias switch/rollback、Profile traffic allowlist、AgentProperties blocklist、Runtime rewrite 和内存 report/audit 不再用于补充实现。

## 4. 背景与目标

当前实现已经具备局部 validation、Gold、alias audit 和 Document observability 骨架，但不能证明目标架构可安全生产启用：

- `DocumentIndexValidationReport` 由当前 task 字段、本地 `Instant.now()` 和散字符串拼接生成，report 未持久化为 subject-bound immutable authority；
- `DocumentGoldQueryBatchValidationRequest` 携带 `Map<String,Object>` filter、caller query vector、embedding field/channel weights 和 alias rollback request，Gold executor自行构造 ES DSL，绕过 02～06 正式执行链；
- threshold、target index、validation digest、operatorRef 由 caller request 提供，无法证明来自受控 policy、当前报告或认证管理主体；
- `EsIndexAliasService` 直接拥有 switch/rollback endpoint、history/audit，同时 01 已冻结“技术原语归01、change决策和持久化归07”，形成双 owner；
- ES alias 只允许一个 target，旧“alias 百分比 canary/多 target”会破坏 01 one request one physical target 与确定性检索；
- Document Profile 是 exact Agent Profile 的 immutable child asset，不存在07独立 hot current/traffic percentage；
- `DocumentRevocationGuard` 仍读取 `AgentProperties.blocklist`，未实现03冻结的 `DocumentEmergencyControlReadPort`；
- 06四类Provider需要07唯一发布`DocumentProviderActivationSnapshot`，但当前07没有provider binding、consumer freshness、distribution、rollback或两跳 readiness定义；
- P1首次迁移必须是一个 Activation Candidate，不能被07“细粒度灰度”拆成新旧contract并行；后续索引/Provider运维又需要与代码/DDL release区分；
- 验证、变更、外部事实、审计和回滚失败之间缺少可恢复的一致性模型。

目标是建立一条不旁路运行时安全边界的治理链：技术/全链场景证据形成subject-bound immutable report；07基于current state、有效报告、readiness与审批形成一次性release gate evidence；index变更由同服务07 coordinator调用01技术原语，Provider变更由agent-service 07 authority发布06 snapshot；03从07 current emergency store fail closed读取；所有外部变更均使用intent→action→actual-read→reconciliation，且不复制P1 Invocation、01 alias actual、02 Profile currentness、03 Guard、04/05业务fallback或06 endpoint算法。

## 6. 上级文档约束

1. L0/L1只预留Multi Agent演进，当前仍是单Agent/CHAT；07不能增加Agent task graph或协调器。
2. Java source contract为运行时权威；validation fixture/report不能成为第二份Capability/Plan/Profile/Policy schema。
3. P1 Authorization、current ExecutionScope、CapabilityResourceLimit、operation metadata和Result Security不可被report/digest替代。
4. P1首次实施只允许一个Activation Candidate；07不能用feature flag、双endpoint、双DTO或流量比例维持旧/新路径。
5. Profile属于exact Agent Profile immutable child asset；07只引用exact safe ref进行验证，不发布独立latest/allowlist/percentage。
6. capability-local Provider输出不可信；07只决定binding是否可ACTIVE，不构造candidate、fallback或P1 metadata。
7. 安全/权限/data-sharing/Result Security gate优先于质量；任一安全门禁失败不能用审批或quality豁免放行。
8. Context/audit/report不保存query/evidence/answer/vector/ACL正文、Provider payload、credential或用户身份全集。
9. external state change不宣称分布式强事务；必须持久化intent、读取实际状态并reconcile。
10. destructive cleanup、DDL、公共/跨服务contract、生产依赖和发布动作必须分别获得显式授权。

## 9. 总体设计

### 9.1 唯一治理链

~~~text
Immutable candidate assets
  -> 01 technical evidence / full vertical scenario observations / 06 readiness evidence
  -> DocumentValidationCoordinator
       -> versioned policy + exact fixture set + exact subject
       -> immutable DocumentValidationReport (DVR-1)
  -> DocumentReleaseGateEvaluator rechecks current reports/readiness/emergency/approval
       -> one-change DocumentReleaseGateEvidence (DRG-1)
  -> unit-specific coordinator
       INDEX_TARGET: es-query-service 07 coordinator -> 01 attach attestation / compareAndSwitch
       PROVIDER_OPERATION: agent-service 07 coordinator -> authoritative activation state / snapshot publisher
       EMERGENCY_CONTROL: agent-service 07 service -> current emergency state; provider target also forces INACTIVE
  -> actual-read / consumer-observed digest
  -> SUCCEEDED | FAILED | UNKNOWN -> reconciliation -> SUCCEEDED | FAILED_SAFE | FROZEN
  -> append-only governance event + low-cardinality metrics
~~~

### 9.2 部署与所有权

07是一个设计专题，不新增“万能治理服务”：

- `es-query-service/.../document/governance`拥有INDEX_RELEASE subject的validation report、release attestation decision、index change/lease/reconciliation，直接调用同进程01 package-private technical ports；不新增跨服务alias command DTO。
- `agent-service/.../capability/document/governance`拥有PROVIDER_OPERATION/P1_RELEASE_CANDIDATE subject的validation report、Provider activation、emergency state/current read、Provider change/reconciliation与运行readiness聚合；Provider adapter通过受认证internal feed读取同一activation authority。
- release tooling在隔离deployment外部调用正常Agent API并产出受完整性保护的safe observation bundle，分别提交给对应subject owner；它不直接写report/current state，也不成为第三个report authority。
- P1 release pipeline/M7只聚合两侧safe report/change/readiness refs形成完整Gate Evidence，不建立第三套runtime current store或es-query→agent反向运行依赖。
- 两侧共享本文DVR-1/DRG-1/DGC-1 canonical规则和contract fixtures，但不新增通用governance-api模块、不建立共同基类或跨库事务。

### 9.3 首次激活与后续运维

| 场景 | 允许单位 | 规则 |
|---|---|---|
| 首次P1/P2_V3落地 | P1一个Activation Candidate | M1～M6同一未激活候选；M7包含本文全部Gate；不按index/provider/profile拆上线 |
| 代码/Java/HTTP/DDL/config schema变更 | 新P1 Release Unit | 重新走G0～G11；07不能用operation开关维持双contract |
| exact Agent Profile/Document Profile变更 | P1 metadata candidate | 07提供验证证据但不独立切Profile；parent candidate原子发布 |
| sealed index内容更新 | INDEX_TARGET change | 仅在目标架构已激活后，通过01单target CAS切换/回滚 |
| 同contract Provider binding变更 | PROVIDER_OPERATION change | 每operation binary ACTIVE/INACTIVE；旧binding不并行收流量 |
| 紧急安全阻断 | EMERGENCY_CONTROL change | 优先禁用，随后按实际原因决定index/provider/P1 rollback |

## 10. 详细功能设计

### 10.1 Validation subject

report只验证exact subject，使用closed union：

~~~java
public sealed interface DocumentValidationSubjectRef
    permits DocumentIndexReleaseSubjectRef,
            DocumentProviderOperationSubjectRef,
            DocumentP1ReleaseCandidateSubjectRef {}

public record DocumentIndexReleaseSubjectRef(
    DocumentCorpusKey corpusKey,
    DocumentPhysicalManifestRef manifestRef,
    DocumentTargetBindingReference targetBinding,
    DocumentProfileCoverageRef profileCoverage,
    Optional<DocumentEmbeddingBindingReference> embeddingBinding)
    implements DocumentValidationSubjectRef {}

public record DocumentProviderOperationSubjectRef(
    CapabilityOperationType operationType,
    DocumentProviderBindingReference providerBinding,
    String validatedCorpusSetDigest,
    String activeProfileCoverageDigest)
    implements DocumentValidationSubjectRef {}

public record DocumentP1ReleaseCandidateSubjectRef(
    String activationCandidateDigest,
    String javaContractBaselineDigest,
    String configCandidateDigest,
    String ddlCandidateDigest)
    implements DocumentValidationSubjectRef {}

public record DocumentProfileCoverageRef(
    List<AgentProfileRef> orderedAgentProfiles,
    String documentProfileSetDigest,
    String featureCoverageDigest,
    String resourceContractCoverageDigest,
    String canonicalDigest) {}
~~~

subject不接受alias/physical index/provider/model自由字符串。Index subject由01 manifest/target safe refs构造；Provider subject使用06 binding；P1 candidate ref由M0～M7 release tooling构造。任一关联asset变化必须产生新subject/report。

### 10.2 Validation policy

`DocumentValidationPolicy`是07拥有的versioned immutable治理资产，包含closed gate集合、quality/capacity阈值、fixture coverage要求、最大报告有效期和validator suite version。它不是02 Profile、P1 Policy或用户request字段，不参与运行授权/limit求交。

~~~java
public record DocumentValidationPolicyRef(
    String policyVersion,
    String validatorSuiteVersion,
    String canonicalDigest) {}
~~~

policy candidate必须通过schema、阈值范围、security gate完整性和向后严格性校验后由治理配置发布；caller不能覆盖threshold。security gate阈值固定为zero leak/zero bypass，不能被policy配置放宽。policy版本变化使未显式兼容的旧report不可用于新change。

### 10.3 Fixture 与 Gold scenario

~~~java
public record DocumentGoldScenarioCase(
    String caseId,
    DocumentFixtureSetRef fixtureSet,
    CapabilityId capabilityId,
    DocumentCorpusKey corpusKey,
    AgentProfileRef agentProfileRef,
    DocumentProfileAssetRef documentProfileRef,
    DocumentFixtureRef executionSubjectFixture,
    DocumentFixtureRef requestFixture,
    List<DocumentFixtureRef> expectedEvidenceFixtures,
    DocumentExpectedSecurityOutcome expectedSecurityOutcome,
    DocumentExpectedOutputMode expectedOutputMode,
    List<DocumentGateCode> requiredGates) {}
~~~

fixture store按版本不可变、加密、最小管理scope访问；query、expected document/chunk identity、ACL fixture和expected answer claims不进入report/audit/log。report只保存fixture set ref/digest、case count、gate observation和安全reason code。case ID和fixture ref必须是opaque safe ID，不能编码用户/文档名。

至少覆盖：SEARCH/ANSWER/SUMMARIZE、allow/deny/revoked、empty/no-evidence、required/optional/disabled、BM25/phrase/vector/context/rerank、citation valid/invalid、factuality positive/negative、permission/emergency变化、deadline/cancel/late、Result Security/candidate leak和limit边界。

### 10.4 场景执行不旁路正式链

Gold/security/output/capacity suite由release tooling在隔离validation deployment外部执行；该deployment使用与release candidate相同的Java artifact、config candidate、contract、Corpus Catalog、Profile/Policy/Permission、Provider binding和operational caps，并把candidate physical index绑定为该环境唯一read target。每个scenario从正常P1 Agent entry启动CHAT Invocation，经过02～06正式链和P1 Result Security；request不能携带validationMode、physical target、Profile override、ACL scope、Provider/model或阈值。

runner只做fixture身份注入、调用正常entry、读取安全响应与受限observation；不直接调用Handler私有方法、不构造ES DSL、不调用Provider client、不跳过authorization/currentness。生产服务main source不保留validation专用runtime branch或公开endpoint。隔离环境attestation必须记录artifact/config/contract/topology safe digest；与生产目标不等价时report不能授权生产ACTIVE。

### 10.11 Index activate/rollback

`DocumentIndexRolloutCoordinator`位于es-query-service 07 governance包，执行：

1. 认证管理scope、幂等request、CorpusKey和expected target safe digest；
2. 持久化PREPARED并取得Corpus exclusive lease；
3. 读取01 actual alias；0/1 target有效，多target立即FROZEN/高危告警；
4. 读取target sealed manifest、attestation、report和current emergency state safe input；
5. 构造DRG-1，planned rollback也必须有current-valid security/technical report；
6. 通过01 package-private factory构造`AuthorizedAliasChangeCommand`，caller不能构造；
7. EXECUTING后调用01唯一`compareAndSwitch`一次；
8. 无论success/exception/timeout均读取actual alias+manifest+attestation；
9. actual=target且binding一致→SUCCEEDED；actual=expected→FAILED_SAFE；第三状态/多target/不可读→UNKNOWN；
10. UNKNOWN进入reconciliation并保持该Corpus后续change冻结；不自动重放ES mutation；
11. 追加安全事件、释放lease并更新readiness。

权限泄露时先写emergency block使03 fail closed，再尝试rollback；不能为了恢复可用性回到过期/未attested/安全report失败的target。无可用rollback target时保持blocked，而不是使用break-glass绕过security gate。

### 10.13 Snapshot publication 与 consumer freshness

`DocumentProviderActivationPublisher`从authoritative row发布同一immutable snapshot给agent-service本地read view和`document-provider-adapter`受认证internal feed。feed只读、mTLS/service scope、strict bytes/schema、无管理写API；consumer校验operation/wire/binding/digest并原子替换本地projection。

consumer effective freshness=`min(snapshot.validUntil, lastSuccessfulRefresh + maxDistributionStaleness)`。超过任一时间、feed不可用、digest回退/跳号、unknown operation、binding/config不匹配时本地视为INACTIVE/UNAVAILABLE，不使用last-known-good继续ACTIVE，也不从config flag恢复。`maxDistributionStaleness`是07 operational safety cap，只能缩短。

snapshot不做周期heartbeat改digest；validUntil续期是有gate的新rolloutVersion，避免例行刷新使06所有in-flight request误判activation变化。续期切换时短暂late/post-reject是安全行为，必须计量并在低峰执行。initial planned enable在required service groups上报candidate readiness后提交ACTIVE；change仅在agent-service和provider-adapter各至少一个当前deployment实例观察到相同digest且其他实例受staleness fail-closed约束后SUCCEEDED，否则UNKNOWN/reconcile。

### 10.14 Provider rollback 与 emergency联动

Provider rollback是新的change，target只能是history中同operation的previous binding，且其report/data-sharing/credential/readiness仍current；同样执行INACTIVE barrier后再激活previous binding。旧binding过期或不兼容时只允许INACTIVE，不能为可用性重新启用。

当emergency target命中`PROVIDER_OPERATION`或`PROVIDER_BINDING`时，事务先将对应effective activation转为INACTIVE并记录cause/control version，再发布新snapshot。clear emergency只移除阻断条件，不自动恢复旧Provider；恢复必须新的planned ACTIVATE change与新DRG-1。这样避免“清除blocklist即自动外发”。

Provider disable存在不可消除传播窗口：command返回`PROPAGATING`直到required consumers确认INACTIVE或`maxDistributionStaleness`上界已过；达到前不声称全局生效。agent-service authoritative emergency read立即让03 final guard拒绝结果，06 pre-write local snapshot和adapter snapshot分别收敛外发；已发送vendor数据无法撤回，进入安全事件和响应处置流程。

### 10.17 Reconciliation

reconciler只读取事实，不自动再次执行mutation：

| unit | actual=target | actual=expected | 第三/unknown状态 |

| INDEX_TARGET | SUCCEEDED | FAILED_SAFE | FROZEN；保留emergency block并人工处理 |

## 13. 状态流转设计

### 13.1 Validation run/report

~~~text
CREATED -> RUNNING -> PASSED | BLOCKED | FAILED | CANCELLED
                      |
                      +-> immutable report published exactly once
~~~

run terminal不等于report PASSED；只有完整gate set形成且integrity写成功才发布report。cancel/deadline不把partial gate结果发布为可引用report。

### 13.2 Planned governance change

~~~text
PREPARED -> GATED -> EXECUTING -> VERIFYING
   |          |          |            |
   v          v          v            +-> SUCCEEDED
FAILED_SAFE FAILED_SAFE UNKNOWN ----------> RECONCILING
                                         -> SUCCEEDED | FAILED_SAFE | FROZEN
~~~

`UNKNOWN/RECONCILING/FROZEN`阻止同unit后续planned change。rollback是新change，不把SUCCEEDED原记录改成ROLLED_BACK。

### 13.3 Emergency control

~~~text
NOT_PRESENT/CLEARED --disable CAS--> ACTIVE --clear CAS--> CLEARED
                                  \--repeat same digest--> ACTIVE (idempotent)
~~~

ACTIVE没有自动TTL清除；过期approval只阻止新操作，不自动恢复。Provider target的effective activation可因ACTIVE emergency变为INACTIVE，但其planned activation history不被改写。

## 14. 幂等、事务与一致性设计

- validation idempotency覆盖subject/policy/fixture/release candidate；相同key不同request冲突，报告canonical在相同稳定observation下确定。
- report header+exactly-one typed subject projection+gate results+integrity在单DB事务发布；发布后repository禁止UPDATE/DELETE结果或projection字段。
- change PREPARED与首个governance event同事务；所有status/state CAS与event append同事务。
- index change无法与ES形成分布式事务，严格使用PREPARED→01 action→post-read→result/reconciliation。
- Provider activation state+change+event在agent DB同事务；snapshot distribution在commit后进行，consumer未观察只会fail closed。观察闭合前change不SUCCEEDED。
- emergency provider disable先提交authoritative block/INACTIVE effective state，再分发；分发未知不回滚block。
- event delivery至少一次，consumer按eventId幂等；delivery retry不重放alias/provider state mutation。
- exclusive lease按unit key有界；lease过期允许reconciler接管，不允许新的activate绕过UNKNOWN。
- Clock全部注入，deadline/validUntil/lease/retention使用UTC；clock skew超cap拒绝planned enable。
- 不宣称跨es-query DB、agent DB、ES、Provider adapter和外部审批系统强事务；Release Gate只聚合safe evidence。

## 15. 权限、风控与审计设计

1. validation fixture管理、report读取、index activate/rollback、Provider activate/deactivate/rollback、emergency evidence issue、emergency disable/clear、reconcile、retention delete使用10.22定义的不同最小management scopes；禁止通用`document.governance.admin`覆盖全部写操作。
2. actor从认证principal生成opaque safe ref；request body中的operator/owner/role一律拒绝。
3. planned enable/rollback与emergency clear必须验证外部approval evidence；break-glass只可disable，不能enable/clear或绕过security gate。
4. separation of duties至少保证candidate/report producer不能单独批准其生产ACTIVE；具体企业审批模型由外部系统负责。
5. Provider data-sharing approval按operation/provider/Corpus coverage exact绑定；unknown classification/purpose或过期整体INACTIVE。
6. snapshot feed和03 read port使用不同受控service scope；用户JWT不转发给governance store/provider adapter。
7. report/digest/attestation不能作为访问令牌；所有管理写仍需认证、scope、approval、expected state和idempotency。
8. audit/event不可由管理caller提供结果；repository本地生成actual/result/reason。
9. permission/security leak触发emergency优先；质量下降不自动推断security incident，但可planned rollback。
10. raw query/fixture/answer/evidence/vector/ACL/principal/document identity/provider body/credential/URL/prompt不进入report/change/event/log/metric。
11. management controller必须使用`DocumentManagementAuthorizationContextResolver`和`DocumentApprovalEvidencePort`；不得把actor/approval/break-glass作为service方法自由String参数从controller透传。
12. EGE-1签发私钥只在agent-service signing provider可见；es-query-service只持exact key-version公钥，key轮换采用显式双公钥验证窗口和单当前签发key，不允许验证端回退共享secret。

## 16. 性能与容量设计

- validation离线执行，run有max cases/concurrency/duration/request bytes/observation bytes；caller不能放大policy cap。
- scenario runner复用正式链但使用隔离deployment/bulkhead，不能消耗生产请求配额或污染生产audit；真实Provider容量测试使用获批窗口与独立budget。
- gate report按closed code有界；不得保存任意Map、大数组或每文档metric。
- index unit一次只允许一个change；alias action一次，reconcile只read，不扫描全索引。
- Provider snapshot每operation常量级；consumer refresh有jitter、backoff和max staleness，但disconnect后不延长ACTIVE。
- emergency final read按bounded target set一次查询；索引覆盖target type+key digest+state，不能逐candidate查询。
- governance event队列有容量/retention；planned enable在无法写event时拒绝，emergency disable可同步写state+event并优先于异步投递。
- metric labels只使用gate/unit/operation/status/reason/safe family，禁止run/change/report/digest/Corpus full key/actor作为label。
