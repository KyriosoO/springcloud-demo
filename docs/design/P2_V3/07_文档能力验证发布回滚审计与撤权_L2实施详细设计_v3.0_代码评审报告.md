| CR-001 | critical | release_gate_bypass | validation models/repositories | PASSED report 只要求“至少一个且都 PASSED”，Provider/Index 管理读取也不复核 required gate | 单个伪 gate 即可形成 ACTIVE/alias change 的本地权威 | 增加 subject/operation-specific required gate set、closed index gate/unit，并在管理读取时再次复核 subject 与 required gates |
| CR-002 | critical | emergency_fail_open | `DocumentRevocationGuard`、target binding | final Guard 不含 capability；Index emergency 用 manifest digest 而非 ITB-1；不核对返回 view 是否覆盖全部 exact targets | 部分 `NOT_BLOCKED` view 或正确签发的 Index/Capability block 可被公开结果绕过 | `DocumentTargetBindingReference` 统一 ITB-1；Guard 核对完整 target set，并加入 capability、exact index、generation provider operation/binding |

## 9. 结论

- 不通过。
- 9 组可局部闭合的代码问题已修复并通过定向、完整 reactor、Python 与静态扫描；critical fail-open 已收紧为 fail closed。
