## 4. 代码问题清单

| 编号 | 级别 | 类型 | 文件 | 问题描述 | 影响 | 处理结果 |
|---|---|---|---|---|---|---|
| CR-001 | high | candidate_set_binding | `DocumentRevocationGuard.java` | Guard 直接信任调用方传入的 candidateSetDigest，未从 candidates/evidence refs/output contract 重算 | 内部错误可使 authority decision 与最终 Result sidecar 绑定不同 identity set | request 显式携带 refs/ContractRef，Guard 使用 DCS-1 重算后再调用 currentness；伪造 digest 测试已覆盖 |
| CR-002 | high | currentness_cap | `DocumentRevocationGuard.java`、配置 wiring | final batch 只依赖 HTTP client 的 compiler cap，未在 Guard 同时应用 typed maxEvidence/maxReturned；替换 port/test double 可绕过 | 超限候选进入 authority 或 final decision，扩大撤权窗口与请求体 | Guard 注入 compiler cap，并与 effective typed limits 取最小值；超限 fail closed |
| CR-003 | medium | canonical_input | `OnlyDocumentIds.java`、`DocumentAclScopeSnapshot.java`、`DocumentProtectedFilterCanonicalizer.java` | principal/document/filter value 除 NUL 外可包含其他控制字符，scope 文本无 512 code-point cap | canonical/log/wire 边界可能出现不可稳定或注入型值 | 统一在 scope candidate 与 DAF-1 前拒绝 ISO control 和超长值；新增负向测试 |
| CR-004 | high | evidence_provenance | `DocumentAclExecutionEvidenceFactory.java` | factory 未核对 operation id/type、ResourceLimitReference、termination 与 permission version，任意 metadata 可进入 DAE-1 | evidence 看似有 digest，但来源不是本次成功 ACL resolve | 构造前校验 exact operation/type/limit/SUCCEEDED/permission binding；新增错 operation 测试 |
| CR-005 | medium | typed_contract | `DocumentAnyTerms.java`、`DocumentProtectedFilterBinding.java` | `DocumentAnyTerms` 接受 null field；filter binding 仅判 digest 非 null，不校验 lowercase SHA-256 | 非法 AST 延迟到 canonicalizer NPE，畸形 binding 可跨 Adapter seam | 构造期拒绝 null field 和非 canonical digest；新增 contract tests |
