| CR-004 | high | catalog_startup_closure | `DocumentCorpusConfiguration.java`、`DocumentSourceConnectorRegistry.java` | `requireCatalogClosure` 已实现但从未被 wiring 调用，配置可引用不存在 connector，服务仍就绪并先创建 PENDING task，直到 worker 才失败 | 配置错误被延迟为数据面失败并留下必然失败任务，与 immutable candidate 原子发布不符 | 新增 `SmartInitializingSingleton` 启动闭包，服务 ready 前校验所有 connector/schema 引用；新增存在/缺失 connector 测试 |

## 9. 结论

- 有条件通过。
- 4 项高风险 generic 隔离、alias unknown outcome、sealed target 完整性和 Catalog 启动闭包缺口已在三轮评审—修复中闭合；本地 Java reactor 与精确扫描通过。
- 当前配置的生产 Source Connector、真实 ES role/secret/schema/vector 和数据库迁移未具备或未验证，因此不能声明生产 corpus/index lifecycle 可启用；启动闭包将按设计 fail closed。
- 主详细设计、关联设计及 L0/L1 架构正文未修改；DOC-001、DOC-002 仅记录，等待单独文档修改授权。
- 未执行生产 DDL、物理索引构建/删除、alias 变更、部署、提交、推送或远端操作。
